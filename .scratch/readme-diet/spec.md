## 2. 拆分规则

### 留在 README（目标 ~800 行）

1. **总览**：一种基础气泡 / 三条路线 / 基础气泡是什么
2. **版本号**：这一页跑的是哪个 build
3. **配置指南**：`mechanics.json5` 的格式、校验规则、运行时 `tuning`
4. **规则说明（19 节，重写成现在时）**：

   关卡：一关一个文件 · 关卡选择与进度 · 触屏控制 · 触屏按钮 · 积分 · 气泡成长阶段的外观 ·
   弹幕 · 吞噬 · 吸附 · 路径点（spline）· 通关流程 · 图鉴页 · 突变 · 擦边 · 小泡泡子弹 ·
   障碍物 · BOSS · 血量：两条路线两套经济 · 六只 BOSS 一个 kind 一只

5. **操作手册**：跑起来、测试、发布流程、测量工具的坑、调手感、代码结构、注意、pwsh 安装

### 搬进 `docs/design-log.md`

其余约 220 节，按原样搬，**零信息损失**：各种「修复：xxx」、美术管线日志（像素化、图集、资产导入）、
验证脚本的来历、历次实测记录、被推翻方案的来龙去脉。

### 直接删掉

**15 个「（历史）」小节**（如"（历史）鱼群做过又删掉了"、"（历史）螺旋下潜"、"（历史）玩家气泡的贴图已导入"）。
它们记的是"当初为什么没那么做"，而那个决定已经在代码里了；这是唯一一处彻底丢弃内容的地方。

### 留下的 19 节怎么改

**只留"现在怎么做 + 为什么这么做"，改动史和实测数据全部进日志。**

一边是"擦边现在怎么算"，另一边是"某次改动把擦边改成了这样"——README 只回答前者。
实测数据（如"实测：分数 35、体积停在 1.0"）是变更证据，属于日志；README 里一条规则不需要证明它被验证过，
它只需要是现在成立的。
