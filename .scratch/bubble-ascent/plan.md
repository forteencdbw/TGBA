规模小的项目不必拆得那么细，但**每一项都要能被独立拿起来做**，所以下面按"一个里程碑一次能做完并测完"来切。

## 二、待办

### 06 · 消化压缩

**Status:** `ready-for-agent` · 规格第四节第 2 条

现在吞下的东西**只能吐出去**。消化是另一半：把胃袋里的东西主动转成成长，同时**主动缩小体积**。

规格要求：

- 长按"压缩"加速消化
- 体积逐渐缩小
- 质量转化为成长能量
- 移动灵活度恢复
- **消化期间防御力下降**
- **消化期间无法使用吸附**

设计上它是**第三条处置胃袋的出路**（另外两条是喷吐、以及不管它等引信烧完），而且是唯一**把库存变成收益**的一条。
这让"我现在该吐、该消化、还是该继续吃"成为一个三方权衡。

**为什么排第一个**：它是唯一还没做的**主动管理体积**手段，而体积现在是所有机制的中心量——喷吐和过饱都已经做好了接口（胃袋、体积、移动倍率），消化只需要接上。

**要注意的**：

- 与过饱的关系：消化应该能**熄灭引信**（腾出空间），否则过饱的答案就只有喷吐一种，消化的定位会变得尴尬
- "防御力下降"需要定义：这个游戏没有防御力，只有**无敌时间**和**血量（体积）**。最自然的读法是**消化期间受到伤害加倍**，或**消化期间无敌时间不生效**
- "质量转化为成长能量"需要一个去处：现在体积只有一个上限，没有别的消耗。要么给一个"成长能量"资源，要么让消化**直接提升体积**（但那样又和"缩小"矛盾）。**这是这个里程碑最需要先想清楚的一点**，建议先和作者确认

**验证**：消化中体积**下降**；引信被熄灭；消化期间吸附被禁用；消化完成的收益可量化。

### 07 · 危险食谱：负面食物

**Status:** `needs-info` · 规格第五节第二类

规格把可吞噬物分三类：可吞噬 / **可吞噬但有副作用** / 不可吞噬。第三类已经做了（不可吞的红色标记，目前默认关闭），
第二类完全没做。规格列了五种：

| 目标 | 副作用 |
|---|---|
| 海胆 | 从内部造成伤害 |
| 电鳗 | 让气泡短暂失控 |
| 腐败物 | 降低消化效率 |
| 炸弹鱼 | 在内部倒计时 |
| 油污 | 占据容量且难以排出 |

**这一类是整个设计里风险决策的来源。** 没有它，吞噬永远是纯收益，玩家会无脑吃；有了它，"这个东西值不值得吃"才成立。

**为什么标 `needs-info`**：这需要**五种新的实体**（海胆/电鳗/腐败物/炸弹鱼/油污），每一种都有自己的行为和外观。
在写代码前需要确认两件事：

1. 是一次做完五种，还是先做一到两种（建议先做**海胆**和**炸弹鱼**——一个内部持续伤害、一个内部倒计时，代表两类完全不同的风险）
2. 它们是否**也出现在危险物列表**（即不吞也会伤害你），还是**只有被吞下才有副作用**

**依赖**：炸弹鱼的"内部倒计时"和油污的"占据容量难以排出"都要求胃袋有**逐件状态**。
现在 `StomachItem` 只有 `kind` 和 `age`，需要一个泛化：每件东西可以带一个**行为**。
这是 06 和 07 共同需要的底层改动，**建议先做它**。

### 08 · 配方系统

**Status:** `needs-triage` · 规格第八节

连续吞下特定组合获得临时能力。规格给了 6 种配方（轻盈气体 / 坚硬核心 / 生物电流 / 爆裂混合 / 净化循环 / 捕食本能）并建议单局 6~10 种，且**用图标提示缺的最后一个材料**。

**为什么标 `needs-triage`**：这是**横切系统**，不是单个机制。它需要：

- 胃袋或一个"最近吞过的种类"的记录
- 一个配方表（配置）
- 临时能力的生效与过期（`Player` 已经有一套 `skillRemaining` 类似的计时器可以借鉴）
- **HUD 上的材料提示**（这一条工作量可能比配方本身大）

而且要小心：配方如果只是"吃了 A+B 就变强"，它会**和成长阶段抢角色**。规格自己也提醒了"为了避免玩家只看体积数值"。
建议先和作者确认：**配方是"更强的成长"还是"不同形状的成长"**（前者会和阶段重复，后者才有意义）。

### 09 · 成长流派

**Status:** `needs-triage` · 规格第九节

四条线：无尽暴食 / 高速消化 / 万物弹药 / 危险食谱。

**这是四条"修改已有规则"的集合，不是四个新机制。** 项目里已经有一套天赋/技能系统（`src/talents.ts`、`src/skills.ts`），
所以更可能的做法是**把四条线做成四组天赋效果**，而不是另起一套。

**依赖**：09 的每一条都建立在 06/07/08 之上——无尽暴食要靠消化、危险食谱要靠负面食物、万物弹药要靠喷吐的扩展。
**所以 09 应该排在最后。**

**先要确认**：单局是**随机给一条**（像现在的天赋），还是**开局选**？这决定它是"重玩价值"还是"构筑玩法"，两者对 UI 的要求差很多。

### 10 · 体积与质量的分离

**Status:** `needs-triage` · 规格第二节

规格要求**质量**（吞噬了多少物质：冲撞力、抗洋流、可吞等级、技能消耗、得分倍率）与**体积**（碰撞范围：口径、吸附范围、转向、缝隙、被打中概率）**分离**，玩家通过消化把质量转成永久能力、同时缩小体积。

**这一条我目前是刻意简化的**：现在质量就是体积（`volume` 一个量），因为规格的第一节（食物链反转）先做时它足够，
而且它让机制立刻可玩、可测。**但规格作者明确说了两者不应完全同步**——所以这是一个**已知的欠账**，不是遗漏。

**为什么标 `needs-triage`**：这是**改地基**，会牵动几乎所有文件（体积出现在每一处判定里）。
在动手前需要确认：

- 分离之后，"血量"跟哪个走？规格没说。现在血量 = 体积 / `hitCost`。如果体积可以主动缩小，血量就会跟着掉，**这会让消化变成自杀**，除非血量跟质量走
- 得分倍率跟质量走的话，结算是要改的

**建议**：等到 06（消化）做完之后再评估——消化是唯一同时改变两个量的操作，它会**暴露出简化的具体代价**，
那时候再决定要不要分离，比现在空想更准。

### 11 · 场景与关卡：更多障碍用法

**Status:** `ready-for-agent`

障碍系统已经做好并接进了时间线，但只用了最基础的两种排布。规格里还提到几种用法没做：

- **渔网**：木箱的变体，撞不碎但可以撕开
- **封路木箱**：需要喷吐才能打碎的厚墙（现在木箱一炮就碎）
- **强制高速卷屏**：规格第十节把它列为最克制吞噬气泡的环境之一
- **狭窄通道群**：连续的珊瑚窄缝，把"极限瘦身"从单次事件变成一段体验

**为什么单列**：这是**内容**，不是机制。机制已经在了，加东西就行。
优先级应该低于 06/07——但**成本也低**，适合夹在大的里程碑之间做。

| 项 | 现状 | 什么时候该重新考虑 |
|---|---|---|
| **气泡内部显示具体物品** | 过饱时只是轮廓鼓包，没有把吞下的东西画出来 | 规格说"内部物品清晰可见"既是容量表达也是笑点。等胃袋有逐件状态（06/07 的底层改动）之后再加，否则画不出有意义的差异 |

| **摇杆改为"按下处浮出"** | 现在固定居中 | 已经决定固定圆盘（可被学会 vs 单次舒服），不打算改 |

## 四、待确认的调参问题

这些不是待办，是**需要作者判断的数值问题**，我列出观察但没有答案。

1. **阶段晋升阈值**：`absorbToStage2 = 12`、`absorbToStage3 = 20`。一局 60 秒，到阶段 3 需要 32 只。
   按现在的泡泡密度是否偏慢？（未实测过一局能吃到几只）
2. **`volumeMax = 10`**：为了让五档食物链全部可达而设。是否偏大？
3. **过饱引信 5 秒**：够不够把东西吐出来？配合 `capacity = 3`、喷吐冷却很短，理论上按三下就解除了。
4. **珊瑚耐久 3.5**：`projectileDamage` 1.2 × 蟹 1.6 = 1.92，所以珊瑚要两炮。是否合适？
5. **`minGapFraction = 0.17`**：约等于体积 1 气泡直径的 1.6 倍。紧还是松？

调这些不需要改代码，改 `config/mechanics.json5` 存盘即可。

## 五、建议的顺序

```
06 消化压缩              ← 唯一还没做的主动管理体积手段
    └─ 先做「胃袋逐件状态」底层改动（06 和 07 共同需要）
07 危险食谱（先做 1~2 种） ← 风险决策的来源，但需要先确认范围
11 关卡内容（夹缝里做）    ← 成本低，适合穿插
08 配方系统              ← 横切系统，需要先确认定位
10 体积/质量分离          ← 改地基，等 06 之后有了证据再决定
09 成长流派              ← 依赖上面全部
```

**每一轮的做法**（沿用已建立的约定）：

1. 数值先进 `config/mechanics.json5`，中文注释，加载器逐项校验
2. 只做最基础的样式，观感留给作者调
3. 判定规则只写一处，碰撞与视觉问同一个函数
4. 写 `e2e/<机制>.spec.ts`，**只跑它**，不跑全量
5. 提交信息记下**做错过的假设**，那是这个项目最有价值的部分
