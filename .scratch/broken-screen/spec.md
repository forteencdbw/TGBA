# 血量告急：屏幕边缘的裂纹

## 1. 这句话

**血量掉到 30% 以下时，屏幕四边向内长出裂纹——气泡要碎了。**

程序生成的矢量裂纹，颜色跟随当前路线/阶段的 HUD 色，强度只跟血量走。

---

## 2. 为什么是程序生成（这条先查过，结论是不用找素材）

项目里**非生物**的东西全部是 Graphics 画的：水体渐变、视差、星点、HUD、爆炸环、Boss 血条。屏幕边缘效果正属于这一类。

素材路线的两个硬伤：

1. 美术管线（Seedream → 像素化 → 图集）产出的是**固定像素密度**的图，而屏幕从 390×844 到 1920×1080 都在跑。边缘效果要铺满就得拉伸，一拉伸就破坏"一个密度"这条规则。
2. 裂纹天然是**沿边框**的，而边框长度随屏幕变——贴图要么拉伸要么平铺，两种都会露出接缝。

矢量没有这两个问题：任意尺寸都清晰，而且是"沿四边"这个形状本身的自然表达。

---

## 3. 决策

| | |
|---|---|
| 形态 | 沿屏幕四边**向内**生长的分叉裂纹，长短不一 |
| 来源 | Graphics 折线，程序生成 |
| 颜色 | **跟随当前路线/阶段的 HUD 色**（`bubbleStateColor`）：不长的路线青→金→粉，沸腾路线随怒气蓝→橙→红 |
| 触发 | `healthView.current / healthView.max < 0.30` |
| 强度 | 静态，只随血量变：`强度 = (0.30 − 比例) / 0.30`，0 → 1 |
| 脉动 | **不脉动**。画面里已经有水流、粒子、擦边慢动作和闪白，再多一个一直在动的东西就是噪音 |
| 层次 | 画在 **HUD 之下**（和 `flash` 同一层），HUD 永远可读 |

### 阈值统一成 30%

血条变红的 `hud.healthBar.lowThreshold` 现在是 `0.34`，改成 `0.30`，和裂纹同一个数。

理由：两个信号说的是同一件事（"你快没了"），分开设两个阈值会让玩家去比较它们的先后，而那个比较没有任何意义。

### 吞噬路线会一直碎，这是已知并接受的

`healthView` 对吞噬路线是 `当前体积/hitCost` 比 `体积上限/hitCost`，开局 **5/50 = 10%**——所以它**从第一秒起就一直在碎**。

接受它，因为吞噬路线**下一轮就要改成独立血量**（见第 6 节）。那之后再回来把这个效果的两条路线统一。

**不要**为了迁就现状去给吞噬路线单独算一个基准：那个基准活不过下一轮，而且会掩盖"它的血量基准本来就不对"这件事。

## 4. 配置键与默认值

```json5
"hud": {
  "brokenScreen": {
    // 触发阈值：血量比例低于它就出现裂纹。和 healthBar.lowThreshold 是同一个数。
    "threshold": 0.30,

    // 裂纹最多向屏幕内伸进多少，相对短边的比例。
    "reachRatio": 0.16,
    // 刚到阈值时的裂纹条数，以及血量归零时的条数。
    "crackCountNear": 6,
    "crackCountDeep": 18,
    // 每条主裂纹分叉的概率，以及分叉的长度比例。
    "branchChance": 0.45,
    "branchLengthRatio": 0.45,

    // 一条裂纹由几段折线组成、每段长度的随机浮动，以及每段最多转多少弧度。
    //
    // 实现时加的三项，因为**前两版默认值画出来不像裂纹**：段少而转角大的时候结果是折线（像电路板走线）。
    // 段多、每段只转一点，才读得出"裂开的口子"。
    "segmentsPerCrack": 6,
    "segmentJitter": 0.35,
    "segmentTurn": 0.7,

    // 线宽（设计像素）与发光的线宽倍数。
    "width": 2.2,
    "glowWidthRatio": 3.0,
    "glowAlphaRatio": 0.35,

    // 不透明度：刚到阈值时几乎看不见，血量归零时最重。
    "alphaNear": 0.18,
    "alphaDeep": 0.85,

    // 每次生成的随机种子（0 = 每局随机）。非 0 时裂纹形状固定，便于截图对比。
    "seed": 0
  }
}
```

`healthBar.lowThreshold` 从 `0.34` 改成 `0.30`。

---

## 5. 实现落点

| 文件 | 改动 |
|---|---|
| `src/main.ts` | 一个新的全屏 Graphics 层，插在 `flash` 旁边（HUD 之下）；按血量重算裂纹 |
| `src/mechanics.ts` | `hud.brokenScreen` 的类型与校验规则 |
| `config/mechanics.json5` | 上面那段；`healthBar.lowThreshold` 改值 |
| `src/background.ts` | 无（裂纹是屏幕层，不是 HUD 层） |

**重算时机**：只在血量比例**跨过阈值或变化超过一个小步长**时重画，不是每帧——裂纹是静态的，没必要 60Hz 重建一堆折线。形状只在比例变化时重新生成，颜色变化只改 tint。

---

## 6. 后续迭代（这次不做，但记在这里）

**吞噬路线改成独立血量，体积与血量解绑。**

- 血量成为主要单位，照不长的路线那套走（默认点数、受击扣点、突变卡回血）
- **血量档位决定体积**：约 30% / 50% / 80% / 100% 各对应一档体积
- 体积不再是血量的容器，而是血量的**表现**

这一轮不做，但它决定了第 3 节里"接受吞噬路线一直碎"这个决定：那个现象的生命周期只到下一次迭代。

## 7. 留给 owner 调的数值

- 阈值 `0.30`（和血条共用）
- 裂纹伸进屏幕的深度 `reachRatio`、条数（两端各一个）、分叉概率
- 线宽、发光强度、两端的不透明度
- 颜色**不在配置里**——它跟着路线/阶段的 `hudColor` 走；要固定成一种颜色的话那是另一件事
