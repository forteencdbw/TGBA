# 血量与体积解耦 · HUD 血条 · 光晕与擦边

## 1. 这句话

**没选吞噬路线，气泡从头到尾一样大；血量不再由体积兼职，改成 HUD 左下角一条独立的血条。**

三件事一起做，因为它们互相咬合：拆开血量和体积，血量才有位置给自己；血条有了位置，光晕才可以让出"我是边界"这个角色。

---

## 2. 现状（改动的理由，都是查证过的数字）

| | |
|---|---|
| 血量 | `volume` 同时是血量和大小。开局 `1.0` → 挨 **5** 下，满体积 `10.0` → 挨 **50** 下 |
| 视觉半径 | `laneRatio × (0.82 + 0.18 × volume)`，体积 1→10 时半径只涨 **2.6 倍** |
| 结论 | 血量的变化速度是可见大小的近 **4 倍**。玩家从气泡大小读不出"我快死了" |
| 吸收 | `growsByAbsorbing` 对 base 和三条路线**全是 true**，吃泡泡都长大 |
| 已经写好但没启用的路 | `run.ts` 里 `grows === false` 的分支：吸收改给分（`score.absorb = 5`），不推进阶段。**零个 form 用它** |
| 光晕 | 外圈画在 `radius × 1.55`，内圈 `× 1.18`；碰撞与绘制共用同一个半径函数，所以外圈是纯装饰外扩 —— 玩家看到的最外沿比真正会碰到的边界大 **55%** |
| 擦边 | 判定是 `(玩家半径 + 怪物半径) × 2.0`，比光晕宽松得多；已有反馈是水里一个「擦边！！」大字 + 全世界慢放半秒 |

---

## 3. 决策树

### 3.1 血量模型

**非吞噬路线（base / 沸腾 / 弹幕）**
- 气泡大小**恒定**：吸收不长大，挨打也不缩。体积冻结在开局值，碰撞半径因此恒定，危险度不随血量变化
- 血量改成**独立数值**，与体积无关。默认上限 **5 点**（= 现在开局的 5 下），挨一下掉 1 点
- 吸收泡泡**给分不给体积**（`score.absorb = 5`，配置里已有）
- 回血**只有一条路**：「修复血条」突变卡
- 阶段（stage）不再推进 —— 这是"不长大"的必然结果，而且是对的：阶段的速度惩罚是长大约的代价，不长的路线不该付

**吞噬路线**
- **完全不变**：体积仍然是血量，吃泡泡仍然长大，5 → 50 下
- 长大同时是变强（血更多）和变弱（判定框更大、速度更慢），这条张力原样保留

**base（还没选路线）**
- 与非吞噬路线一致：不长大。理由是「吃=变大」这个手感一旦建立，选了非吞噬路线再收回，比一开始就不给难受

### 3.2 HUD 血条

- **位置：屏幕左下角**。左下角现在是空的 —— 触屏按钮全在右下角一列（skill 最下、往上叠 charge/burst），拖动是"屏幕任意位置起手"，血条是纯显示、不参与命中测试，所以不挡操作
- **形态：固定长度的进度条 + 数字 `3/5`**。条的长度不随血量上限变化，只有填充比例在动；两种路线同一套画法
- **两条路线都显示**。吞噬路线的血量是 5～50 的连续量，同样从气泡大小里读不出来
- **数字格式 `当前/上限`**：吞噬路线长到 50 时它自己变成 `37/50`，不用换一套读法

### 3.3 突变卡

| 卡 | 改动 |
|---|---|
| `armor` 减伤 +8% | **文字不变**，作用对象从"每次扣的体积"改到"血量"上。对固定血条就是每次少扣 8% 的血；对吞噬路线仍然减少体积损失 —— 同一个 `shrinkResistance`，两条路线各扣各的那一份 |
| `heal` 修复体积 | **改为「修复血条」**，回 1 点血。对吞噬路线，1 点 = 0.2 体积 |
| `maxHp` 血上限 +1 | **新增卡**。`routes: 'all'`，可无限叠加（与非吞噬路线没有封顶一致）。**对吞噬路线加的是 0.2 体积** —— 与"体积=血量"完全一致，气泡跟着大一点点；体积撞到 `volume.max = 10.0` 之后这张卡对它自动失效（现成的 `available` 条件就能筛） |

### 3.4 光晕与擦边

- **光晕：删掉外圈（1.55），保留内圈（1.18）**。可见边界 = 碰撞边界，距离误判归零。内圈剩下那点溢出在深色水里读作气泡高光，不像轮廓
- **擦边：气泡边缘闪一下**（在现有的「擦边！！」大字 + 慢动作之上叠加）。闪的是玩家自己的气泡，不是怪身上的圈 —— 强调"差一点碰到的是你"。不常驻显示擦边圈，那会变成瞄准辅助

## 4. 配置键

### 新增

```json5
// 非吞噬路线的固定血量。与 volume 是两套经济：这套不参与大小。
"health": {
  "start": 5,          // 开局上限（点）。1 点 = 挨一下
  "healPerPick": 1,    // 「修复血条」每级的回复量（点）
  "maxPerPick": 1      // 「血上限 +1」每级的增量（点）
}
```

```json5
"hud": {
  "healthBar": {
    "x": 18,              // 离泳道左边缘（设计像素）
    "y": 26,              // 离画布底边（设计像素）
    "widthRatio": 0.45,   // 固定长度，占泳道宽度
    "height": 8,
    "trackColour": 0x0a0f1c,  "trackAlpha": 0.72,
    "fillColour": 0x6fe3ff,   "fillAlpha": 1,
    "lowColour": 0xff6b6b,    // 血量低于阈值时的填充色
    "lowThreshold": 0.34,     // 比例阈值
    "borderColour": 0xffffff, "borderAlpha": 0.35,
    "labelSize": 12, "labelColour": 0x7fc4e8, "labelGap": 8
  }
}
```

```json5
"graze": {
  // ... 现有键不动
  "playerFlash": {
    "seconds": 0.25,      // 闪多久
    "colour": 0xffffff,
    "alpha": 0.9,         // 峰值不透明度
    "widthRatio": 0.22    // 描边宽度，相对气泡半径
  }
}
```

### 删除

- 每个 stage appearance（`stages.appearance`、rage 的四档）里的 `glowOuterAlpha`、`glowOuterRadiusRatio` —— 外圈没了，这两个键没有读者

### 不动

- `volume.start / max / hitCost / absorbEfficiency / laneRatio`：吞噬路线整套照旧
- `score.absorb = 5`：本来就是为"不长的类型"写的
- `graze.radiusMultiplier = 2.0`：擦边判定范围不变，只是多一个视觉确认

## 6. 连锁影响（要一起看的）

1. **难度确实上升**：非吞噬路线以前可以靠吃泡泡回血，现在只有突变卡能回。5 点血打一整关，中后期挂了一格就是挂了一格
2. **`maxHp` 卡会稀释卡池**：它可无限叠加，后期池子变薄时它会成为常客 —— 这正是"numeric cards stack"那条设计要的效果
3. **消化（`drainByDigesting`）** 现在只作用于体积。实现时确认它是否还需要碰血量（当前 `spit` / `compress` 是 dormant，可能没有调用方）
4. **非吞噬路线不能再吃生物**：本来就不能（`swallowsHazards: false`），这条不受影响
5. **非吞噬路线能吃的泡泡范围恒定**：体积冻结 → 半径恒定 → `playerR >= bubbleR * 0.92` 的边界恒定。撞上更大的泡泡仍然受伤

## 7. 留给 owner 调的数值

以下都进了配置，默认值是我按"沿用现状手感"挑的，不是设计结论：

- 血量上限 **5**（`health.start`）
- 血条的长度、高度、离左下角的距离（`hud.healthBar.*`）
- 低血量变色的阈值 **34%**（`hud.healthBar.lowThreshold`）
- 修复卡回 **1** 点、血上限卡每级 **+1** 点
- 擦边闪光时长 **0.25s**、宽度、颜色（`graze.playerFlash.*`）
