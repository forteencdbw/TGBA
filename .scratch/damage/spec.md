# 血量与伤害：从"点数"换成"数值"

## 1. 这句话

**血量上限 100，每个敌人有自己的伤害，玩家的防御是一个能堆的整数。**

公式：`扣血 = max(伤害 × 10%, 伤害 − 防御)`

---

## 2. 现状（查证过的事实，其中有两条和最初的描述不一样）

| | |
|---|---|
| `damage` 字段 | **已经存在**：`hazards.<kind>.contactDamage`（喷口 5、水母/虾各有值、六只 BOSS 每只一行），`enemyBullets.shooters.<kind>.damage`（手枪虾 2）。普通鱼等几处硬编码 `damage: 1` |
| 施加方式 | `for (i < damage) takeHit()`，而 takeHit 扣 `1 × (1 − shrinkResistance)` |
| 实际公式 | **已经**是 `敌人伤害 × (1 − 减伤)` |
| 真正的缺口 | 数值空间。血量上限 **5 点**，所以伤害只能是 1/2/5 这种整数，而 `−8%` 作用在 1 点上等于 0.92——小数血量和整数伤害挤在一起 |
| 六个受伤来源 | 敌人接触、敌方子弹、障碍物碰撞、怒气失控（3 点）、连锁放电自伤（1 点）、垃圾袋吸取（每秒 1 点） |
| 喷口不是必杀 | 写的是 `contactDamage: 5`，开局 5 点血时确实必死，但血量长大后就扛得住。README 里"进去就是死"是**设计意图**，不是当前行为 |

---

## 3. 决策

### 3.1 数值规模

- **血量上限 100**（`health.start`），死亡是 `血量 ≤ 0`
- **敌人伤害 5~40**，每只单独标定（见第 4 节的默认表）
- 换算是 ×20：现在开局 5 点、鱼 1 点 = 挨 5 下；新的 100 / 20 保持同样的手感

### 3.2 伤害公式

```
扣血 = max(伤害 × 0.1, 伤害 − 防御)
```

- **纯减法，没有百分比抗性**。`shrinkResistance` 整个移除——混合公式被否掉了，理由是"防御 + 抗性"两个通道对玩家太复杂，而操作才是这个游戏的主菜
- **保底 10%**（不是固定 1 点）：在 100 制下 `max(1, …)` 几乎等于没保底——20 伤害的鱼打 30 防御的玩家每下掉 1 点，等于无敌。10% 的意思是"防御最多吃掉九成"
- **防御的初值是 0**，且**没有上限**（可堆叠的整数正是这次要的养成要素）

### 3.3 六条来源

| 来源 | 吃不吃防御 |
|---|---|
| 敌人接触、敌方子弹、障碍物碰撞 | **吃**（世界打你） |
| 怒气失控、连锁放电自伤、垃圾袋吸取 | **不吃**（`defense` 传 0） |

自伤不吃防御，是因为防御若也能挡自己的失误，怒气经济就失去闸门——玩家堆防御等于把"要不要压着怒气"这个决定一起删掉。它们仍然走**同一套扣血代码**，只是防御参数为 0。

### 3.4 没有"一击必杀"

喷口不再是必杀，而是一个**介于精英和 BOSS 之间的高伤害**（默认 35）。血量上限可以成长，所以"够大的伤害"是个会过期的判断，而"必杀标记"会引入第二种伤害单位。

### 3.5 卡与天赋

| 现在 | 变成 |
|---|---|
| `armor` −8% 扣血 | **+2 防御** |
| （新） | **+5 防御 大卡**，和 +2 并存 |
| `heal` 回 1 点 | 回 **20** 点 |
| `maxHp` +1 上限 | **+20** 上限 |
| `silt` 天赋 `shrinkResistance: 0.6` | **+15 防御** |

防御的来源就这三个：`armor` 小卡、+5 大卡、`silt` 天赋。天赋每关重掷，所以防御会跟着关次波动——这正是天赋该有的样子。

### 3.6 吞噬路线

- **三条路线共用一套血量**（吞噬不再"体积 = 血量"）
- **体积由血量档位决定**，四档：

  | 血量比例 | 体积 |
  |---|---|
  | < 30% | **2** |
  | 30–50% | **5** |
  | 50–80% | **8** |
  | ≥ 80% | **10** |

  最小档要**明显**小（2 而不是 5），因为"我快碎了"应该同时被三样东西说出来：血条、屏幕裂纹、以及一颗小到能钻过去的气泡
- **档位只在关卡开始时重算**，战斗中不掉档。判定框在战斗中突然变小会让"贴多近能吃"的时机判断失效
- **吃泡泡只加当前血量**（不加上限）。上限只由 `maxHp` 卡给

### 3.7 HUD

血条数字写 `87/100`——上限是会变的（`maxHp` 卡、+5 大卡），而"该不该拿下一张血上限卡"取决于离上限多远。

## 4. 数值标定表（**默认值，按危险度标的，你调**）

### 敌人接触伤害

| 伤害 | 谁 |
|---|---|
| **10** | `mineral` 矿物颗粒 · `rain` 雨 · `foam` 碎浪泡沫 · `trash` 垃圾袋（吸取另算） |
| **20** | `fish` 鱼 · `tuna` 金枪鱼 · `shrimp` 盲虾 · `crab` 螃蟹 · `urchin` 海胆 · `archer` 射水鱼 · `starfish` 海星 · `puffer` 刺魨 |
| **30** | `dolphin` 海豚 · `jelly` 水母 · `angler` 灯笼鱼 · `torpedo` 鱼雷 · `zapper` 电击水母 · `pistol` 手枪虾 · `eel` 电鳗 · `rot` · `oil` |
| **35** | `octopus` 章鱼 · `shark` 大白鲨 · `bombfish` 炸弹鱼（爆炸） · `whale` 座头鲸 · **`vent` 喷口** |
| **40** | 六只 BOSS |

### 自伤（不吃防御，所以这几个数是**原值**）

| 来源 | 现在 | 变成 |
|---|---|---|
| 怒气失控 | 3 点 | **60**（一关 100 血里的一多半，够疼但不再是死刑） |
| 连锁放电自伤 | 1 点 | **20** |
| 垃圾袋吸取 | 每秒 1 点 | **每秒 20** |

### 敌方子弹

`shooters.<kind>.damage` 的校验范围从 0–10 放宽到 **0–60**，现有值 ×20（手枪虾 2 → 40）。

### 吃泡泡回血

`absorbEfficiency` 保留，但单位从"体积"变成"血量"：一个泡泡回的血量 = `泡泡体积 × absorbEfficiency × 20`（沿用旧的 ×20 换算，这样"吃小泡泡不划算"的手感不变）。

## 6. 两步落地

**第一步：公式 + 数值规模。** 100 制血量、减法防御、敌人伤害表、三张卡重标、六条来源。跑起来能独立验证：防御对不对、挨几下死、一局打成什么样。

**第二步：吞噬的血量模型 + 体积档位。** 只有在血量已经是 100 制之后才有意义。

合成一个提交的话，手感不对时分不清是公式错了还是档位错了。
