# 冒泡大作战 / Bubble Battle

一个关于「涌现」的 GameJam 项目。9:16 竖屏、手机优先、浏览器直接玩。

设计文档：`.scratch/bubble-ascent/spec.md`（吞噬气泡的完整设计）
　　　　　`.scratch/bubble-ascent/types/angry.md`（暴躁气泡，第二种类型）
后续工作：`.scratch/bubble-ascent/plan.md`（做到哪里、还剩什么、刻意没做什么）

## 一种基础气泡，两条路线：先玩，再定身份

**没有选角色了。** 每一局都从同一个**基础气泡**开始：一把自动开火的枪、**一个从头到尾一样大的身体、一条自己的血条**。它是这个游戏的地基；而**成长**不再是地基
的一部分——它是吞噬路线那一张卡带来的东西，见下面「血量：两条路线，两套经济」。

身份在**进游戏之前**定：点「开始游戏」之后是一屏**形态选择**，选中哪一种就用哪一种开局，本局另外一条路线的卡永不再出。
（上一版是「第一次升级的三选一」；身份现在是**一局的第一个决定**，而不是局内的一次奖励。）

| | **原样开局** `base` | **吞噬** `devour` | **沸腾** `boil` |
|---|---|---|---|
| 宣言 | 什么都不加：枪、成长、操作，全靠这一局自己挣 | 食物链反转：吃掉一切，越大越强——代价是越来越难躲 | 以怒为刃：越挨打越烫，满怒自动炸开，靠近你的人自己烧起来 |
| 选它立刻得到 | 什么都不加——**始终可选，不用解锁** | 贴脸即吞 + 吸附按钮 | 怒气槽 + 怒甲节拍 + 贴身灼烧（**一个主动按钮都没有**） |
| 配色 | 成长阶段（青→金→粉） | 成长阶段（青→金→粉） | **换成怒气**（蓝→橙→红） |
| 专属卡（进池） | 无：共用池就是它的池 | 吸取范围 / 吞噬无敌 / 大胃口 | 怒气积攒 / 爆破半径 / 余温 |

**每一次三选一都是均匀抽卡**：没有分支节点，也没有首抽保底——那是「在水里选身份」时代的两个例外，
和那次选卡一起删掉了（形态开局就定了，没有节点可站，也没有「刚买的身份」要立刻深化）。

> 这是"第二刀"：类型系统曾是开局菜单上的三选一（吞噬/暴躁/普通气泡），砍掉它的理由和砍胃袋同源——
> 一个"比基础还少"的玻璃炮角色（普通气泡，一滴血不成长）和分支"在基础之上长出什么"的方向相反；
> 而把身份搬进游戏里，选路线这件事本身就成了一局的第一个决定。普通气泡随选角行一起删除，它的
> 精神（玻璃炮）以后可以作为突变卡回来，不占路线位。

**按钮布局属于形态，不属于全局** —— 这是设计文档里定下的架构决定：某个形态自己的输入就写在那个形态的
控制表里，别的形态不受影响。触屏层在选卡的那一帧重排按钮（`applyFormToTouch`），画布上的控件和形态永远不会是两个时代的。

**外观命名空间也是按形态分开的**：成长阶段管速度与大小，怒气管颜色与形变（沸腾路线在选定那一刻
把配色从成长切到怒气——"我有多烫"从此写在气泡上），两者不会抢同一块画布。

### 基础气泡：每局的地基

- **它有枪**（`firesBullets: true`）：枪是这个游戏的默认武器，不是哪个角色的能力。没有它，每个生物都是
  必死的障碍物，唯一的选择就是跑。
- **它不长大**：吸收泡泡**给分**（5 分一颗），气泡保持开局大小；血量不在体积里，而是左下角那条血条
  （100 制，见下面「血量与伤害」）。**想变大的话得选吞噬路线**——那条路线的体积跟着血量走（见「体积」一节），
  不是每个气泡的默认。HUD 的状态行会写「不成长」，选定路线后带路线名前缀（如「吞噬 · 幼泡 1阶 0/12」）。
- **它没有**吸附、不能吞危险物、没有怒气：这些是形态的事。**每一局开局就是把这一摊交给一种形态**，
  而选形态发生在见到水**之前**——没有「纯地基的一分钟」了，因为那一分钟被那一屏取代了。

### 沸腾路线：三个被动，一个按钮都不留

这一轮把它整条重做了：**压缩蓄力 + 冲撞**和**失控倒计时**都删掉，换成三条被动。两处删掉的理由是同一个——
**它们都在夺走操作**：冲撞是一次玩家没要求的位移，失控是一段四秒的"变笨"，而这条路线的全部卖点是
"主动贴上去打"。现在它**一个主动按钮都没有**，**走位完全由玩家自己决定**。

主干是 **积怒（挨打）→ 满怒自动爆破** · **怒甲按节拍攒 → 撞人消耗** · **贴身灼烧常驻**：

- **它不能吞危险物。** 这是它和吞噬路线最根本的差别。碰到敌人就是挨打——而那正是设计要的：它的怒气
  来源就是被打。它只吃气泡（食物），靠接触、不靠吸力，所以收集得笨（设计第九节把"精准收集能力弱"
  列为它的弱点，这里采用了最彻底的读法）。
- **怒气只从"挨打但没破"来**。致命伤会结束这一局，没有状态可以携带怒气，所以也不可能有"死了还赚
  怒气"这种事。**它和怒甲是两条独立的线**：怒气是引信（挨打攒、满了就放），怒甲是弹药（按固定节拍
  攒、撞人时花）。让怒气影响攒甲速度，会把"我现在能不能撞"变成第二张要读的表。
- **满怒就是那一发**：怒气槽的顶端不再是"失控倒计时"，而是**自动放掉的爆破**（一次花光全部怒气）。
  检查放在衰减**之前**——跨关带过来的满条也必须放得出来，否则它每帧被扣掉一点，`>= 满` 永远不成立，
  那一发会安静地永远不放。
- **怒甲**：每 **5 秒**攒 1 个、最多存 **2** 个。**撞上敌人时消耗 1 个**：**你不挨打**、它吃 **20 点**、
  并且中**破甲**（`受到的所有伤害 ×1.5`，持续 4 秒）。没有甲的时候接触照旧挨打——"碰到就疼"这条
  全游戏最基础的规则没有消失，它只是**被变成了资源**。撞不死的才吃破甲（鱼、虾、水母、鱼雷这类薄的
  一下就被撞死，章鱼、鲨鱼、鲸、鮟鱇、海胆、BOSS 才是它的对象），所以它是**一张给大东西用的记号**。
- **撞击也保留撞开封路木箱的能力**（`angry.armour.breaksUnrammable`，改成 `false` 就让它对木箱无能
  为力）。这不是顺手保留：**子弹打不坏障碍物**，而爆破按设计也打不开砖石——冲刺没了之后，**怒甲撞击
  是沸腾形态唯一能开墙的动作**。
- **贴身灼烧**：半径 **2.5 × 你自己当前的半径**（跟着气泡长，所以永远是"贴着你"）、每 **0.5 秒**一跳。
  它是这条路线唯一**不花怒甲也不靠挨打**的伤害来源——没有它，玩家在没挨打、怒气也没满的时候完全无害，
  而近战特化不该有那种空窗。破甲的敌人被它烧得更疼（破甲乘的是**所有**伤害）。
- **怒气爆破**：满怒自动放，以气泡为中心一圈冲击波，**怒气越高范围越大**（0 = 0.22 泳道，满 = 0.85）。
  它做三件事，而且**"清"和"推"是分开配置的**：
  - **清掉软体小敌人**：鱼、水母、垃圾袋；
  - **弹开清不掉的尖锐危险物**：海胆、电鳗、炸弹鱼——推得动但清不掉，所以冲击波对它们是"给我让开"
    而不是"删掉"；螃蟹也是推开，因为它是机会不是敌人；
  - **震碎脆弱障碍**：伤害 1.6 刻意只够木箱（1.0）和渔网（0.4），**珊瑚（3.5）和封路木箱（3.0）只掉
    一层皮**——开墙是怒甲撞击的活。
  哪一种是"清"、哪一种是"推"写在 `angry.burst.hazardMode`，**每种危险物都必须有一行**，缺一行是加载
  报错——否则那种生物会安静地免疫冲击波，看起来像设计而不像漏写。
- **怒气槽**：HUD 文字下面一根条，填充色就是当前怒气阶段的颜色，**刻度是阶段阈值**。
  **三个阶段**：平静 0 / 烦躁 25 / 暴怒 55——原来第 4 段"失控"（85 以上、一段四秒的倒计时）删掉了。

**沸腾路线到此闭环。** 设计文档的切分表里只剩 **G（环境内容：船锚、逆向洋流、可反弹墙面）**，
那是纯内容，它依赖的东西已经全部到位。

配置在 `angry` 段（怒气收支、**怒甲**、**贴身灼烧**、爆破、三个阶段的外观、共用几何、怒气槽），
全部有中文说明；`node scripts/probe-rage.mjs` 把这三条被动的承诺逐条断言了一遍。
路线本体（名字、动词、专属卡）在 `src/bubbleTypes.ts` 的 `ROUTES` 表，和基础形态 `BASE_TYPE` 放在一起。

## 版本号：这一页跑的是哪个 build

**主菜单底部**和**关卡内左上角调试读数的第一行**都会显示：

```
v1.0.0 · 51be519 (uncommitted)
```

- **版本号**唯一来源是 [`package.json`](package.json) 的 `version`。**每次改动都在同一个提交里递增它**
  （1.0.1、1.0.2……），这条写在 `AGENTS.md` 里。为什么要有版本号：手机上的页面、部署出去的 URL、
  别人发来的一张截图，都回答不了"我看的是哪一版"。
- **git hash** 由**构建时**从 git 读出来（见 [vite.config.ts](vite.config.ts) 的 `define`），
  不是手写的——手写的 hash 就是一个会撒谎的 hash。
- **`(uncommitted)`** 表示打这个包的时候工作区有未提交改动，也就是：**这页是那个提交再加一些别人复现不出来的编辑**。
  没有这个标记，hash 会悄悄宣称比它知道的更多，那比什么都不显示更糟。

两个值都**不是运行时读的**：浏览器里没有 git，手机上没有文件系统。它们在你启动 dev server /
执行 `pnpm build` 的那一刻被**编进包里**（`src/version.ts` 是唯一的出口）。

> ⚠️ **dev 下它是在 Vite 启动时读一次的。** 提交之后显示的 hash 会过期，直到 Vite 重启（改这个文件会触发重启）。
> 这是**诚实**的：那个浏览器里的页面确实是用旧代码加载的。

## 改数值看这里

**所有可调的机制数值都在 [`config/mechanics.json5`](config/mechanics.json5)**，每一项都有中文说明。
改完存盘即可，页面会自动重载（Vite HMR），不需要重新构建。

格式是 **JSON5**（JSON 的超集），所以：

- `//` 行注释和 `/* */` 块注释
- 最后一项的尾逗号
- 键名不加引号
- 颜色写 `0x9fe4ff` 十六进制字面量（写 `"#9fe4ff"` 字符串也认）
- **写错"是什么"会在浏览器控制台报错并指出是哪一项**：把数字写成字符串、把颜色写成 `red`、把该给列表的
  地方给了个对象、少了一个数组元素、拼错一个枚举值。报错点名那一项，不会静默退回默认值——一个悄悄失效的
  配置文件比没有配置文件更糟
- **但数值的"大小"不查**。写多大的数都收，包括明显写错的那种。这是有意的：范围校验是**设计的第二份
  副本**，写在一个没人调参的文件里——两份不一致时赢的总是那份副本，于是你在配置里改一个完全能玩的数，
  页面反而打不开。那比它想防的坏数字更糟：坏数字一跑就看得见，而被拒绝的好数字看起来像游戏坏了。
  校验管的是**形状**，不是**平衡**
- **文件里每一个值都必须有校验规则**，而且这条是**双向**的：加了一个键却没有给它规则，页面会打不开并
  点名那个键（`src/mechanisms.ts` 末尾的覆盖检查）。否则一个拼错的键名就是"静默无效"，正是上一条要避免的事
- 运行时的 `window.__GB.tuning` 和它是**同一个对象**，所以控制台里改和改文件是一回事
  （`tuning` 的每一个成员都是 getter，直接读写 `mech`——它曾经有一半是**加载时抄下来的值**，
  在那几个名字上赋值是没有反应的，而且看不出来：一个被抄下来的数字和一个活的数字长得一模一样）

代价是 json5 解析器会进包：**主包 +33 kB（gzip +10.5 kB）**，一次性。这是"配置文件人能手工编辑"
的价格。

`src/mechanisms.ts` 负责读取与校验，`src/config.ts` 只保留**不是数值旋钮**的东西（设计分辨率、
世界投影、标定契约），因为那些改起来会牵动代码而不只是平衡。它另外导出 `tuning`：一份把配置里
**按系统分组**的路径换成**按玩法命名**的活别名（`tuning.hitPointVolume` ⇄ `mech.volume.hitCost`），
每个成员都是 getter，所以控制台里改它和改 `mech` 是同一件事。

### 关卡：一关一个文件，在 `config/levels/`（手工配置刷怪）

**关卡是数据，不是代码。** 一个关卡 = 一段水域 + 一张刷怪表 = **一个文件**：

```
config/levels/
  01-black-smokers.json5     第一关 黑烟囱墓场
  02-wreck-gorge.json5       第二关 沉船幽谷
  03-jelly-forest.json5      第三关 发光水母林
  04-thermocline.json5       第四关 猎食者温跃层
  05-storm-surge.json5       第五关 风暴暗流
  06-dawn-surface.json5      第六关 破晓海面
```

**文件名前面的编号就是关卡顺序**（加载顺序 = 解锁顺序）。加载器是 `import.meta.glob('../config/levels/*.json5')`
按文件名字典序读，所以：

- **加一关** = 加一个文件，不用改代码、不用改索引——没有"第二处要记得改"的地方。
- **在两关之间插一关** = 用 `01b-xxx.json5` 这种号，**不用把后面所有文件改名**，顺序仍然一眼看得出来。
- `config/levels.json5` 还在，但它只是**字段说明文档**（一个关卡能写什么，全在那份注释里），里面的 `levels: []`
  是空的，加载器会跳过空列表；关卡数据不在那儿了。

每一关的文件是**一个 JSON5 对象**，字段见 `config/levels.json5`（那份注释就是字段说明文档）。
**这一关用哪首录好的曲子**写在顶层的 `music` 字段里（曲名，不带扩展名，文件在 `src/assets/audio/music/`）；
两关可以写同一个名字，共用一份文件。不写就按关卡 id 找（旧约定），再找不到就播该关的合成曲。
中文注释和机制配置一样**逐项校验并指名报错**，而且报错**直接说文件名**：

```
levels/03-jelly-forest.json5 (level "jelly-forest"): paths.weave.points[0].y should be a number …
```

**一块刷怪**（`spawns` 里的一项）说清楚四件事：

| 你要决定的 | 写什么 |
|---|---|
| 什么时候 | `at`：相机走过多少米（**按距离，不按时间**，所以改节奏不会让关卡错位） |
| 刷什么、几个 | `kind` + `count`。`kind` 可以是收集物、**`hazards.health` 里列出的每一种生物**（金枪鱼也在内），或障碍物 |
| 怎么摆 | `arrange`：`single` / `line`（横排）/ `column`（竖列）/ `spread`（沿距离摊开，横向正弦摆动）/ `barrier`（留缺口的障碍横排） |
| 从哪边进来 | `from`：`top`（默认）/ `left` / `right` / `bottom`，见下 |

**每一块自己掷一次左/右**：一个 spawn 块被放出来的那一刻掷一次硬币。翻到“镜像”时，这一块的
`x → 1-x`、`from: 'random'` 的侧别换边、path 的每个点 x 取反；整排障碍、整条鱼队因此保持一个形状。
一个块展开出的多条 entry 共用同一次结果。**显式写的 `left`/`right` 不翻**（文件说了在哪边，就以文件为准），
但 `x` 是坐标而不是侧别，所以仍然镜像。

**从四边进场**：`from` 决定内容从哪条边进来，`top`（默认）是视野上方生成、随水流向下漂进画面。

- `random`：每块掷一次，约一半从左、一半从右。**不写 `from` 仍然是 `top`，不是随机**。
- `left` / `right`：在**泳道外**生成，横向游进来，`depth` 决定它在屏幕哪个高度切入（0 = 下边缘，1 = 上边缘）。
  `arrange` 给出的 x 是它**进场后要去的位置**。水流仍在往下带，所以进场路线是斜的。
- `bottom`：在视野下方生成，以比水流更快的速度**向上**追，**一路升到和玩家齐平**才交回给它自己的 AI。
  这一条是必要的：这个游戏里所有东西相对玩家都在下沉，所以如果进场只到"看得见"就结束，它会露一下脸然后
  立刻掉回去。进场速度必须盖过关卡的 `driftSpeed`（生物在屏幕上的下落速度），默认值（45 对 25）有余量。
- **只有生物和障碍物能从侧面/下方进来**：收集物随水流下来，写在配置里会加载报错。
  **障碍物不能写 `bottom`**（布景不会自己往上游）；`left`/`right` 的障碍物会横着漂进来，
  **停在 `x` 指定的位置**（像被水冲过来的木箱），不会一路漂穿泳道。
- 每块可以覆盖 `enterSpeed`；默认值和"出生点在画面外多远""切入高度"这些手感数字在
  `config/mechanics.json5` 的 `spawning` 段，全关卡共用。
- `aboveMeters`：在视野顶边**上方**多少米生成（默认 0 = 贴着顶边）。只给从 `top` 来的生物用——朝下的喷口
  用它把本体停在屏幕外，让更长的火焰先从顶边探进来。它不改 `at`：还是同一时刻放进水面，只是晚几秒才被看见。

**例子**（第一关 `config/levels/01-black-smokers.json5` 里就有这几块，可以改也可以删）：

```json5
// 一小队鱼从随机一侧游进来，散在 24 米里
{ at: 300, span: 24, count: 3, kind: 'fish', arrange: 'spread', from: 'random', depth: 0.68 },
// 同上，但钉死从左边来（显式侧别不翻）
{ at: 340, span: 24, count: 3, kind: 'fish', arrange: 'spread', from: 'left', depth: 0.68 },
// 从下面追上来的两条鱼：压力来自背后
{ at: 900, span: 18, count: 2, kind: 'fish', arrange: 'spread', x: 0.5, from: 'bottom' },
// 被水冲进来的木箱，漂到泳道 0.72 处停下；侧别随机，x 会跟着镜像
{ at: 1010, kind: 'crate', x: 0.72, from: 'random', enterSpeed: 26 },
// 热液喷口：**没有 `x`**，位置由 `side` 推出来（贴着那面墙），朝向相对它自己那面墙。
// 不写 side 就是左右随机；写 side: 'left' 才会钉死。
{ at: 760, kind: 'vent', aim: 'flat' },
```

**火山（`vent`）的三个专属键**：`side`（`left` / `right` / `random`，**可省略**；省略和 `random` 一样，
每块掷一次左/右）、`aim`（`up` / `flat` / `down`，斜向上 / 横向 / 斜向下，默认 `up`）、
`startDelaySeconds`（出现后先安静多少秒，默认取 `hazards.vent.startDelaySeconds`）。
细节见下面"加载器会拒绝的东西"和机制配置里 `hazards.vent` 那一段。

**加载器会拒绝的东西**（每条都会说出是哪一关、第几块、哪一项）：拼错的键名（否则那一项会被静默忽略，
看起来像游戏坏了）、从侧面进来的收集物、从下方进来的布景、把生物排成 `barrier`、
`at`/`kind` 缺失、**没有缺口的障碍横排**（那会让"要不要变瘦"不再是选择题）、
**火山写了 `from`**（它是地形，是它就在那儿，没有东西把它冲进来）、
以及**给非火山写了 `side`/`aim`/`startDelaySeconds`**（那是三个会静默失效的键）。
写错 `count` 之类的数字**不会静默**——但只查它是不是个数，不查它是不是个"合理"的数：见上面机制配置一节
的"数值的大小不查"。

**换关卡**改文件顶部的 `start`（那是**每一局开始**的那一关）；`levels` 数组里可以放多关。


### 节奏：两条曲线，一关一个形状

**节奏的度量单位是"每屏多少秒"，不是"总共多少秒"**（一屏 = `WORLD_HEIGHT` = 190 米）。这条写在
`.scratch/bubble-ascent/spec.md` 里，原因是曾经把总时长当目标、反推出一个曲线，结果**第一屏要 90 秒**——
看起来就是静止的水。而"节奏是一条**形状**，不是一个均值"：一关从头到尾 7.7 秒/屏到 4.7 秒/屏，"平均 5.9 秒"这句话
描述不了其中任何一秒。所以两把尺子**都报成序列**。

```
node scripts/probe-pacing.mjs        # 不需要浏览器，打印六关的两条曲线
```

| 尺子 | 量什么 | 从哪来 |
|---|---|---|
| **秒/屏** | 这一屏要多久走过去 | `scrollSpeedCurve`（见下）。恒定速度时它就是一条平线 |
| **威胁/屏** | 这一屏里的内容拿走了你多少余量 | `pacing.threat` 的权重 × 每块的 `count`，按块开始的屏归位 |

**威胁权重（`pacing.threat`，39 行）** 只服务这一条曲线，**不参与任何玩法**——改一个数不会让任何一只怪变强。
分类的唯一原则是"**它拿走了你哪个选项**"，不是"它有多快 / 多疼"：0 收集物、1 绕开就行、2 它会来找你、
3 它拿掉了你的一个选项（朝你开火 / 封住路线 / 致命地形）。**每个能刷的种类都必须有一行**，缺一个就加载报错——
否则"这关很空"和"我忘了给这种怪算分"在读数上长得一模一样。

**速度曲线（`scrollSpeedCurve`）** 写成 `[[走过多少米, 速度], ...]`，线性插值：

```json5
scrollSpeedCurve: [ [0, 24], [900, 32], [2090, 41] ],
```

- **用米而不是秒**：`at` 也是米，所以改速度**不会移动关卡里任何一个东西**——变的是它们**什么时候**到。
  写成秒的话，每一块手摆的内容、每一串 spline、每一道障碍缺口都得重算。
- **一个点就是常数**，所以没写曲线的关卡行为完全不变——可以一关一关改。
- 总时长和"秒/屏"是**积分出来的**（`1/速度` 的积分没有初等原函数，所以是数值积分），
  `assertLevelSane` 的 10–400 秒边界也按积分后的时长算。
- **横幅 = 爆发点**：`landmarks` 的那一条和刷怪表里那一次爆发落在同一个深度。一个概念，两种表达——
  分开写的话它们必然会漂，而"横幅说爆发、水里没动静"正是第一关原来的样子。
  **所以探针把它打出来**（`banner 1690m深 = 400m 暖水层 <- fish at 400m (+0m)`），差超过半屏就报警：
  `depth` 从水面往下数、块的 `at` 往上数，两者相等当且仅当 `at === scrollLength - depth`，
  而这六个数是六个文件里手写的——上一轮就有三关漂了 20–190 米。
- 横幅只显示关卡自己写的 `label`。曾经有个硬编码的 `EVENT_CALLOUTS = ['鱼群来了','气泡潮','爆发']` 按**下标**
  拼在后面，于是六关的九条横幅说的是同三句话（"管虫丛 · 鱼群来了"）。
- **收集物的分布也是这条读数的一部分**，虽然它一分威胁都不算（`food/scr 6 3 4 - 3 3 - 3 - 8`）：
  威胁序列看不见"食物全堆在开头"这件事，而那正是所有六关原来的样子（中间 45–58 秒空着）。
  细节见上面「收集物的分布本身是一条规矩」。

**六关都按这套改过了**（2026-10-16）。改之前每关都是**恒定速度**、长度只够装它那一轮的内容，所以关卡越到后面越短
（第一关 83 秒，第六关 50 秒）——**最后三关加起来还没第一关一半长**。现在六关是同一条曲线的六个刻度：

| 关 | 米 / 屏 | 秒 / 屏 | 时长 | 威胁 | 威胁/屏 | 威胁/秒 |
|---|---|---|---|---|---|---|
| 1 黑烟囱墓场 | 2090 / 11 | 7.7 → 4.7 | 65.1 | 129 | 11.7 | 2.0 |
| 2 沉船幽谷 | 1900 / 10 | 7.7 → 5.7 | 65.3 | 138 | 13.8 | 2.1 |
| 3 发光水母林 | 1900 / 10 | 8.4 → 5.8 | 69.6 | 154 | 15.4 | 2.2 |
| 4 猎食者温跃层 | 2090 / 11 | 9.2 → 5.5 | 77.2 | 187 | 17.0 | 2.4 |
| 5 风暴暗流 | 2090 / 11 | 10.1 → 5.5 | 80.7 | 211 | 19.2 | 2.6 |
| 6 破晓海面 | 2280 / 12 | 10.7 → 5.7 | 91.9 | 276 | 23.0 | 3.0 |

**四列都是单调的**（密度、时长、每屏秒数、威胁/秒），而**每一关内部也是单调的**：慢着开场，越走越快。
这张表本身由 `probe-pacing.mjs` 打印并在发现倒挂时报警——上一轮就是它抓出"第三关比第四关还密"这个倒挂的。

**第一关的前后对比**（它是这一轮的样板，其余五关照抄这个做法）：

| | 改前 | 改后 |
|---|---|---|
| 时长 / Boss | 83.3 秒 / 76.7 秒 | **65.1 秒 / 60.4 秒** |
| 秒/屏 | 6.3 6.3 6.3 …（平线） | **7.7 → 4.7**（曲线的形状） |
| 威胁/屏 | `9 10 35 30 38 33 15 0 0 0 0 0 0 0` | `3 10 9 19 7 17 24 10 30 0 0` |
| 形状 | **前半挤爆（有内容的那些屏 24.3/屏，全六关最挤）、后半 5 屏空的** | 安静开场 → 起 → **爆发一 19** → 落 → **爆发二 24** → 落 → **顶点 30** → BOSS 前收一屏 |

三次爆发的间隔是 **3 屏 → 2 屏**（第一关）/ **2 屏 → 1 屏**（改前）：紧张感靠"这次来得比上次快"，
不是靠把底噪一点点调高。

**这一轮换来的是什么、代价是什么**：把关卡拉长的同时**内容也跟着长**（六关合计 170 → 1095 分威胁），
否则"时长变长"只是"每秒变得更空"。所以**每秒钟的压力比改前平**（2.0→3.0，改前是 2.2→4.2）——
如果之后想要"同样的强度、更多的时间"，那要把这套量再翻一倍，是另一次作业。

**没有跟着变的是 `driftSpeed`**（生物在屏幕上的速度）：慢下来的是**关卡推进**，不是那些鱼。
两者一起变的话，整关会看起来像水冻住了——那正是最初把总时长当目标时踩过的坑。

### 关卡选择（主菜单最上面一行，**调试专属**）

主菜单最上面那一行关卡选择**只在调试模式下出现**（设置面板 → 作弊区 → 「调试模式」）。关掉调试模式，整行
连同它下面的说明文字一起消失，主菜单就是一个干净的开始按钮，**每一局都从文件里的 `start` 开始**。

- **开着调试模式时，每一关都能点**——锁的概念在阶梯上看不到。解锁规则仍然照算、仍然写进存档，只是在工具
  开着的时候它不参与"能不能点"。
- **阶梯不标"已通关"**：它现在是一个跳转菜单，不必兼任进度显示。填充的那一格是**当前所在的关卡**。
- **一局是从第一关开始一路打上去的**：通关一关会自动进下一关，所以隐藏阶梯不会把后面的关卡卡住。
- **通关时不再播报"新关卡解锁"**：那句话原本是为了让人注意到菜单上某一格变色，而现在没有那一格了。
  存档照写——哪天阶梯恢复成正式功能，数据一直在。

解锁规则本身没变，但它现在只喂存档，不喂 UI：

- **第一关永远算解锁**；第 N+1 关要**通关第 N 关**才算解锁（`cleared` 里必须有前一关的 id）。
  这是**按顺序的规则**而不是"通关了几关"的计数：以后在文件中间插一关，规则依然正确，计数会错。
- **通关 = 击败这一关的 BOSS**（不是活下来更久、也不是跑完距离）。
- 存档会**存进 `localStorage`**，key 是 **`tgba.progress.v1`**，内容是 `{ cleared: ["..."] }`。

### 主菜单的动态背景

主菜单背后是**活的**：鱼一直在游，底部两排珊瑚。点「开始游戏」之后它们**转身游走**，清场后第一关开始。

**它是菜单自己的一个世界，但画的是游戏自己的图。** 菜单有一个属于它自己的 `HazardField` 和一个 `ObstacleField`
（`src/menuBackdrop.ts`），run 的字段一概不碰——所以一只装饰鱼不可能影响你要开的那一局。但画用的是
`paintHazards` / `paintObstacles`：同一批贴图、同一套动画、同一套朝向规则。标题底下游过去的那条鲨鱼，就是
等下会朝你冲过来的那条。

**三层**（显示顺序就是深度顺序）：后层珊瑚（远、小）→ 鱼 → 前层珊瑚（近、大）。从前层珊瑚后面游过去的鱼，
就读作"在更深处"。两份珊瑚是**两个字段**而不是一份画两遍——它们的大小不同，而大小是珊瑚自己的属性。

**出场名单**排除三类：**BOSS**（它的出现是关卡花一整个流程铺垫的节拍，在标题画面随手漂过去就把那个节拍花掉了）、
**环境物**（喷口/矿物/泡沫/雨——那是地形和天气，不是敌人）、以及 `trash`/`rot`/`oil`（那是玩家吃或躲的东西，不是会游的东西）。

**鱼只游**：不追、不冲锋、不开火。菜单里没有玩家，而一只正在冲锋落空的鲨鱼看起来像游戏坏了一半。

**退场是有上限的**：点开始后不再刷新、现有的鱼朝最近的边转身游走，同时跑一个短倒计时；到点剩下的直接不画。
不封顶的话，"等最后一只游出去"会变成等那个**最晚刷出来的**一只，可能是五到十秒的空等。整层同步淡出。

**那十二张泡泡图，收集物也在穿**（`collectableArt`）。为什么是十二张而不是一张缩放的，`menuDrift.ts` 里写着：
像素边框经不起缩放，一张图放大到顶会变成一根粗棒、缩到底会细成发丝。收集物比菜单多一条约束——
**它的大小是玩法**（`半径 = 玩家半径 × 关卡写的比例`，六关里是 0.35–0.7），所以图**缩放到碰撞半径**，
而不是反过来让图决定大小。穿哪张按**它相对你多大**选（0.35 穿最小的那张、0.7 穿最大的），
再对每颗缩放到精确半径：于是**边框的粗细一直在说"它相对于你有多大"**，而那正好是"能不能吃下它"这件事。

**收集物的分布本身是一条规矩**：它的定位是"击败怪物的间隙顺手捡到"，所以它**从头到尾都在**——
起/落屏各 3–4 颗（一小串 `spread`，顺手就能吃到一颗），**爆发屏一颗都不放**（那一屏只有威胁），
开场 6 颗、收尾 8 颗。上一轮六关都是**两头两撮、中间 45–58 秒一颗都没有**，因为食物当时只写在
"安静开场"和"收尾"两处，而中间那段正是它该发生的地方。

这条规矩**威胁值为 0，所以节奏读数看不见它**（`pacing.threat.bubble` 就是 0，一屏放 30 颗和 0 颗在威胁序列里
一模一样），于是它单独有一条读数：`probe-pacing` 会打出每屏的收集物数（爆发屏画 `-`）和**最长空档**，
爆发屏里出现一颗、或最长空档超过 15 秒都会报警。上一版就是这么被抓出来的——块尾正好压在屏边界上，
`spread` 把最后一颗放在 `at + span`，于是四颗食物漏进了爆发屏。

两条顺带的现状：**长边对直径**（`imageScale: 1`），所以非正方的图只会显得比判定小、不会显得大——
大了就是"看着能躲过、其实碰到了"。以及，六关的比例都在 0.35–0.7，意味着收集物**永远比玩家小**，
所以 `drawPickups` 里那条"太大不能吃"的金色硬边分支（连同 `consumption.bumpDamage`）**今天进不到**——
留着是给以后真做"比你大的泡泡"用的，不是现在有效的信号。

**两个只属于菜单的旋钮**：`creatureScale` 和 `creatureAlpha`。背景用的是游戏里**真实的大小**，而一条鲨鱼在关卡里
是"占掉泳道三分之一"的压迫感，放在标题底下就成了抢戏——这两个数让它小一点、暗一点，而且**不动游戏里任何一只**
（`radius` 和 `hazardArt.scale` 决定的才是游戏里多大）。

数值都在 `config/mechanics.json5` 的 `menu.backdrop` 段；单位是"屏幕宽度的比例"或"每秒多少屏"，所以换窗口大小观感不变。

### 音效：一个声音一行配置，录音可以直接盖掉

每一个音效都是 `config/mechanics.json5` 里 `audio.sfx.sounds` 的一行：名字（`src/soundIds.ts` 里那份 id 表）、
分组、若干层 tone/noise，以及它们的频率、时长、音量、延后、颤动。**名字就是接口**：

- **换成真实录音**：把 `<名字>.wav`（或 `.mp3`）放进 `src/assets/audio/sfx/`，同名文件自动盖过配方。
  不用改代码，也不用改配置。**短音效用 WAV**（MP3 每个文件开头会有约 25ms 空白，对命中音这种几十毫秒的声音很明显）。
- **调参数**：改那一行里的数字。`gap` 是同一个声音最少隔多久才能再响（防止一串敌人叠成一团）、
  `pitchJitter` 是每次随机偏多少音高（防止连发听起来像节拍器）、
  `pitchPerIntensity` / `gainPerIntensity` 让强度越大音高 / 音量越高（强度由触发处给，例如吸收的泡泡越大）。
- 现在 **68 个**，分四组（`ui` 界面 / `combat` 战斗 / `player` 玩家 / `env` 环境），每组在 `audio.sfx.buses` 里
  各有自己的相对音量。界面的音不受同时发声上限（`maxVoices`）限制。
- **世界里的声音按位置分左右**（`panWidth`）：左边的鱼偏左耳，界面音和玩家自己的声音居中。
- **试听**：设置面板作弊区里的「试听音效」，一页 12 个，点一下就放。我这边听不到，所以占位音效的好坏只能靠你耳朵判断。

敌人按**六类**共用「被打中 / 逃走」两个声音（小鱼群游 / 大型捕食者 / 水母与电 / 硬壳带刺 / 远程射手 / BOSS），
分类表在 `src/soundIds.ts` 的 `ENEMY_CLASS`。想给某一种单独的声音，就在那张表里把它挪到自己的类，或者再加一类。

### 背景音乐：合成的当后备，录音放进去就自动替换

两条路并存，`src/recordedMusic.ts` 决定哪条在响：

- **每关一段合成曲**（`src/music.ts`，配方在 `audio.music.tracks`）——这是**后备**，不是过时的东西。
- **录好的曲子**放 `src/assets/audio/music/`，文件名是**曲名**；关卡在顶层 `music` 字段里点名，两关可以共用一首：

| 文件 | 什么时候播 | 现在有吗 |
|---|---|---|
| `slow-100.mp3` | 第一、二关（`music: 'slow-100'`），替换掉那两关的合成曲 | 有 |
| `black-smokers.mp3` | 第三、四关（`music: 'black-smokers'`）；它是**原第一关主题** | 有 |
| `battle-1.mp3` | 第五、六关（`music: 'battle-1'`） | 有 |
| `boss.mp3` | BOSS 战：BOSS 登场时切过去，被击败后回到关卡曲 | 还没有 |
| `summary.mp3` | 通关结算页 | 还没有 |

关卡没写 `music` 时仍按 `<关卡 id>.mp3` 找（旧约定），找不到就播该关的合成曲。调试关沿用第一关的曲子。

**某几个槽位空着是支持的状态**，不是缺东西：没有文件的关卡照旧播合成曲，没有 `boss.mp3` 就继续播关卡曲。

- **主菜单那一首**固定在 `src/assets/audio/abyssal-menu.mp3`（约 158 秒、2.5 MB），只在 `phase === 'menu'` 时播，
  点开始后淡出让位给关卡。
- 全部**边下边播，第一次点击之后才开始下载**：整首解码成 PCM 要占约 67 MB 内存，手机上不划算；
  浏览器在第一次手势之前也不允许出声。第一次 `play()` 放在指针按下的那一刻，是因为 iOS 只放行手势里发起的那一次。
- **循环靠淡入淡出，不追求样本级无缝**（MP3 本来也保证不了）：距曲末 `loopFadeSeconds` 时淡出，回到开头再淡入。
  进入、离开、循环三件事共用同一个包络。
- 四个槽位各有自己的音量（`audio.music.recorded.*Volume`），因为录制的响度不会一样。没有做过响度归一，
  听着偏响或偏轻就调那一格。

**死亡那一下**是一段短的 sting（不循环），它是音效 `defeat.sting`，所以换成录音就是放一个
`src/assets/audio/sfx/defeat.sting.wav`。

**这些曲子是怎么导出的**（原始 WAV 几十 MB、**不入库**，所以这一节就是它们的记录）：

```
pip install --user lameenc numpy
python scripts/encode-music.py "<原始 wav 路径>" <槽位名> [--kbps 128]
```

槽位名就是曲名（`slow-100`、`battle-1`、`black-smokers`、`boss`、`abyssal-menu`……），脚本据此决定文件落在哪。四件**故意不做**的事，
每一件都是"顺手优化"会悄悄改掉声音的地方：**不重采样**（保留源文件的 48 kHz，重采样等于白白多一道有损）、
**不裁首尾**（循环靠淡入淡出处理，见下；裁一刀只会冒着削掉一个音头的风险）、**不做响度归一**（混音是你的，
每一格音量在 `audio.music.recorded.*Volume` 里调，而不是在这里压扁）、**不动循环点**（MP3 本来也放不下样本级接缝）。

默认 **128 kbps**。主菜单那首是 96——氛围曲撑得住，而密集的混音撑不住：码率低最先听出来的是打击乐和镲。
觉得不对就用 `--kbps` 改。

### 设置面板里的两个滑条

**音乐**和**音效**各一条，都是 `src/audio.ts` 里自己的总线（主增益只管静音）。关卡合成曲、录好的曲子走音乐那条；
环境底噪和全部音效走音效那条。设置里的音量不再乘进音乐，否则同一个设置会被算两遍。

### 鱼群（Boids）：前景和背景

关卡里一个刷怪块写 `boids: true`（配 `kind: 'fish'` 和 `path`），这一块的 `count` 条鱼就是一个**鱼群**：路径驱动一个看不见的
领队，领队只影响离它近的几条鱼，其余的鱼靠分离、对齐、聚合跟邻居走，所以转向是从头一条一条传到尾的，不是整群同一帧转。
数值在 `config/mechanics.json5` 的 `hazards.boids`，要看效果就开调试模式进「调试关」（`config/debug-level.json5`）。

**前景鱼群**的每一条都是真的鱼（会碰伤你、能被打）。再写 `layer: 'back'` 和 `distance`（0 近 ~ 1 远），它就成了**背景鱼群**：
同一套模拟，但鱼不是敌人，没有碰撞盒，子弹穿过去、碰不到、吃不到，画在所有生物和障碍物后面、背景图前面。`distance` 只决定
大小和亮度（两端的值在 `hazards.boids.back`），**不改游速**——游多快是路径的 `seconds` 说了算。所以"先在背景有好几群鱼游过，
让玩家有心理准备，再来一群前景"，就是把背景块的 `at` 写小。

**生物和子弹在屏幕坐标里运动，关卡卷动只是进度。** 每关有两个速度：`scrollSpeed`（关卡推进、时间线、背景视差）和 `driftSpeed`
（生物在屏幕上的下落速度）。改前者不会让任何一条鱼变快或变慢。

### 调试模式和碰撞盒（设置面板 → 作弊区，**两个开关都默认开启**）


作弊区里并排两个开关，**互相独立**：

- **调试模式**：**关卡阶梯出现**（见上一节），以及主菜单设置里的「进入调试关」按钮。
- **碰撞盒**：**把所有碰撞盒用线描出来**（下面整节讲的就是它）。

分开是因为这是两个问题：调碰撞盒的人想要线、不想要阶梯；走阶梯的人不想要满屏的红线。碰撞盒的开关在游戏进行中的设置面板里
也能用（调试模式的那两样只在主菜单里有意义，游戏中点它不会改变正在打的这一局）。

**覆盖层是纯读取者**：画线用的是判定**正在读的同一个表达式**（`h.radiusFraction`、`radiusOf`、`stageRadiusFraction`、
`graze.radiusMultiplier`……），所以**线画在哪，就打到哪**。它不改任何判定——它是一面镜子，碰撞盒错了它显示的就是错的那个值，
而不是把它藏起来。想调碰撞盒的尺寸就改配置文件，然后看线有没有对上美术。

**六类实线**（碰上去就生效）：

| 颜色 | 类别 | 形状来源 |
|---|---|---|
| 红 | 生物 | **精灵占的那块矩形**：宽 `2 × radius × scale`、高 = 宽 × 图高/图宽 |
| 橙 | 非生物危险物（喷口 / 矿物 / 泡沫 / 雨） | 同上（矿物有图，所以是矩形）；**喷口是底座圆 + 沿朝向的等宽胶囊** |
| 紫 | 障碍物（木箱 / 珊瑚 / 墙 / 网 / 管虫） | `obstacles.radiusFraction` 的圆（另一套表）|
| 青 | 玩家子弹 | `radiusOf(age)`——**随飞行时间长大** |
| 品红 | 敌方子弹 | `b.radiusRatio`（出膛时定死）|
| 绿 | 玩家气泡 | `stageRadiusFraction(阶段, 体积)` |

**生物是矩形而不是圆**，因为鱼不是圆的：一只 `scale` 2.5 的金枪鱼画出来是判定圈的 2.5 倍宽，而圆**没法**修这个
（圆要么盖住宽度、要么盖住高度）。矩形用的是绘制用的同一组数——`radius`、`scale`、以及**贴图自己的宽高比**——
所以"看见多大就撞多大"是推出来的，不是靠人对数字。宽高比**从贴图读、不写进配置**：配置里的副本才是会在换图之后
活下来的那一份，而读贴图不会和画面对不上。美术没加载时两边一起退回半径 `radius` 的圆。

**但精灵盒不总是合适的**，所以 `hazards.hitboxScale` 是一个**每只生物自己的倍数**（不写就是 1），只作用于判定、
**不动美术**：`<1` 让判定比图小（尾巴、触须、裙边可以不参与），`>1` 让图小但威胁大的东西判定更大。它**按种类写、
不按变体**——变体已经有各自的宽高比了，再让倍数随变体变，同一只鱼的难度就会跟着一个随机的 `variety` 滚来滚去。
没有美术的五种也能调，倍数是加在那个圆上的；喷口有两层贴图（底座 + 火焰），但判定仍是底座圆加沿朝向的胶囊。

**同一套动画的各帧尺寸必须一致**（否则判定会随游动逐帧变形）——`scripts/probe-atlas.mjs` 断言这一条，并打印出
每个生物当前的判定框尺寸。

**虚线**是擦边圈（贴着过去但没碰到才给分），它和主判定是分开的两档：正在冲锋的生物、以及还擦得动的敌方子弹。
公式和判定一样，是"主判定形状向外扩 `(玩家半径 + radius) × (graze.radiusMultiplier − 1)`"。

**刻意不画的两样**：BOSS 身上那圈「往这打」的提示环（`weakPointWidthRatio` 只是一条描边的宽度，**游戏里没有弱点判定**）、
以及气泡自己的擦边圈（擦边圈长在**擦过去的东西**身上，不长在气泡上）。在一个合同写着"这就是碰撞盒"的覆盖层里画它们，
就是它本来要抓的那句谎话。

数值（颜色、线宽、虚线长短）在 `config/mechanics.json5` 的 `debug` 段。

**默认开启，且不区分构建环境**——`pnpm build` 出来的线上页面也是开机就画。这是**有意**的：目前唯一的玩家就是开发者。
把「碰撞盒」关掉就没有线；再把「调试模式」关掉，线上页面就是正常游戏的样子（也没有关卡阶梯）。两个开关都不存档，刷新就回到开。

**关于存档**（这是这个项目里唯一会跨页面存活的东西）：

- **读的时候不信任它**：解析失败、形状不对、`cleared` 里出现**已经不存在**的关卡 id，全部丢弃。
  最坏的结果是"从头开始"，而不是"开机崩溃"。私有窗口里 `localStorage` 会抛异常，那种情况下游戏照常能玩，
  只是不记事。
- **可以重置**：`window.__GB.game.debugResetProgress()`（进度回到只剩第一关、选中文件里的 `start`），
  或者手工删掉那个 key。测试也靠这个钩子把阶梯重置到干净状态。
- **测试里**还有 `debugProgress()`（读）和 `debugClearLevel(id)` / `debugSelectLevel(id)`（写，
  走的是菜单用的同一条路径），所以不用真打两遍关卡才能测到解锁。

**还没做**：关卡选择只在主菜单上（关卡中途不能换，符合直觉）；星级/最好成绩**没有按关卡分开存**——
`最好 Xm` 目前是本次会话内的。要按关卡记录成绩，是给存档加两个字段的事，等你需要的时候说。

**节奏是关卡的属性**：`scrollSpeed` 和 `scrollLength` 一起写在关卡文件里，因为同样长度的两关应该允许有不同的节奏。

**关卡推进和玩法是两件事**：`scrollSpeed` 只决定关卡走多快（时间线、进度、背景视差、深度读数）；生物、子弹、敌方子弹、冲锋瞄准都在**屏幕坐标**里运动，它们的速度看 `driftSpeed`（米/秒，每关必填）。改 `scrollSpeed` 不会让任何一条鱼变快或变慢。地形、障碍物、喷口、收集物和天气（泡沫、雨）仍然跟着世界走——它们往下掉本身就是关卡在推进。

### 触屏控制：屏幕任意位置拖动

手机上**没有摇杆**：在**屏幕任意位置**（按钮以外）按下并拖动，气泡就按手指移动的方向和距离移动**同样的距离**——
手指在屏幕上移动 30px，气泡就在自己的位置上移动 30px。松手即停，没有惯性、没有加速。

这是**相对位移**，不是"气泡跟到手指下面"：手指可以按在离气泡很远的空白水面上，一边看着气泡一边操作，
手不挡视野。

配置在 `movement.drag` 段，有中文说明：`sensitivity`（位移倍率，1 = 严格 1:1）和 `penaltiesApply`
（成长阶段/吸附/减速这些速度惩罚要不要也乘进拖动距离，默认关——关着才是严格 1:1）。

### 积分（常驻在左上角）

屏幕**左上角常驻显示本局得分**（`分数 1234`，金色），每局从 0 开始；结算卡上给最终分数和本次会话的最佳得分。

**什么给分**（都在 `score` 段，键名就是事件名，**任何一项设成 0 就等于把这件事从积分里拿掉**，不会留下一串零）：

| 事件 | 默认 | 为什么给它分 |
|---|---|---|
| `drivenOff` | 25 | 把一条生物**打跑**（血打空）。这是枪的回报：不设分的话，开枪只是把水变空 |
| `absorb` | 5 | **吸收一个收集物**。只发给"不能靠吸收长大的类型"——对吞噬路线来说成长本身就是回报，再给一次分等于把同一件事付两遍。**突变值那张表故意不是这么分的**，见上面「来源按速率刻意拉开」 |
| `eaten` | 40 | **吞掉**一只生物。反转是招牌动作、也是最危险的那个（气泡会变大变慢），所以它给分 |
| `boss` | 1000 | **击败 BOSS**：一关的目标，整局最大的一笔，其它都是零钱 |

（枪管、射速这些**都由突变三选一发放**，不是拾取物——见下一节。）

分数读数长什么样（位置、字号、颜色、不透明度）在 `hud.score` 段，也是设计像素。分数记的是**每个事件发生了多少次**（账本），总分按当前配置算出来——所以改一个数值，不会留下"一半按旧表算的总分"。

**得分会在原地飘字**：`+25` 出现在**得分发生的位置**（打跑鱼的地方、吞下它的地方），向上飘、渐隐、3 秒后消失。**所有参数都在 `score.popups` 段**（字体族除外，那是全局的 `text.fontFamily`）：

| 键 | 默认 | 管什么 |
|---|---|---|
| `lifeSeconds` | `3` | 活多久（就是你要的那个数） |
| `risePx` | `46` | 这段时间向**上**飘多少（设计像素） |
| `riseEase` | `1` | 上升曲线：`1` 匀速 · `0.6` 先窜后缓（街机手感）· `1.6` 先慢后快。**只改路径形状，不改总高度** |
| `size` | `16` | 字号（设计像素） |
| `colour` | 金色 | 颜色 |
| `alpha` | `1` | 基础不透明度（淡出是在这个值上再乘，`0.6` = 整体淡一点） |
| `weight` | `"bold"` | `"bold"` 或 `"normal"` |
| `prefix` | `"+"` | 数字前面加什么。`""` 就只显示数字 |
| `fadeFrom` | `0.45` | 前百分之多少的时间保持全亮，之后才淡出 |
| `fadeEase` | `1` | 渐隐曲线：`1` 线性 · `2` 亮到最后一下没 · `0.5` 一开始就明显变淡 |
| `anchorX` / `anchorY` | `0.5` / `0.5` | 事件位置落在飘字的哪个点上（`0` = 左/上边缘，`1` = 右/下边缘）。`0.5/0.5` 是以事件为中心；想让数字从事件**上方**冒出来，把 `anchorY` 设成 `1` |
| `max` | `24` | 同时在飞的上限，**护栏**不是预算：真到上限就退休最老的那个（玩家早读过了） |

**每一项都能在控制台里实时改**（`window.__GB.mechRef.score.popups`）：飘字是池化复用的，所以每一发都会重新套用样式（Pixi 的样式 setter 在值没变时会提前返回，所以常规情况只是几次比较），不会出现"改了一半标签还是旧样式"。

> **位置是"发生那一刻的屏幕位置"，不是世界坐标。** 挂在世界坐标上的话，水面以 25 m/s 往下走，会把飘字一起带下去，比它自己往上飘的还快——**净结果是往下沉**。一个往下沉的东西不叫"漂移"，而漂移才是让人看见它的原因。（左上角那个读数说的是"这局值多少"，说不出"刚刚这一下值多少"，这就是飘字存在的理由。）

**结算卡会换行**：换行宽度是 `hud.resultsCard.widthRatio`，以**屏幕**为基准。"一行字能有多宽"和"一米占几个像素"没关系，跟着世界缩放的话，往上加一条事实就会被屏幕两边切掉——玩家只看到自己成绩的中间一段。

**最佳得分是"本次会话"的，不写进存档**——和 `bestClimbed` / `bestVolume` 一样，这是 `src/progress.ts` 里的明确决定：存档只存关卡解锁，分数是每局的事实。

### 触屏按钮：右侧一列

**所有动作按钮竖排在泳道最右边**，从下往上按"越常用越靠下"：反射动作（喷吐/爆破）在最下面，拇指最容易够到，往上依次是其余动作（消化）。

**为什么挤到一条边上**：移动是"任意位置拖动"，所以屏幕左边和中间整片都是干净的操控区——手指不用绕开按钮、也不会挡住气泡；按钮集中成一列，位置固定，闭着眼也能按。两个下角各放一组的话，两个角都被花掉，玩家只能在中间那道缝里操作。

按钮的顺序**按类型也固定**：某个形态没有的按钮就空着那个位置，不会把别的按钮挤上来——所以"爆破在上面"在任何一局里都成立，换个气泡不用重新记。（喷吐/消化/爆破三个按钮现在全是休眠路径——`layout()` 仍为它们算位置、但没有任何类型声明它们，所以不画也不响应。`ControlId` 里保留这些 id，是给未来某个要这些动词的路线复用的（第二刀的三条路线都没用上它们）。）

配置在 `touch` 段（半径、半径上限、离右边缘的距离、离底边距离、按钮间距，都是设计像素）和
**HUD 里没有水位管、没有地标标签**：距离不是进度（一关的终点是它的 BOSS），而段落名关卡本来就会在事件发生的那一刻用横幅喊一次——屏幕边上一列常驻的段落名读起来像菜单，不像水里的景象。

**run 横幅（"射速升级 · 第 2 档"这类提示）是居中的、并且会换行**：一条横幅挂半条在屏幕外等于没写，所以它的锚点、对齐和换行宽度都是明确的（`hud` 段）。

> 按钮尺寸用 `designScale(画布)`，和 HUD 一样，**不是** `viewport.scale`（世界缩放）：横屏/矮窗口下世界缩放反而很大（915×412 的手机横屏是 2.49 px/米），按它算按钮半径会到 95px，整列被顶出屏幕。这是 `TouchControls.layout` 内部自己算的，没有"传错的参数"这回事。

**为什么不是"气泡跟着手指走"**：跟手是把手指位置当作**目标位置**，于是手指必然挡住气泡——
拇指得待在目标位置上，玩家自己的手遮住了自己在操控的东西，而这个游戏的核心玩法就是早点看见危险。
拖动保留了"手不挡视野"，同时因为是**相对位移**，力度也不再被浪费：移动多少就是多少。

**代价，说清楚**：既然"手指移动多少气泡就移动多少"，那"气泡越大越慢"就没法同时成立，所以
**成长阶段和吸附的速度惩罚默认不作用于触屏**（键盘不受影响）。想要那条张力，把 `penaltiesApply` 打开，
代价是不再严格 1:1。

### 气泡成长阶段的外观

**每个阶段一个对象**，在 `stages.appearance` 数组里，所有外观数值都在里面（含 alpha 和线宽）——
改一个阶段不用在多个平行数组之间数下标，加阶段就往数组末尾再塞一个对象。少于阶段数时最后一个会被复用。

| 键 | 管什么 |
|---|---|
| `radius` | 阶段越高气泡越大。**同时影响判定**——画多大就吃多大，两者走同一个函数 |
| `rim` / `rimAlpha` / `rimWidthRatio` | 轮廓。**色相的主要载体**，最饱和、接近不透明，余光里分辨阶段靠它。**想换颜色先改这里** |
| `glow` / `glowInnerAlpha` / `glowInnerRadiusRatio` | 光晕，**只有一圈**（默认 1.18 倍半径）。要**亮**，不要饱和——它以一个大圆压在气泡内部之上，亮度直接决定内部多亮 |
| `inner` / `innerAlpha` | 内部填充。只有 12% 不透明度，**接近白色**即可 |
| `innerRing` / `innerRingAlpha` / `innerRingWidthRatio` | 轮廓内侧的细环。**形状线索**：手机上白天看暖金和暖粉会混，一圈和两圈不会混。想让**更多阶段**靠形状区分，就把它改成"环的数量" |
| `sheen` / `sheenAlpha`、`specular` / `specularAlpha` | 内高光和镜面高光点 |
| `hudColor` | HUD 上阶段标签的颜色。要**在深色 HUD 上**看得清，和 `rim` 的背景不同，不能混用 |
| `name` | 阶段中文名 |

**光晕只有一圈，而且贴着边**。它曾经还有一个画在 `1.55 ×` 半径上的外圈，而绘制和碰撞**共用同一个半径函数**
——于是玩家看到的最外沿比真正会碰到的边界大 **55%**，按它估距离的人每一次擦边都会估错。错掉的边界只有拿掉
才归零，调小或调淡都只是削弱它；留下的那 1.18 倍溢出在深色水里读作高光，不像轮廓。

**内部为什么几乎透明**：四个半透明浅色层（光晕、填充、内高光、镜面高光）叠在一起会趋近白色，
在深色水上就是**中性灰**——阶段色相恰好在玩家最常看的地方被平均掉了。所以内部保留水的深色，
色相交给天生不透明的轮廓和光晕承担。


颜色两种写法都认：JSON5 十六进制字面量 `0x9fe4ff`，或取色器给的 `"#9fe4ff"` 字符串。

### 弹幕：逼你不断移动

默认节奏是"躲开"，但如果危险只会慢慢飘过来，站着不动就是最优解。所以要有**主动压过来**的威胁：

**冲锋（`charges` 段）**：`chargers` 表里的生物进入自己的 `triggerMeters` 就会**蓄势**——把自己将要走的**整条曲线**画出来（落点上还有一个环）——然后沿这条**固定曲线**一头撞过来。**每种生物一行**（和敌方子弹的 `shooters` 一样的约定），所以不同生物可以有不同方向的冲锋：

| | 小鱼 `fish` | 水母 `jelly`（碰到还会**减速 + 掉血**） |
|---|---|---|
| 路径 | 从它现在的位置直接俯冲，弯 0.3 | 从它现在的位置甩出一条大弧（弯 **0.85**），所以看起来是横扫过来 |
| `triggerMeters` | 300 | 320 |
| `telegraphSeconds` | 0.75 | 0.95（它的弯更大，需要更多时间让人读出"它要绕哪边"） |
| `travelSeconds` | 0.55 | 0.6 |
| `bowRatio` | 0.3（弯一点，逼你读方向） | 0.85（甩出去再扫回来） |
| `cooldownSeconds` | 2.2 | 2.8 |

`telegraphColour` / `telegraphAlpha` / `trailColour` / `trailAlpha` 是所有冲锋共用的外观：预警曲线（蓄势时脉动，所以静止的线读起来是倒计时）和冲刺拖尾。

> **为什么是固定曲线，而不是追踪**：曲线在**蓄势开始那一刻就定死**，瞄准的是"那一刻的你"，之后**永不修正**。这是"有规律的弹幕"和"不公平的追踪攻击"之间的区别——玩家永远只需要做一件事：在窗口里**挪开**。`bowRatio` 的理由也是公平性：直线冲锋看一眼就知道往旁边站，弯过来的必须读出它**弯向哪边**，"往哪躲"于是从条件反射变成一次判断。
>
> **公平性的一半是可见性**：曲线和落点环在蓄势期间就画在屏幕上，玩家不用背板也不用猜。水母也一样：它的弧线在蓄势期间就画出来了。


**爆炸会抖屏**（`hazards.bombfish.blastShakePixels` / `blastShakeSeconds`，默认 7px / 0.3 秒）：抖的是**整个画面**（连 HUD 一起），因为这不是"水在晃"而是"这一下打在你身上"；幅度刻意小，抖屏期间玩家还得躲下一颗子弹。实测舞台位移峰值约 4px（配置 7 × designScale 0.76 = 5.3px 振幅，采样间隔导致的低估），结束后精确回到 (0, 0)。

**② 敌方子弹（`enemyBullets` 段）**：`shooters` 里列出的生物会**瞄准你开火**。默认是电鳗（**蓝色电箭**，108 m/s、0.6 发/秒）和**海胆（尖刺，181 m/s —— 全场最快）**——**不在表里的生物就是不开枪**（不是用默认值：一个因为漏写配置而开始开枪的生物，是一次没人做过的难度改动）。水母不在表里：它是从侧面冲锋的，不开枪。电鳗的弹用贴图「电鳗闪电」——一小簇分叉的蓝白电弧；贴图缺失时退回蓝色的程序化弹丸。**电鳗的弹主要是麻痹来源**：命中后左右操作反向 0.5 秒（`hazards.eel.paralysisSeconds`），每发只掉 **5** 点血；撞到电鳗本体也会麻痹，本体伤害 **10**。

| 键 | 默认 | 管什么 |
|---|---|---|
| `shooters` | 电鳗 / 海胆 / 四枪手 | 每种会开枪的生物一行：`perSecond`（每秒几发；**0 = 弹存在但从不主动开火**，刺魨用）、`speedPerSecond`（速度，**泳道宽/秒**）、`spread` + `spreadRadians`（一次几发、扇形夹角）、`damage`（扣几个命中点）、`shape`（`bolt` 普通弹丸 / `spike` 尖刺）、`radiusRatio`（可选：这一种子弹的半径，手枪虾的大弹用）、`coreColour`/`rimColour`（可选：这一种子弹的亮芯/外圈颜色，电鳗的蓝色用）、`image`/`imageScale`/`imageAlpha`（可选：这一种子弹的贴图、画面宽度相对判定直径、不透明度；电鳗的闪电簇用） |
| `rangeMeters` | `420` | 只在这个距离内开火，所以子弹**永远不会从你看不见的地方飞过来**；超出时扳机是**按住**而不是攒着 |
| `radiusRatio` | `0.016` | 子弹半径（相对泳道宽），每行可用自己的 `radiusRatio` 覆盖 |
| `lifeSeconds` | `7` | 存活秒数 |
| `coreColour` / `rimColour` / `rimAlpha` | 暖金 / 橙红 | 外观：亮芯 + 暖色外圈，和玩家那串冷色小泡泡在余光里不会混 |

> **公平性靠三件事，而且三件都是配置**：瞄的是**开火那一刻的你**（之后不修正）；速度是**泳道宽/秒**，默认 0.22~0.3，比你横穿泳道的 2 秒慢得多，所以"躲得开"在物理上永远成立；只在 `rangeMeters` 内开火。**弹幕的难度全在这三个数上**——嫌凶就调 `perSecond`，嫌烦就把某一行删掉。

**子弹会被障碍物挡住**（和玩家的子弹同一条规则：看得见的木箱就该挡住子弹），所以布景对双方都是掩体。命中走的是**同一个 `takeHit`**，没有第二条伤害路径；同一帧里的**不同发**会被无敌帧合并，这是有意的保护——但**同一发的多点伤害不合并**（手枪虾一发 = 2 次 `takeHit`）。


### 吞噬：食物链反转（即时版）

**刚才还要躲开的东西，血多的时候可以回头一口吃掉。**

判定是**双向**的，这是它好玩的原因：

- 体积**够** → 你撞上去，它被你吃掉，你回血
- 体积**不够** → 同一只、同一次碰撞，但结果是它伤害你

而体积现在是**血量的读数**（见「体积」一节），所以"我能不能吃它"和"我还能挨几下"变成了同一个问题的两面：
满血时吃得动的东西，掉到三成血就吃不动了。没有任何东西被脚本改成"现在可以吃了"，是世界对玩家的意义变了。

**吃是即时的**：贴脸碰到吞得动的危险物，那一刻就到账——血量（按质量 × `healthPerVolume`）、分数（`score.eaten`）、
突变经验（`mutation.gain.eaten`），外加 0.35 秒无敌（`consumption.eatInvulnerableSeconds`，和阶段晋升同理由：
刚做完一次正确的冒险就挨一下，手感上像在惩罚你做对了事）。**没有库存**：不进胃袋、没有引信、
不需要吐出来或压下去——吃这个动作的全部后果在当帧结清。

> **没有胃袋**：吞进去 → 库存 → 喷吐当弹药 / 按住消化换吞阶 / 不管它就过饱爆炸。那是一套**库存管理**玩法，
> 和这个游戏"操作与技巧换收益"的核心不在一条路上，而且每加一种生物都要为它多写"进了胃里会怎样"。
> 留下的恰好是同族里属于技巧的那一半：**贴脸吃是高风险的即时收益**（挨得太近就是挨打），
> 吸附是主动把风险拉到脸上。

配置在 `consumption` 段：

| 键 | 管什么 |
|---|---|
| `tierVolume` | **体积档位阶梯**。下标就是档位，值是进入该档所需的体积。默认 5 档（微型/小型/中型/大型/巨型） |
| `edibleAtTier` | 每种危险物从第几档开始可吃。调高 = 威胁期更长 |
| `mass` | 每种危险物吃下去值多少体积 |
| `massEfficiency` | 吃的损耗。小于 1 表示吃危险物得到的比它自身轻，于是不能靠它无限膨胀 |
| `eatInvulnerableSeconds` | 吃下那一刻的短暂无敌 |
| `marker` | 可吞噬标记的颜色/线宽/不透明度 |

**为什么档位阶梯是独立的、而不是复用成长阶段**：成长阶段按**吸收个数**晋升，体积按每颗的大小累加，
两者不是同一个量——**体积反推不出阶段**。拿吸收个数当体积阈值就会这样：长到阶段 2 的玩家体积只有 2.3，
而"第 2 档"要 13，于是**永远吃不到鱼**。

**标记用的是独立的一套视觉语言**：阶段色（青/金/粉）继续说"我是第几阶段"，可吞噬标记是画在危险物
**自己**身上的金色光环，说"这个是食物"。两者互不覆盖。默认只画"可吞"这一半，因为那是玩家**行动所需**
的信息；`marker.showBlocked` 打开后会额外画红色硬边表示"不可吞"。

判定规则只有一处实现（`src/consumption.ts`），**碰撞和标记问的是同一个函数**——如果两者不一致，
标记承诺是食物而碰撞给了一下伤害，那会是这个机制最糟的 bug，因为它惩罚玩家相信看到的东西。

### 吸附（拉近范围内的东西）

**吸附场是有机制的，但目前没有任何输入能把它升起来。** 它原本挂在屏幕右下角那个按钮的"按住"上，那个按钮随技能系统一起删掉了；机制本身（`src/suction.ts`、`Run.suctionUp`、`Input.suctionHeld`）刻意留着，等吞噬路线的动词重新设计——`Input.suctionHeld` 上有一段说明记着这件事。

配置在 `suction` 段，全部有中文说明：

| 键 | 管什么 |
|---|---|
| `radiusRatio` / `radiusPerVolume` / `maxRadiusRatio` | 吸附半径随体积增长（体积越大吸得越远） |
| `pullPerSecond` | 拉动速度 |
| `heavyRatio` / `heavyFloor` | 按**目标质量 / 玩家质量**衰减。≤1 全速，≥`heavyRatio` 只剩 `heavyFloor` |
| `moveSpeedFactor` | 吸附期间玩家速度倍率（**这是这个机制唯一的代价**） |
| `fieldColor` / `fieldAlpha` / `fieldWidthRatio` | 吸附场的视觉 |
| `tetherAlpha` / `tetherWidthRatio` | 预留给"吸附轨迹"连线 |

**关键设计：吸附只负责拉近，不负责吃。** 拉到位之后仍然走食物链档位判定——所以把一只你吃不了的螃蟹吸过来，等于**加速把危险物拉到自己脸上**。加上吸附期间减速，两重代价合起来才让"什么时候开启吸附"变成真正的决策，而不是白送的加宽嘴巴。

**为什么按相对质量衰减**：同一个浮游生物，在你小的时候很重、在你巨大的时候微不足道——于是吸附能力**自动随玩家成长**，不需要第二套成长系统。


### 路径点（spline）：一串敌人沿同一条曲线游过屏幕

关卡里新增 `paths` 表，刷怪块用 `path: '名字'` 把它的 `count` 个敌人放到同一条曲线上，于是就成了"一串鱼"：

```json5
paths: {
  weave: {
    points: [
      { x: 1.25, y: -0.2 },   // 屏幕右侧外面，屏幕偏上的高度
      { x: 0.78, y: -0.75 },  // 进来、下沉
      { x: 0.45, y: -0.15 },  // 再上扬
      { x: 0.16, y: -0.8 },
      { x: -0.3, y: -0.25 }   // 从左侧出去
    ],
    seconds: 7.5              // 走完整条曲线要多久
  }
},
// 时间线里：
{ at: 400, kind: 'fish', count: 6, path: 'weave', x: 1, pathSpacingSeconds: 0.5 }
```

**坐标是两种不同的东西，这是刻意的**：

- `x` 是 **泳道比例**：0 是屏幕左边缘、1 是右边缘，<0 / >1 就是屏幕外——"从右边进、从左边出"是关于屏幕的陈述。
- `y` 是 **屏幕比例，相对出生点，正值朝上**：1 就是"一屏高"，所以 `0` 是出生点（顶边）、`-0.5` 是屏幕正中、
  `-1` 是底边、正的就在顶边外面。

**`y` 为什么不是米**：这个游戏**一屏有多少米是看设备的**。泳道锁死 361 米宽，于是屏幕上能装多少米 = `屏高 / scale`
—— 实测手机 781 米、桌面窗口 433 米。写米的话"屏幕中央"在两种设备上会变成两个地方，而"从屏幕右侧中央出发"
正是作者要说的那句话。

曲线是**穿过**路径点的 Catmull-Rom spline，不是 Bézier：作者写"从这里过一下"就是要真的从那里过，而 Bézier 只会被拉近。路径在**屏幕坐标**里走，不再叠加卷动带来的下沉：画出来是什么样，看到的就是什么样（水平的路径就是水平的）。

**一串里谁先谁后靠出发延迟**（`pathSpacingSeconds`，`LevelEntry.pathDelaySeconds`）：整串一起出现在曲线**起点**排队，然后每隔 `pathSpacingSeconds` 走一条，所以看到的是一群鱼游进来，而不是几条鱼凭空出现在曲线中段。**这也是为什么每条路线的第一个点都在屏幕外**——排队的地方要是看得见，那就是一坨。想让一串更密就把 `pathSpacingSeconds` 调小，想让它更长就加 `count`。

> **"被校验、被写进文档、却没有效果"的关键字，是这里最不想有的东西。** 两个这样的键已经不在了：
> `staggerMeters`（"相邻两条间隔多少米"）读进 `PathSpec` 之后没有任何代码写进那张表，间隔恒为 0；
> `pathOffset`（"按 `i / count` 沿曲线排开"）会让同一帧进场的一串当场叠成一坨，而且每个成员的曲线原本
> 锚在自己出生点上——六条鱼是同一个形状画了六遍。


修了两个实现上的坑，都记在提交信息里：路径的 x 一开始被**加在出生点上**（于是 x=1.25 变成 2.25 泳道宽，鱼永远进不来），以及普通生物的**泳道夹紧**把路径的两端钉在了泳道边缘（于是"从屏幕外进来"变成了"贴着右边墙出现"）。

### 通关流程：继承强化、过关演出、最终结算

**① 武器强化跨关继承**：枪的**排数**和**射速档位**是**这一局**的东西，和分数一样——走关带着走，死亡重来才清零。走进下一关是同一次下潜的继续，拿走玩家刚用来通关的强化等于**惩罚他通关**。

**② 攻克 BOSS 的演出是"赢的样子"**，和死亡刻意不同：

```
playing → cleared → ascend → intro（下一关）
```

- **cleared**：气泡**停住不动**、**无法操作**（除了 `playing`，没有任何阶段接受输入），同时播放一段**过关音乐**（`audio.clearSting`：大调上行琶音 do-mi-sol-do）。音乐长度从演奏用的同一组数字算出来，所以"音乐播完"和"气泡起飞"不可能各说各话。
- **ascend**：气泡**向上飞出屏幕**。这一段的上升走的是玩家的**屏幕比例**而不是世界坐标——`player.y` 每帧由摄像机推出来，直接写 y 会被覆盖（实测 600m 的爬升只画出 11m）。实测现在 `screenY` 到 **1.14**（越过屏幕顶边）、世界高度上升 **510m**，确实飞出去了。
- 飞出之后才切关（或进入结算）。

**③ 六关通关后展示结算界面**（`src/summary.ts` + `summary` 配置段）：面板显示**本轮总得分**（一个数字，最大字号）、通关数、用时、最佳得分/新纪录、构建号，以及一个**返回主菜单**按钮（唯一一个按钮，因为只剩这一件事）。它自己处理指针（全屏面板如果让点击穿到水里，会去操控一个看不见的气泡），遮罩 0.86 把水和 HUD 压下去。


### BOSS：每关的终点

**一关的终点是它的 BOSS，不是距离**：卷动到 `scrollLength` 就停住（最后一段自然变成一个出不去的决斗场），只有**打掉这一关的 BOSS** 才算通关。没有击败它，这一关永远不会结束——这正是它的意义。

| 写在哪 | 内容 |
|---|---|
| 每关文件里的 `boss` | `at`（走到多少米它出现，**必须 < scrollLength**，否则加载就报错）、`health`、`name`、`colour`。这是**关卡强度**：两只 BOSS 可以不一样厚、不一样颜色。 |
| `mechanics.json5` 的 `hazards.boss` | 它怎么动（`holdMeters` 悬停高度、`patrolAmplitude` / `patrolPeriodSeconds` 横向游弋、`seekSpeedFactor` 追你的速度）、`contactDamage`、`radiusRatio`（体型）、颜色与受击闪白 |
| `enemyBullets.shooters.boss` | 它的枪：一次一波扇形（默认 5 发、±0.62 弧度） |

**它不随水流走**——它咬住画面，一直悬在你上方 `holdMeters` 处横向游弋并缓慢逼近。所以它跑不掉，只能打（或者死）。它是一条 hazard，所以玩家的子弹打它、无敌帧保护你、伤害与飘字全都不用新代码；只有三件事是它自己的：**不下沉**、**血量归零是"死"而不是"逃跑"**（那也正是通关信号）、**不能被吃**（`edibleAtTier` 锁在最高档）。

**屏幕顶部那条紫色的条就是这一关的进度**（`hud.bossBar`：位置、宽度、颜色、字号）。它只在 BOSS 战期间出现——**它的"不出现"本身也是信息**：BOSS 来之前和死之后，屏幕顶上不该有一条显示 0 的条。

**BOSS 默认不调头**（`hazardArt.boss-*.fixedFacing`，写在六行里）。立绘**永不镜像**——不朝玩家翻、也不按自己漂的方向翻，永远按原图的样子画。

- **为什么**：BOSS 是一场仗的布景，立绘是照着那样画的；而且它按 `scale: 2.8` 占掉三分之一泳道，0.4 秒的转身（横向压扁）放在这么大的东西上，看起来像画面抽了一下，而不是像它转了个身。
- **要让某一只调头**，把那一行的 `fixedFacing` 改成 `false`——它会按玩家所在的左右侧镜像，转身动画和其它生物一样（`hazardFacing.turnSeconds`）。打开之后看一眼：站到它右边，它看起来朝左就说明立绘本来朝左（六行的 `front: "left"` 是从旧 BOSS 那一行继承来的，没人逐只量过）。
- **代码里的默认值也是"BOSS 不调头"**（`paintHazards` 里 `fixedFacing ?? 是BOSS`），所以加第七只 BOSS、忘了写那一行，它也不会偷偷调头。六行写 `true` 只是把状态说出来。
- **攻击方向不受影响**：BOSS 的攻击是从玩家所在的那一侧发出来的，不看朝向——关掉调头不会让它打歪，只是立绘可能看着朝反方向挥手。
- 顺带：`hazardMirror` 上面那段注释以前说 `h.facing` 会被"弩手武器方向、冲锋方向、碰撞盒"读到，**那是假的**——查过整个 `src/`，它只有画面一个读者（画出来的身体按自己相对泳道中心的位置算朝向）。这句话现在写在注释里，因为"BOSS 不调头"之所以安全，正是因为没有任何机制跟着朝向走。


### 突变：局内的三选一成长线（原"掉落物"已移除）

**地图上没有可拾取的道具**：枪管、射速**全部由突变三选一发放**（`kind: 'upgrade' / 'rate'` 这类拾取物不是合法的刷怪种类，写了会加载报错）。一切成长都走突变。

**突变值条**在顶部中央（每个形态都有，沸腾路线时叠在怒气条下面；`mutation.gauge` 段管外观），攒满一级**不会立刻冻结**：先走一段**慢动作预告**，卡片等它走完才出现。三张卡**必须选一张**（点卡或按 1/2/3），选完世界慢慢回到原速并给半秒无敌（`mutation.resumeInvulnerableSeconds`，防止"选完当场被打死"）。跨关保留、死亡清零——和分数同等待遇。

**慢动作预告**（`slowMotion.pick` 段，见下面「慢动作：一个时间轴，两处用它」）：条一满，世界慢到 0.3 倍、保持 0.6 秒，**这 0.6 秒走完卡片才出现**；选完之后再花 0.4 秒回到原速。**这段时间玩家还能操作**——它是预告，不是剥夺控制。

- **无敌**：预告期间打不掉血（`Run.pickProtected`）。卡是玩家自己攒满的，被一颗刚好飞过的子弹收走，挫败感来自"我什么都做不了"而不是"我打错了"。
- **打死的东西照算**：分数和突变值都照涨。世界是真的在跑（只是慢），画面里敌人确实死了，不给分是玩家看得见的谎。
- **突变条亮起来**（`mutation.gauge.rampStroke*`）：条上那圈比"攒着一张卡"更亮更厚，用来解释**为什么水慢了**。不加文字横幅——那会挡住水里，而这 0.6 秒是唯一还能操作的时候。
- **一次吃两张**：选完如果余量还够，第二组卡**立刻弹、不再走一遍慢动作**。预告的作用是"从战斗切到选择"，第一次已经切过去了。
- **Boss 战期间照常弹**：压住不弹会让满条撑到关卡结束，而那时已经不是 `playing`，于是那一关永远弹不出来、只能顺延到下一关——玩家打完需要它的那仗才拿到卡。
- **跨关带过来的满条**：新关卡气泡落位就走同一套（卡是欠着的，开场是这一关最安静的时机）。

**形态选择在「开始游戏」之后、加载之前**（`src/routePick.ts`）：一屏三张卡，选中哪一张就用哪种形态开局——
形态当帧就位（按钮重排、沸腾换怒气配色、吞噬开口），选路线则那条路线的专属卡进池、另外一条的卡本局永不再出，
选**原样开局**则什么都不加，只走共用池。
**死亡重开不会重新问**（形态是这一局的；每次死都问一遍会把一个决定变成一道关卡），**再开一局**才会再问一次。

**两个进化形态（吞噬 / 沸腾）要先通关一次（用哪种形态通关都算）才解锁。** 锁着的时候照样列出来、灰掉、底下写「通关一次解锁」——
看不到自己在追什么的玩家，没有在追什么。解锁是**从存档推出来的**（`progress.cleared` 里有没有最后一关），
不新增字段，所以老存档自动满足。

**来源按速率刻意拉开**（`mutation.gain` 段，任何一项设 0 就等于拿掉）：

| 来源 | 默认 | 说明 |
|---|---|---|
| 随时间 | `autoPerSecond: 1.0`/秒 | 最慢。纯挂机 80 秒攒满第一级——首级就是选路线的节点，所以它得在这个量级上 |
| **拾取气泡** | **2/颗** | **紧挨着它上面。**比时间快、比打跑敌人慢，就是这一档的入口。实测六关的泡泡密到 **0.40 颗/秒**（全收下），所以"一路捡着走"的速率是 **1.81/秒**、首级约 **44 秒** |
| 打跑/吞噬 | 3/只 | 居中。挂账和积分同款事件，未来新事件自动接入 |
| 子弹擦边 | 4/次 | 电鳗的闪电擦身而过（过点判定，小字「擦」）。刻意最小：子弹比冲锋频繁得多，这是经济里"最碎"的一档 |
| 贴脸击杀 | 8/次 | 在接触半径 × `pointBlankRadius`（1.3）内用枪打跑一只怪（小字「贴脸」）。枪对擦边的回答：一个奖躲、一个奖贴 |
| 远距拆弹 | 15/次 | 在爆炸半径外把炸弹鱼打死（小字「拆弹」）。一次性低频事件 |
| **冲锋擦边** | 25/次 | **最快**。危险打法大约每 8-10 秒一次 ≈ 2.5-3/秒 |
| BOSS | 100/只 | 一大笔，跨关携带时滚进下一关的条（"打完 BOSS 开局半管"） |

**拾取这一笔和积分那张表故意不同**：`score.absorb` 只发给"不能靠吸收长大的类型"（对吞噬路线来说成长本身就是报酬），而突变值**两条路线都给**——拾取这件事两边都发生了，而成长更快的路线不该在突变上反而落后。

**三条小技巧共用一套浮字样式**（`mutation.callouts` 段，比冲锋擦边的大字小一档），**都不触发慢动作**——慢动作是冲锋擦边独享的身份标识。三条的判定规则与冲锋擦边完全同构（过点判定、无敌帧不判、一次一个），只是各自的"过点"长在不同东西上：子弹看飞行方向、贴脸看击杀距离、拆弹看爆炸半径。

**擦边经济里唯一的看门处**：若实测"贴着电鳗闪电走"的流追上冲锋擦边流（2.5-3/秒），先压 `mutation.gain.bulletGraze` 再考虑加合并窗口——冲锋擦边"玩命最快"是这套经济的招牌承诺。

**等级曲线**（`mutation.first: 55`、`growth: 1.3`）：第 N 级要 `55 × 1.3^(N-1)` 点，**溢出保留**（一次大额擦边冲过门槛不截断爽感）。首级落在 **29 秒（一路捡着走）到 55 秒（只靠时间线）** 之间——`node scripts/probe-pacing.mjs` 用第一关自己的食物密度把这个窗口算出来。80 → 55 是因为形态卡组是**围绕形态本身**的，第一次三选一得赶在玩家忘记自己选了什么之前。一整局（约 5 分钟）5-7 次；擦边流更快。BOSS 的 100 点可能在低等级一次跨过两级——弹窗会连开两次，第二次换新卡。

**升级池**（`src/mutations.ts`，数值在 `mutation.pool` 段）：**必选、全池均匀随机、数值型可叠加、按路线过滤废牌**（选了沸腾就永远抽不到吞噬专属；枪管到顶后"枪管 +1"也不再出现——一张死卡出现在必选里是对玩得好的惩罚）。卡面：

- **全员**：枪管 +1 / 射速 +1 档 / 子弹伤害 +15% / 弹速 +25% / 越大伤害越高 / 越快伤害越高 / 大弹丸 +30% / 射程 +40% / 追踪弹 30% / 护甲 +2 防御 / 厚甲 +5 防御 / 修复血条 +20（一次性）/ 血上限 +20 / **霰弹支线五张**（见下）
- **吞噬专属**：吸取范围 +15% / 吞噬无敌 +0.3s / 大胃口 +1 档（比体积说的话多吃一档）
- **沸腾专属**：怒气积攒 +15% / 爆破半径 +15% / 余温（怒气衰减 -25%，十张封底 0.05）/ **怒甲支线四张**（见下）

**枪卡全部在全员池**（枪管/射速/伤害/弹速/大弹丸/射程/追踪弹/霰弹）：枪是每个形态的基础武器，所以枪卡是每个人的卡——形态之间分的只是身体，不是武器。

**怒甲支线四张：沸腾路线自己的卡组**（`mutation.pool.rage`）。和霰弹那套不同，这几张**不深化某一张转型卡**
——沸腾开局就带着怒甲和灼烧，所以它们没有前置条件，沸腾的第一次三选一就可以是"关于沸腾"的：

| 卡 | 效果 | 每张的量 |
|---|---|---|
| 怒甲更快 | 攒甲间隔 ×(1 − 20%)：5 秒 → 4 → 3.2 → 2.56 | 地板 **1.25 秒**（乘法的封底，见下） |
| 多存一层 | 怒甲上限 +1：2 → 3 → 4 | 封顶 **5** 层 |
| 破甲更深 | 破甲倍数 **+0.25**：1.5 → 1.75 → 2.0 | 加法，不封顶 |
| 灼烧更烈 | 每跳伤害 **×2**：2.5 → 5 → 7.5（7.5/0.5 秒 = 15 点/秒） | 乘法，不封顶 |

两个封底/封顶都在配置里写着理由：攒甲间隔和灼烧是**乘法**（攒甲五张就掉到三分之一，一秒一个甲不再是
"节拍"而是贴脸即无敌），上限则是不让它从"攒一手"变成"只要不一直撞就一直有"。另外两张是加法，加法自己封顶
——玩家的卡位就是上限。**「破甲更深」是"和霰弹结合秒杀一切"的那个开关**：霰弹贴脸几颗一起命中，把破甲乘上去
就是成倍的伤害。破甲倍数现在由 `run.armourVulnerableMultiplier` 决定并在**标记落地时
拷贝到敌人身上**（卡在窗口期拿到不会追溯改写已经发生的那一下）。

**霰弹：枪的一条支线**（`mutation.pool.shotgun`）。枪的常规升级方向是**大而远、精确**；这条支线是**反方向**：一次打出一把，间隔拉长，靠贴脸拿收益。

- **转型卡「霰弹枪」**（只拿一次）：射速 ×0.5、每排一次打 **4 颗**、4 颗在 **12°** 里均分。四张配套卡**只在拿过它之后才进池子**——单独拿到"多一发"没有张角就是白送 DPS，一张会在错误的时候被抽到的废卡是这个池子最不该有的东西。
- **配套**：多一发（齐射 +1 颗）/ 抵近射击（60 米内弹丸伤害 +35%，可叠加）/ 收束（张角 −25%，**有 40% 的地板**，否则叠四张后弹丸叠成一条线，"散"就看不见了）/ 顶开（命中击退 +50%，可叠加）。

**"近身高伤害"没有一行衰减代码**：弹丸是**直线斜飞**的，所以越近全中越多、越远越散——几何自己就是那句话。这条阶梯是量出来的（`node scripts/probe-shotgun.mjs` 打出来并断言，一屏 361 米宽、一条鱼 0.035 泳道宽）：

| 距离 | 命中 | 意味着 |
|---|---|---|
| ≤120 m | **4/4** | 一枪 4 颗全中，DPS 是普通枪的 **2 倍** |
| 200–450 m | 2/4 | 半速 × 两颗 = **和普通枪刚好打平** |
| ≥700 m | 0/4 | 什么都打不到——**你只能逼近** |

**12° 这个数是这条阶梯定的**，不是拍的：20° 会把整条阶梯拉近（120 米只剩两颗、450 米全空），等于删掉"中距离打平"那一段，让这条支线退化成纯贴脸武器。

**"追踪弹"和它是反的**：追踪会把飞散的一两颗拉回目标身上，所以"追踪 + 霰弹"是**收敛**而不是散开——同一把枪上两条相反的轴，拿到一起是一把会拐弯的霰弹。

**两张"伤害跟着子弹状态走"的卡**（`sizeDamagePerPick` / `speedDamagePerPick`）是**付钱买耦合**：

- **越大伤害越高**＝（当前半径 ÷ 发射半径 − 1）× 每张。注意「大弹丸」的倍率在这一项里**会约掉**（它同时抬高起始半径和成长率），所以它奖励的是**飞得久**——实际是张射程卡。
- **越快伤害越高**＝（弹速加成 − 1）× 每张，也就是按**弹速卡的堆叠**算，不按飞行过程算。

**两者读的东西不同，这是故意的**：如果都读飞行时间，"两条路"就会退化成"两张都拿"。正因为一个读飞行、一个读堆叠，**射程流**和**弹速流**才是两个构筑。两个 bonus 乘算。

默认伤害**故意不跟体积挂钩**——否则"慢速大气泡流"自动变成唯一正确答案，BD 就没有选择、只有正确答案。这两张卡是让玩家**主动花钱**买那个耦合。

「弹速」**最早从路线专属放开到全员池**：不放的话「越快伤害越高」在别的形态那里就是一张写在牌面上的 +0%——它按弹速加成算伤害。

**数值型卡改的都是乘数，计数存在 `run.mutations` 里、每次开新关后从计数重新推导**（`applyMutationPassives`）——否则跨关时玩家本体重建会把已选的乘数悄悄洗掉。

#### 暂停面板里的「成长」：这一局到目前为止拿到了什么

局内点齿轮暂停，面板顶部（标题之下、音量之前）有一段 **成长 / GROWTH**，纯文字：

- **五项当前数值**：血上限、枪管（几排 / 最多几排）、射速（发/秒和第几档）、伤害、护甲。读的是模拟正在用的那些字段，
  所以这是"现在的你"，不是"卡片单独给了多少"。
- **拿过的卡**：只按**第一次拿到**的顺序列一组**突变**，
  同一张拿了多次合成一行写 `×次数`。每行名字下面的小字就是卡自己的说明，**原样复用三选一面板上的那句**，两边不会说法不一致。
- 卡片放在一个**可拖动滚动**的窗口里（手指或鼠标按住往上拖，鼠标滚轮也行，窗口右边有一根细滚动条）。窗口高度跟着内容走，
  最多 `settings.growth.windowMaxHeight`；局内的面板因此会变高（上限 `panelMaxHeightRatio`，从主菜单打开的面板不变，仍是屏高的 66%，也**没有**这一段）。
  每次打开都从顶端开始。

**这份清单靠一个日志**：`Run.picks` 按拿的顺序记每一张卡的 id。以前只有叠加类突变有次数（`run.mutations`），枪管、射速、修复血条
各改各的字段，没有"拿过"的记录，所以不可能列出来。现在**所有选卡只经过 `pickMutationCard`（`src/mutations.ts`）一个地方**，
它同时执行卡、写日志、重新推导被动数值——想绕开它拿一张卡，面板上就不会出现这张卡。日志和 `run.mutations` 同一个生命周期：走进下一关保留，死亡才清空。

数值和排版都在 `config/mechanics.json5` 的 `settings.growth`（字号、间距、七个颜色、窗口高度范围、没有卡时的提示语），都有校验规则。
文字内容由 `src/growth.ts` 的 `growthView(run)` 算出来（纯函数，不依赖 Pixi），`scripts/probe-growth.mjs` 用真正的选卡路径验证它。

### 擦边：贴着死亡飞过去

一条正在**冲锋**的生物（过了前摇、正在飞的那一段）从你身边掠过——**近到贴脸、却没有碰到**——就是一次擦边：

- **过点判定**：只有当冲锋的怪**不再朝你过来**（运动方向与“怪→你”连线点积 ≤ 0——正在远离、或在最近点上垂直掠过）而它还在圈内，才算擦边。**一条笔直冲着脸来的冲锋，进圈到撞上全程不判**——站在弹道上不叫擦边，钱是躲闪的报酬，在怪真正擦身而过的那一帧到账。判定圈是接触半径 × `graze.radiusMultiplier`（默认 2，怪越大圈越大）；追着一头正在离场的冲锋怪贴上去也算（它本来就在走，追它有代价）。
- **一次冲锋限一次**（冲锋状态自带 grazed 标记）；**碰到过你的冲锋永不判擦边**（hitPlayer 标记——挨过你一下的冲锋什么也不欠你，出圈也不补发）；**挨打后的无敌闪烁期间同样不判**（闪烁期白嫖经验违背“擦边最危险”的定位）。
- **即时结算**：慢动作、突变值、“擦边！！”浮字在过点那一帧当场到账，之后被不被击中都不回收。
- BOSS 甩出来的**矿物颗粒**走同一套冲锋曲线（前摇为 0），躲颗粒贴脸也算擦边——BOSS 战因此也有得赚。
- **子弹擦边是同构的小兄弟**：电鳗/海胆射出的子弹，用同一套过点判定（子弹飞行方向不再指向你）+ 同一个 `graze.radiusMultiplier`，小字「擦」、4 点、不慢动作——见上面那张来源表。
- **慢动作是全局统一的**（`slowMotion.graze`：0.25 倍持续 0.5 秒，再花 0.3 秒渐回）：玩家、生物、子弹一起变慢。过点判定下它在危险峰值**之后**触发——**后怕节拍**：怪已经擦过去了，世界慢半秒让玩家看清刚才发生了什么、顺便喘口气（和 DMC/Bayonetta 的 near-miss 反馈同一个位置）。**连续擦边不叠加只刷新**——奖励是"时间"不是"超能力"。
- **"擦边！！"浮字**独立一套样式（`grazePopups` 段），比分数飘字更大更响；浮字系统为此加了一个直接写文字的入口（`NumberPopups.say`）。
- **气泡边缘闪一下**（`graze.playerFlash`，默认 0.25 秒，画在**碰撞半径**上）：这是三样反馈里唯一长在**气泡自己身上**的——浮字说的是发生了什么，慢动作说的是看这里，只有这一下说的是"差一点被碰到的是你"。**不做常驻的擦边范围显示**：那等于把擦边从手感变成看圈办事。

### 慢动作：一个时间轴，两处用它

**游戏里只有一个时间缩放**（`frame()` 里的 `timeScale()`）。它乘在 dt 上，而 dt 是**唯一的灌注点**——固定步长和绘制都从它出来，所以玩家、生物、子弹、水、飘字一起变慢，没有哪一处能和另一处不一致。这个游戏里所有计时都是 dt 驱动的，所以不需要逐系统改；工程量小是因为架构本来就是这样。

**两件事会触发它**，各给一组数（`slowMotion` 段），但共用同一套算术——"硬慢到 `factor`、保持 `slowSeconds`、花 `recoverSeconds` 线性回来"：

| | 触发时机 | 时间感 |
|---|---|---|
| `slowMotion.graze` | 擦边的危险峰值**之后** | **后怕**：回头看刚才差点死在哪，短促（0.5 秒） |
| `slowMotion.pick` | 突变条满、卡片出现**之前** | **预告**：告诉你接下来要选了，够长到反应过来（0.6 秒） |

**同时发生取更慢的那一个，不叠加**——两者都是"整个世界慢下来"，相乘会让一次擦边撞上一次选卡变成谁都没调过的速度。

**两处的倒计时都按真实时间走，而且在暂停 / 三选一 / 菜单里冻结**：慢动作不该在暂停面板背后偷偷跑完。

**音乐怎么跟着**：

- **录音**（`src/streamedTrack.ts`）用 `playbackRate` 跟着时间缩放——这是 `<audio>` 元素唯一能被拖慢的方式，音高一起降，像磁带。三选一期间**按住不动**：淡出到静音（`holdFadeSeconds`，和 `pick.slowSeconds` 对齐，所以卡片出现的同一刻刚好静音）、`pause()`，但**记着播到哪了**；选完从那一秒接着播，不回到开头。173 秒的曲子一关弹三次三选一，每次都回开头会很出戏。
- **合成音乐**（`src/music.ts`）几乎不用为慢动作做什么：`update` 每个模拟步调一次，慢下来时铸出的步数变少，音符自然拉开（这一条是免费的）。多做的只有一件事——把音高乘 `scale`、时长除 `scale`，补成真正的磁带慢放，否则它和录音会在同一个机制下听起来不一样。
- **音效**（`src/sfx.ts`）世界里那三组（`combat` / `env` / `player`）跟着慢：音高乘 `scale`、每段时长除 `scale`。**`ui` 那组不慢**——按钮、卡片、以及"慢动作要开始了"这句提示，都是玩家对一个**控件**的反馈，不是发生水里的事；把它们拖慢只会让面板本身显得卡住。

**为什么录音音乐必须按真实时钟淡出**：它一度跑在 `step` 里（世界时钟），于是"0.6 秒淡出"在 0.3 倍慢动作下实际用了 2 秒——实测淡出速率正好是斜坡的 0.53 倍，也就是那个 0.3 系数，卡片弹出时音乐还剩三分之一音量。录音的淡出是媒体元素上的包络，不是模拟量，所以它在 `frame` 里、按真实 dt 走。

> **这条机制在项目史上有前案**：`.scratch/bubble-ascent/types/angry.md` 设计过「精准擦边流」（擦边喂怒气、完美擦边短暂减速），砍掉的原因恰恰是**缺判定层**。现在判定层补上了，经济改喂突变值；"擦边喂怒气"留作暴躁气泡的二期差异化强化。

### 小泡泡子弹（气泡自带的枪，默认一直开火）

**不用按键**：气泡按固定节奏自己往上吐小泡泡，像街机空战里的子弹。打在生物身上**掉血**，血掉光它**不会死，而是掉头加速游出屏幕**——被赶走，不是被杀。

**子弹会加速、也会变大**——而且这两件事是同一个机制的两面：

| 键（`bullets` 段） | 管什么 |
|---|---|
| `rateTiers` | **三档射速**，如 `[4, 6, 9]`：第一档是开局，每选一次「射速 +1 档」的突变升一档。**档数 = 这个数组的长度**；第一档设 0 = 完全关枪 |
| `damage` | 每发伤害。**与体积、速度都无关** |
| `speedStartPerSecond` / `accelerationPerSecond` / `speedMaxPerSecond` | **速度曲线**：初速 →（每秒加这么多）→ 最高速封顶。单位是泳道宽/秒（加速度是每平方秒） |
| `radiusRatio` / `radiusGrowthPerSecond` | **体积曲线**：发射那一刻的半径，以及每秒长多少（泳道宽的比例） |
| `lifeSeconds` | 存活秒数，也就是射程 |
| `colour` / `alpha` / `rimColour` / `rimAlpha` | 外观 |

**体积只跟"它还能活多久"有关**，不跟速度直接挂钩——所以飞得慢的子弹在屏幕里待得久、一路胀成大圆，而飞得快的还没胀起来就已经出屏幕或者打中了。这就是"**高速弹幕流**"和"**低速大气泡流**"这两条路的分岔点，也是默认伤害**不**跟体积挂钩的原因：挂钩的话慢速流会自动变成更强的那个，BD 就没有选择、只有正确答案。

- **没有体积上限**：唯一的限制是 `lifeSeconds`。加一道人为的天花板会让"堆射程"在后期变成一张被截断的卡。子弹因此会挡视线——那是**数值问题**（调小每秒增长），不是机制问题。
- **命中判定用实时半径**：画多大就碰多大（项目铁律），所以一颗飞了很久的子弹是从更远处打中的。那是这个机制本身，不是副作用。
- **三张卡各自抬高一整条曲线**：`弹速 +25%` 把初速/加速度/上限一起乘，`大弹丸 +30%` 把起始半径和成长速率一起乘。**`射程 +40%` 因此顺带让子弹长得更大**——"活得久"和"长得大"在这个模型里是同一件事，拆开反而要另立一套记账的例外。
- **贴图保留**（`image` / `imageScale` 不动）。连续放大确实会把像素拉花，但那是**接受的效果**：一颗正在胀大的气泡在像素画里越来越糊，本身就是"它变大了"的一种表达。

速度的三个阶段（初始 / 加速 / 最高速）默认**在射程内都到得了**：默认 1.4 秒到顶，而 `lifeSeconds` 是 2.2 秒。默认值也让**总射程与旧的匀速版本大致相等**（≈3.5 泳道宽），所以这一版不加强也不削弱枪。

血量在 `hazards.health` 段，**每种危险物一行**（漏了会加载报错）。这里存的是**血量**，不是"几发"——伤害能被卡堆高，所以同一条鱼的所需发数是你当时构筑的**结果**，不是配置里的规定。量级上鱼是标准（**10**），海胆是最厚的靶子（**75**）。**0 = 子弹直接穿过去**，也就是"这种不参与被打跑"——地形、环境干扰和**电鳗**是 0，其余都是正整数。

**电鳗是唯一的不可伤害炮台**：打不掉（血量 0），也吃不到（`edibleAtTier` 锁在最高档，体积和「大胃口」都够不到）。它仍然随水流漂、仍然开火，玩家只能躲位移，不能把它清出水面。它的代价在**麻痹**（左右反向），不在伤害：弹 5 点、本体 10 点。

**打跑不等于拆弹**（炸弹鱼）：它的血打空就**在原地**炸开——远距离打爆是唯一安全的拆法，贴脸打爆等于自爆。这一条和它的追踪速度、点燃距离、引信长度、爆炸半径一起写在 `hazards.bombfish` 段。

**海胆是全场最快的子弹来源**：发射**尖刺**（`shape: "spike"`），181 m/s，比电鳗那发 108 m/s 快 1.67 倍。尖刺画成一颗顺着飞行方向的细长菱形——远程的普通弹丸在余光里只是一个点，而一根针能说出它朝哪去。

**退场是三个方向随机之一：上方 / 左边 / 右边**（`fleeScreensPerSecond` 是速度，单位**屏幕高/秒**，默认 0.9 ≈ 一秒多窜出画面）。为什么不是永远往上跑：只有一个方向的话，玩家两分钟就学会"被赶走的鱼都往上飘"，那看起来像一段固定动画；三个方向都有，每次都不一样，才像"这条鱼自己决定跑了"。侧向退场会从左右边缘游出画面（所以横向也要有清理），而且**朝向会跟着退场方向**（往左跑就是头朝左）。

> 速度单位为什么是"屏幕高/秒"而不是"相对水流几倍"：水流只有 25 m/s 而一屏有 800 m，"水流的 2.2 倍"听上去很快，实际是半分钟才出画面。

**退场中的鱼是暗的**（`fleeAlpha`，默认 0.42）：用**同一套画法整体压暗**，而不是换一套退场专用颜色——形状、颜色、朝向全都还是它，只是明显比水里的其它鱼淡。玩家一眼就能分出"这条已经在走了，别浪费子弹"。

**开枪和打中各有音效，而且是"一对"**：打出去是往**下**掉的一小声加一记气声（`audio.bulletFireVolume`，默认 0.3），打中是往**上**挑的一声脆响（`audio.bulletHitVolume`，默认 0.5）——光凭方向就能分出是出膛还是命中。打中那个更响，因为**开枪是节奏、打中才是信息**。

- 打出的声音**每一发音高随机飘几个百分点**：一秒四发、音高完全一样的话，它就不是音效而是节拍器。
- **打空、打在木箱上都不出声**，只有真的掉血那一下才响；把生物打跑的那一发会按打中的音量再响一点（×1.4），算是"这条搞定了"的收尾。
- 两者都是全游戏最短的音效，因为一秒要响好几次，不能挤掉别的音；打中的那个和"挨打"那声低沉闷响是两件事（一个"我被打了"，一个"我在打它"）。

**两个设计判断，写在这里免得被当成 bug：**

- **掉血不等于死。** 这游戏里生物只有两条出路：**被吃掉**（食物链反转）或**被赶走**。小泡泡买的是第二条，所以血掉光时它加速离场，不爆炸、不给分、不掉东西。
- **开枪是类型属性**（`BubbleType.firesBullets`），两种气泡默认都开着。想让它纯粹是近身角色，把这个类型的那一项改成 `false` 就行。
- 子弹会被**障碍物挡住**（看得见的木箱就该挡住你打出去的东西），但**不会打坏它**——开箱子是冲撞和爆破的活。

### 障碍物（四种，四种答案）

障碍是**已有机制的靶子**：冲撞撞碎东西（沸腾路线），体积碾压（大过阈值就撞得动）。

四种障碍**不是四档耐久，而是四个不同的答案**——这是它们存在的理由，所以每一种都必须有一句话能说清"怎么过"：

| | 怎么过 | 撞得碎吗 | 耐久 | 外观 |
|---|---|---|---|---|
| 木箱 `crate` | 撞碎它 | 体积 ≥ 4 | 1.0 | 棕色方格 + 细十字 |
| 珊瑚 `coral` | 绕开它，或者变小穿缝 | 体积 ≥ 4 | 3.5 | 粉色团块 + 分枝 |
| 封路木箱 `wall` | **从最小缺口挤过去**（沸腾路线的冲撞/爆破除外） | **撞不碎** | 3.0 | 棕色**横板**（同一种木头，形状更厚） |
| 渔网 `net` | **穿过去就撕开了** | 不适用 | 0.4 **秒**（见下） | 青色绳网 + 撕开的洞 |

配置在 `obstacles` 段，全部有中文说明。`ramVolume` 里按种类覆盖"撞碎它需要的体积"，`null` = **撞不碎**。

**`null` 而不是一个很大的数**：`volume.max` 以后可能调大，而 99 会某天变成可达的。用 `null` 的话，"墙撞不碎"是规则而不是当前的数值巧合。

**渔网的耐久单位是秒，而且是被物理定下来的**。它不是被打碎的，是被**撕开**的：接触期间每秒算 1 点，所以 0.4 就是"在网里待 0.4 秒"。为什么是 0.4：玩家被卷轴以 25m/s 带着走，和一张网的重叠大概只有 0.5 秒。**撕裂时间必须短于一次穿过**——更长就意味着"永远撕不开"，而一张撕不开的网看起来什么都没做。撕开只有"推进去"这一条路。

**渔网会拖慢你**（`netDrag` 0.35，两轴都乘）。这不是装饰：一个又挡不住你、又不掉血的障碍如果什么都不做，就**和空水域完全没区别**，玩家冲过去不会知道那里有东西。拖慢是能感觉到的，而且它顺带解释了为什么会被撕开——被拖住的那点时间刚好够把它磨开。

**渔网不掉血**（`contactHurts` 对它是 false）。它是唯一对**小**的玩家不惩罚的障碍：小的玩家撞不碎木箱，但可以穿网。

**封路木箱用横板，因为"它和木箱是同一种木头，只是不给你一次撞碎"这句话得让形状说**：四等分会读成**窗框**（一个带厚框的物体），四等分再加木板线会读成**格栅**——那是最糟的一种，因为**长得像渔网的墙，是玩家一眼认不出来的墙**，而这两者是相反的答案。横板和绳网没有任何共同形状，也和单个木箱没有。

**最重要的一条规则**：`minGapFraction` 要求**每一排都必须留出一个玩家最小时也能通过的缺口**。

这不是体贴，而是让"变小"成为**选择**而不是必需——如果某排能把泳道封死，玩家就必须在那个时刻是小的，否则死，于是"这里该不该大"就不再是问题。留了缺口之后，大气泡永远可以选绕路（慢、贵、大概要挨一下），小气泡可以穿线，**两种都可行，选择才是真的**。

`assertLevelSane` 在启动时对着这条规则检查**每一个手工排布的排**，违规直接抛错并指出是哪一排：

```
Level "open-water" is unusable: obstacle row at 1070m leaves no gap of 0.17 or more
```

`place.barrier` 是**先把缺口撑开、再把块放在外侧**（不是先均匀放块、再删掉落在缺口里的——那样留下的块离缺口不够远），所以缺口宽度由同一条规则推导出来，是保证而不是请求。


#### 关卡里的用法：先教，再并排，最后连成一段

- **750m**：第一张渔网，两块、缺口很宽。它教的是一件**没有别的障碍教过的事**——它挡住你、不伤你、你一直压着它就开了。刚学会"木箱撞、珊瑚绕"的玩家没有理由猜到这一条，所以第一张是拿来试的，不是拿来考的。
- **920m + 960m**：渔网和封路木箱**并排**（相隔 40m）。和 1030/1070 的珊瑚+木箱同一个手法：两种障碍放在一起，"我手上有什么、我有多宽"才会变成一个**问题**，而不是两件事。
- **1386 / 1416 / 1446m**：最后一段变成**连续的窄缝走廊**（三排珊瑚，间隔 30m = 1.2 秒），关卡最后的**海胆和两个垃圾袋就在走廊里面**。

最后这一条是把"极限瘦身"从**一个瞬间**变成**一段状态**：一次窄缝是你要活过去的事，三次、中间还夹着危险物，是你必须**保持**的状态。吃下去的东西挡路的时间从一秒变成四秒，而"要不要继续变瘦"在这四秒里一直是个决定。

顺带删掉了 1440m 那排鱼（6 条）。**不是为了腾地方，是它已经不构成压力了**：鱼追最大的气泡，而走廊的作用恰恰是保证玩家到海面时是小的——一排鱼对着一个小气泡是**饭**，不是威胁。留着它就是把奖励伪装成危险。


### 血量与伤害：一个池子、一个能堆的防御

**血条走 100 制**（`health.start`），**三条路线共用**。它曾经是两套：会长大的路线把血量藏在体积里，另外两条用一套
独立的点数。那代价是死亡由**体型**决定——玩家看着气泡多大来猜自己还剩多少血，而那个换算（开局 5 下、满体积
50 下，十倍的跨度）藏在只有 2.6 倍的尺寸变化里，读不出来。

**伤害是减法**：

```
扣血 = max(伤害 × 10%, 伤害 − 防御)
```

- 每个敌人**一行伤害**（`hazards.contactDamage`，10~40）：小鱼 **20** 是标准，精英 **30**（会冲锋的、会开枪的），
  鲸鱼和喷口 **35**，BOSS **40**。
- **防御是一个能堆的整数**，初值 0、没有上限：「护甲 +2」和「厚甲 +5」两张卡。
- **保底是伤害的 10%，不是"至少 1 点"**：在 100 制下 1 点几乎等于没有保底——20 伤害打 30 防御每下掉 1 点，
  那是换了个说法的无敌。10% 的意思是"**防御最多吃掉九成**"。
- **百分比抗性没有了**：`shrinkResistance` 和给它供数的「减伤 +8%」一起删掉了。防御和抗性两个通道答的是同一个
  问题，而一个能在减法之上再叠百分比的玩家没有可读的上限。
- **没有"一击必杀"**：喷口是 35 点（一堵明摆着的墙，三下拿走你的血），不是一个必杀标记——血量上限会成长，
  "够大的伤害"是个会过期的判断。
- **被动回血每秒 1 点**（`health.regenPerSecond`），三条路线共用，只在**关卡进行中**生效：暂停、选卡、出生演出、
  破裂、爬升和结算都不回。攒够一秒才跳 1 点，血条上的数字始终是整数；只封顶在 `healthMax`，没有每关额度。
  关卡中途回血**不会**让吞噬路线的气泡变大——体积仍只在关卡开始和选路线时重算。

**哪些伤害吃防御**：敌人接触、敌方子弹、障碍物碰撞。**哪些不吃**（`defense` 传 0）：怒气失控、连锁放电自伤、
垃圾袋吸取。那些是玩家自己的动作在收账，防御若能挡它们，堆防御就等于把"要不要压着怒气"这个决定一起删掉。

**血条在左下角**，固定长度进度条 + `87/100`：条说比例，数字说绝对值。低于 `lowThreshold`（默认 **0.30**）填充
变红，同一个数也是屏幕裂纹的起点。放左下是因为那一角一直是空的——触屏按钮全在右下角一列，拖动是任意位置起手。

配置在 `health` 段（上限、被动回复、两张卡的增量、保底比例）、`hazards.contactDamage`（每种敌人一行）、`hud.healthBar`
（长度、位置、配色与阈值）。设计与那几轮取舍记在 [.scratch/damage/spec.md](.scratch/damage/spec.md)。

### 体积：血量的表现（吞噬路线）

**吞噬路线的体积不是吃出来的，是血量的读数**：满血最大，快死了最小，四档。

| 血量比例 | 体积 |
|---|---|
| < 30% | **2** |
| 30–50% | **5** |
| 50–80% | **8** |
| ≥ 80% | **10** |

- **只在两个时刻重算**：关卡开始时，以及**选下吞噬路线的那一刻**。战斗中途不重算——判定框在战斗中途变小，会
  让"贴多近能吃"这个刚学会的判断当场失效，而那是这个游戏里最贵的一种困惑。
- **血是跨关继承的**（见上一节的 `resetHealth`），所以这几档真的会动：带着 40% 血进下一关，气泡就真的是一颗
  小气泡。每关开始就回满的话，这个设计会永远停在最高档，等于没有。
- **吃泡泡回血**（`volume.healthPerVolume`：每一点体积换 10 点血）：一个中等泡泡回 10 点，大的回 40。所以
  "追大泡泡"这条老规矩没变，变的只是它付的货币。
- **吞生物**同样回血（按质量换算），分数与突变经验不变。
- **不长的路线体积恒定**（开局定下就不再变），不吃这一套。

配置在 `volume.healthBands`（四档与三个阈值）和 `volume.healthPerVolume`（一个泡泡值多少血）。

### 血量告急：两壁的裂纹 + 四边的逼近

血量比例低于 `hud.brokenScreen.threshold`（默认 **0.30**，和血条变红**同一个数**）时出现**两层**效果，它们说的是不同的话。

**裂纹（`hud.brokenScreen` 本体）说的是"哪里裂了"**：

- **从泳道两壁，不是从屏幕四边**：水域在纵向上是无限的（它在卷动），所以"屏幕的上边缘"是视口造成的、不是一堵墙。气泡能碰到的只有左右两壁，所以只有这两条会裂。**量的尺子也是泳道**：桌面窗口里泳道只有中间那一条（上限 900px），按画布算的裂纹会长到泳道外面的水面上——那是气泡碰不到的地方。
- **程序画的，不是素材**：裂纹是"沿边框"的形状，而边框长度随屏幕变（390×844 到 1920×1080）。素材管线的
  图是固定像素密度的，贴图要铺满不同屏幕就得拉伸，而拉伸正好破坏"一个密度"那条规则。
- **颜色跟随当前路线/阶段的 `hudColor`**：不长路线青→金→粉，沸腾路线随怒气蓝→橙→红——和气泡自己是同一个颜色。
- **强度静态**，只跟血量走（`(阈值 − 比例) / 阈值`），不脉动。
- 因为静态，它只在血量变化时重画（守卫在强度上，2% 一档），不是每帧重建几十条折线。

**边缘渐变（`hud.brokenScreen.vignette`）说的是"整个画面在逼近"**：

- **在泳道里**：上下两条横跨**泳道的宽度**，左右两条就长在**两壁上**。泳道外面的水是气泡碰不到的地方，在那儿画警告是在警告一件不存在的事（这个坑 BOSS 血条、进度图、裂纹各踩过一次）。纵向没有这种边界——水域在卷动，所以上下两条仍然到屏幕边缘。
- 从边缘向中心淡出，**按固定频率闪动**（`pulseHz`）。
- **颜色固定蓝**，不跟路线走：裂纹已经跟路线了，两张不同的嘴说同一句话会互相抵消。这一层是屏幕级的压迫感。
- **每边按自己的轴延伸**：横向的两条按**泳道宽度**、纵向的两条按屏幕高度，不是统一按某个基准——统一的话四条边的观感就不一样了。
- **闪动有底**（`pulseDepth` 默认 0.45）：让它在闪的同时不至于完全灭掉，因为"看不见"的那几帧会被读成"危机解除了"，而那是警告最不能撒的谎。
- 它**每帧都在动**（闪动），所以几何只在强度变化时重建，每帧动的只是这一层的 `alpha`。

两层都画在 **HUD 之下**，HUD 永远可读。

配置在 `hud.brokenScreen` 段（阈值、裂纹条数与深度、线宽与发光、两端不透明度、形状随机种子）和它的 `vignette` 子段（颜色、最深处不透明度、延伸比例、闪动频率与深度）。
设计与取舍记在 [.scratch/broken-screen/spec.md](.scratch/broken-screen/spec.md)。

## 测试

**端到端测试用 Playwright**，在 `e2e/`：

```bash
pnpm test                # 全部（phone + desktop 两个 project）
pnpm test:phone          # 只跑手机尺寸，迭代时用这个
pnpm test:ui             # 交互式：时间旅行、逐帧看、重跑单个用例
pnpm test:report         # 打开上一次的 HTML 报告
pnpm test:shots          # 只截图（不算测试，看画面用），输出在 test-results/
```

**为什么是 Playwright。** 之前 `scripts/` 里的探针每一支都靠裸 CDP 驱动浏览器：手动 spawn Chrome、
轮询 `/json/list` 拿 websocket、手写 promise 客户端、再 `Runtime.evaluate` 字符串。**每个文件重复约 130
行脚手架，而那些探针的绝大多数 bug 就住在那层脚手架里**——读了游戏已改名的字段、抄了实现而没调用它、
`until` 辅助函数返回了上一轮的采样。

Playwright 把这一切换成 `page.evaluate(() => ...)`：页面里的真函数调用、自动等待的 locator、trace 查看
器、`--ui` 模式、失败重试和失败自动截图。**脚手架成本归零，断言终于可以只关心游戏本身。**

游戏自己的测试钩子 `window.__GB` 仍然是正确的接缝——canvas 里没有 DOM 可查，水面、气泡、危险物都是
Pixi 的绘制调用，所以"气泡动了"没有诚实的 locator。钩子是**刻意的**：它暴露卷轴、玩家的屏幕比例、危险物
列表和音频图，好让测试断言**事实**而不是事实的替身。

只有两样东西走真实输入，因为那才是被测对象：**菜单的开始按钮**和**设置面板的控件**——它们由游戏自己做
命中判定，所以点歪了就是失败，而不是悄悄通过。

| spec | 覆盖 |
|---|---|
| `main-loop` | 菜单→开局；**版本号与 git hash 真的画在菜单和调试读数上**（且与编译进去的一致）；**卷轴独立于玩家**（静止和按着时分别测速率）；两轴匀速；无输入不漂移 |
| `settings-and-menu` | 齿轮暂停（断言 `scrolled` 不动，不是标志位）；滑块驱动主增益、点轨道也生效；取消/保存恢复；重开回到阶段1；退出到菜单**并停止环境音** |
| `stages` | 按配置阈值晋升；每级**实测更慢**（稳态速度 + 位移）；**画出的半径与轮廓色**逐级不同 |
| `drag` | 触屏拖动：**屏幕任意位置按下就能操控**（不用找控件）、手指位移与气泡位移**严格 1:1**（按像素折算成泳道宽/窗口高）、**松手后一格都不漂** |
| `consumption` | 食物链反转：档位以下受伤、档位以上吃掉、逐档逐种类校验、质量来自配置 |

| `score` | 积分：开局为 0、**每一种事件按配置给分**（打跑 / 吞下 / 击败 BOSS 各自计价）、**账本按事件计数**（总分不可能和配置对不上）、把某项设成 0 就真的不给分也不记账、**读数真的画在屏幕上**（读的是 HUD 的字符串，不是重算一遍）、**飘字出现在事件发生的位置**（实测得分处 ≠ 气泡处）并且**一路向上**（不是被水带着往下沉）、**每一项参数都从配置读**（含两条曲线，实测 `riseEase` 只改路径不改总高度）、到点消失、开新一局会清干净、结算卡的最终分数与会话最佳、**开新一局归零而最佳保留** |
| `obstacles` | 障碍：**每一排都有可通缺口**（对配置里列出的每一种都对，不是只对木箱和珊瑚）、小气泡被挡且掉血 / 大气泡撞碎、珊瑚比木箱硬、**四种障碍是四种答案而不是四档耐久**、**封路木箱体积 20 也撞不碎**、**渔网穿过去就撕开且不掉血、全程被拖慢** |
| `routes` | **主菜单没有选角行，而一局开局就是选形态那一屏返回的形态**（与游戏拥有的形态逐一比对）、**另外一条路线的卡本局永不再出**、怒气只从存活下来的伤害来并会衰减、**爆破清小敌人 / 推尖锐的 / 震碎脆弱障碍且花光怒气**、**爆破半径随怒气变大**、**每种形态要么当场吃掉、要么根本不能吃**（吃是即时的，没有库存）、**沸腾路线不能吞：碰到敌人是挨打而不是被吃**（同一场景下吞噬路线当场吃掉、体积当场增长） |
| `layout` | 手机铺满、宽窗封顶居中；resize 后控件仍在屏内（**含横屏/矮窗口**，那是按钮整列被顶出屏幕的地方）；2560 宽下面板仍能打开 |
| `level-select` | 关卡阶梯（**调试专属**）：**菜单列出的关卡和文件里的完全一致（连顺序和名字）**、阶梯上**每一关都可点**（锁不参与"能不能点"）、选中哪一关就**真的玩那一关**（长度 / 节奏 / 刷怪表都是它自己的）、**抵达海面会记录通关**（跑完真关卡，不只是调钩子）、**通关记录在选择重载页面后依然在**（读的是 `localStorage`，不是内存）、解锁规则仍是"前一关"而不是计数、**进度可以重置** |
| `spawns` | 关卡刷怪表：**运行时报告的块数与关卡文件里的条数一致**（两个方向都校验，没有写死的数字）、**块的 `count` 决定刷出几个**（1+2+3+4+5 = 15）、写错的键 / 从侧面来的收集物 / 从下方来的布景 / 生物排成 barrier / 缺 `at` / 未知 `kind` **全部按名字拒绝**、**从左边进场的生物出生在泳道外**（x < 0，实测）然后游进来、**从下方进场的会一路升到和玩家齐平**（不是露个脸就掉回去）、**漂进来的障碍物停在配置给的位置且不会漂穿**、**发货的那一关真的会从左右下三边刷东西**（把卷轴加速跑完 1500 米，按边计数） |
| `screenshots` | 只截图不断言（`pnpm test:shots`） |

## 发布流程

### 公网：push 到 `main` 就自动发布

站点在 **<https://forteencdbw.github.io/TGBA/>**，HTTPS，手机流量直接打开就能玩。

[`.github/workflows/deploy-pages.yml`](.github/workflows/deploy-pages.yml) 在**每次 push 到 `main`** 时自动
跑：`vite build` → 把 `dist/` 的内容 force push 到 `gh-pages` 分支 → GitHub Pages 从那个分支发布。
实测从 push 到 run `success` 约 40 秒。

**唯一的前提是「必须 push」。** `git commit` 是纯本地操作，GitHub **看不见**它，所以不会触发任何东西——
**这个坑真踩过一次**：两个提交做完了但停在本地，站点一直没动，看起来像"workflow 坏了"，其实只是"没推"。
一句话：**站点永远等于 `origin/main` 的尖端，不是你本地 `HEAD` 的尖端。**

> 想重发不用造一个提交：Actions 页面 → Deploy to GitHub Pages → **Run workflow**
> （workflow 里有 `workflow_dispatch`）。

**为什么跑的是 `vite build`，不是 `pnpm build`。** `pnpm build` 是
`tsc --noEmit && tsc --noEmit -p tsconfig.e2e.json && vite build`，会**连带类型检查 `e2e/`**。
那样**正在开发中的一个 spec 文件里哪怕只是一个未使用变量，就能让站点停止更新**。Vite 只转译、
不检查类型，所以类型错误照样发布。**这是刻意的取舍**：宁可发布半成品，也不要让站点变得可被一个
坏测试文件卡死。想加质量门禁就是在 workflow 里加一行——但那就把上面这句话反过来了。

**为什么推分支，而不是用官方的 `actions/deploy-pages`。** 官方那套要求把 Pages 的 Source 改成
"GitHub Actions"，那是一次额外的仓库设置改动，而且 workflow 一旦有问题站点就直接**空白**。推分支沿用
"Deploy from a branch" 的现有设置，也让构建产物不进 `main` 的历史（`dist/` 仍然是 gitignore 的）。

**Pages 设置**（已在仓库配好，这里只是记录）：Settings → Pages → Source = **Deploy from a branch**，
分支 **`gh-pages`**，目录 **`/ (root)`**。

> ⚠️ **不要选 `main` + `/ (root)`。** 仓库根目录的 `index.html` 是**开发入口**
> （`<script type="module" src="/src/main.ts">`，TypeScript 源码），而 Pages 只是把文件当静态资源发出去，
> 结果是**白屏**，且报不出有用的错。要发布的是 `gh-pages` 分支，那里才是构建产物。

> **`gh-pages` 是生成产物，不要手工编辑它。** workflow 每次 force push 覆盖它，所以它没有值得保留的历史。

> **缓存**：Pages 回 `Cache-Control: max-age=600`，所以刚发布后手机上**最多可能滞后约 10 分钟**才看到
> 新版——"明明发布了手机还是旧的"多半是这个，不是没发布。资源文件名带内容哈希，新资源本身立刻可取，
> 被缓存的是 `index.html`；强刷或换无痕窗口即可立刻确认。

### 手动打包（itch.io、离线分发）

需要 zip 的场合才走这条：

```bash
pnpm build                              # 类型检查 → dist/
node scripts/verify-dist.mjs            # 必做：确认打包产物能跑
```

```powershell
Compress-Archive -Path dist\* -DestinationPath release\bubble-battle.zip
```

**产物**：10 个文件 / **763 kB**（主包 gzip 后 **159 kB**），打成 zip **233 kB**。
（这组数字以前写的是 590 kB / 101 kB / 175 kB，早就过期了；现在是重新量过的。）

> ⚠️ **`pnpm build` 现在会警告主包超过 500 kB**（514 kB，Vite 的默认阈值）。**这条警告是留着的，不是没看见**：
> 阈值看的是压缩前的体积，而实际传输量是 gzip 后的 159 kB；把阈值调高只会训练人忽略警告。

`vite.config.ts` 设了 `base: './'`，所有资源都是**相对路径**，所以：

| 目标 | 做法 |
|---|---|
| itch.io | 把 `dist/` 里的**内容**（不是 `dist` 目录本身）压成 zip 上传 |
| 任何静态托管 | 把 `dist/` 整个目录作为站点根，**放在子目录也行**（`/bubble/` 已实测；GitHub Pages 就是 `/TGBA/`） |
| 本地试跑 | 见下 |

> ⚠️ **不能用 `file://` 直接打开 `dist/index.html`。** 这是 ES module 的 CORS 限制，浏览器会拒绝加载模块，
> 页面上不会报有用的错，只是**白屏**。本地要起一个静态服务：
> `npx serve dist`、`python -m http.server -d dist`，或 `node scripts/verify-dist.mjs`（它就顺带验证了）。

**source map 默认不发。** 它们曾占产物的 2.9 MB / 3.0 MB，而浏览器只在打开 devtools 时才下载。
需要读压缩后的堆栈时，把 `vite.config.ts` 里的 `sourcemap` 临时改成 `true` 再构建。

> 以前这里写着"**故意不做环境变量开关**：读环境变量要用 `process`，而本项目 tsconfig 是浏览器向的、没有
> Node 类型，于是 `pnpm build` 会直接失败"。**那个理由现在不成立了**：`vite.config.ts` 已经搬到自己的
> [`tsconfig.node.json`](tsconfig.node.json)（它要在构建时读 `package.json` 和 git，本来就需要 Node 类型），
> 而游戏的 tsconfig 仍然只有 `vite/client`——所以 `src/` 里出现 `process` 或 `fs` 依旧是类型错误。
> 两条都保留：配置有 Node 类型，游戏没有。
>
> 开关本身仍然不做：一个只有构建机才能翻的开关，就是一个永远不会被翻的开关。

### 关于验证（约定）

**没有回归测试套件了，2026 年删的。** 曾经有 15 个套件、并行跑约 88 秒，靠一行
`CHECKS: {...}` JSON 判定通过与否。删掉的原因是**维护成本**：玩法从"强制上升 + 只能左右"
改成"平面自由移动 + 卷轴关卡"之后，其中 5 个测的是已删除的功能，另外 4 个引用着已改名的字段。
把它们逐个修好、再让它们跟上后续每一次机制调整，花掉的时间**超过了它们挡住的 bug 的价值**。

留下的是**不花时间的工具**：`probe-layout` / `measure-pixels` / `performance` 都只输出数字或图片
给人和 agent 看，不作断言，所以既不会过期也不会拖慢任何东西。

日常验证就两条：**`pnpm typecheck`**（顺手、约 5 秒），以及**针对自己刚改的东西做一次真实测量**。
改完手感或布局后，`probe-layout` 截一张图看一眼通常比任何断言都值。

## 测量工具的坑（重要）

**不要用 `drawImage` 读画布像素。** Pixi 没开 `preserveDrawingBuffer`，WebGL 画布合成后缓冲区即被清空，
`getImageData` 会**静默返回全黑**——我因此误判"渐变没铺满"并去修一个不存在的 bug。

要读真实像素，用 `scripts/measure-pixels.mjs`：它走 CDP 截图 + 自己解 PNG。

同理，**不要用 `--dump-dom` + `--virtual-time-budget` 验证动画**：那样只跑得到个位数帧，
看起来像"世界没推进"。用 `scripts/probe-layout.mjs`（CDP + 真实墙钟时间）。

## 调手感

所有手感参数集中在 `src/config.ts` 的 `tuning`，**运行时可改**，不用重新编译：

```js
// 浏览器控制台
__GB.player                        // 实时状态（x 是水柱比例 0..1，vx 单位是"水柱宽/秒"）
__GB.game.diagnostics              // 帧数 / 用时 / 名义总时长 / 本机标定出的横向参数
__GB.lateralSnapshot               // 这台设备解出的 accel / boostSteerFactor / stopSpeed
__GB.frame()                       // 一次性打印所有尺寸（排查移动端显示问题用这个）
```

> **横向手感参数不在这里**，而在 `src/config.ts` 顶部的**手感目标**里，以"横穿时间"表达：
> `COLUMN_CROSSING_SECONDS`（默认 2.5s）、`KEYBOARD_CROSSING_SECONDS`（默认 2s）。
> 真正的速度由 `src/lateral.ts` **按泳道宽度运行时反解**，所以换个设备手感不变。
> 纵向速度是它的 `verticalSpeedScale` 倍，两个方向用同一个常量，斜向移动不会更快。
>
> **关卡节奏改关卡文件里的 `scrollSpeed`**，它与操作、与生物的速度都解耦：
> 改它只影响关卡推进多快、一关多长（`scrollLength / scrollSpeed` 秒），不影响手感，也不影响鱼游多快（那是 `driftSpeed`）。

## 注意

- `vite.config.ts` 里 `build.minify` **不能**设成 `'esbuild'`：esbuild 只是 Vite 8 的可选
  peer dependency，pnpm 默认不装，会直接导致构建失败。
- `server.watch.ignored` 排除了 `scripts/`、`.scratch/` 等目录：Windows 上 Vite 的 fs watcher
  碰到编辑器/工具产生的临时目录会抛 `EBUSY` 并**直接杀掉 dev server**。
- **用 `pwsh` 跑 `.ps1`**。Windows PowerShell 5.1 在这里的执行策略是 `Restricted`（脚本文件被禁），
  而 `pwsh` 继承 `LocalMachine = RemoteSigned`，本地脚本可直接运行。
  若 `pwsh` 找不到，见下。

## pwsh 的安装方式（本机特殊情况）

PowerShell 7 是以 MSIX 包装在
`C:\Program Files\WindowsApps\Microsoft.PowerShell_<版本>_x64__8wekyb3d8bbwe`，
而机器 PATH 里留的是**已不存在的旧版本目录**（7.6.4 装完升级到 7.6.6 后旧包被删），
所以 `pwsh` 无法解析。

两个坑：

1. **PATH 扫描会跳过 `WindowsApps` 目录本身**。把 junction 建在 `WindowsApps` 里面**没用**，
   `where pwsh` 依然找不到。
2. 直接写死带版本号的路径，**下次升级就会再坏一次**。

所以稳定入口建在 `%LOCALAPPDATA%\pwsh7`（junction，指向当前包），并加进用户 PATH。
**PowerShell 升级后重跑一次即可**（脚本自动发现最新版本目录，可重复执行）：

```powershell
pwsh -File scripts\install-pwsh-path.ps1
```

> 机器 PATH 里那条失效的 7.6.4 条目已经无害（目录不存在，只是拖慢一点点路径查找），
> 但它归 `Machine` 作用域，**需要管理员**才能清理。脚本只报告、不修改。
