# 冒泡大作战 / Bubble Battle

一个关于「涌现」的 GameJam 项目。9:16 竖屏、手机优先、浏览器直接玩。

设计文档：`.scratch/bubble-ascent/spec.md`（吞噬气泡的完整设计）
　　　　　`.scratch/bubble-ascent/types/angry.md`（暴躁气泡，第二种类型）
后续工作：`.scratch/bubble-ascent/plan.md`（做到哪里、还剩什么、刻意没做什么）

## 三种气泡：先选角色，再开始

开局**一局选一种**，在主菜单上选（选择行在「开始游戏」上面）：

| | **吞噬气泡** `devour` | **暴躁气泡** `angry` | **普通气泡** `plain` |
|---|---|---|---|
| 一句话 | 吃掉一切，越大越强——代价是越来越难躲 | 挨打积怒，把怒气撞出去——**怒气不看体积** | 什么都不会，一滴血——**碰到就破** |
| 按钮 | 右侧竖排（下→上）：技能/吸附 · 喷吐 · 消化 | 右侧竖排（下→上）：技能 · **蓄力/冲撞** · 爆破 | 只有技能 |
| 颜色由什么决定 | **成长阶段**（青→金→粉） | **怒气阶段**（蓝→橙→红→赤红） | **什么都不随**（灰白） |
| 第二资源 | 没有 | **怒气**：受伤 +25、安全 3 秒后每秒 −5 | 没有 |
| 血量 | 体积就是血量（5 点起，吃大就更能挨） | 同左 | **恒定 1 点，与体积无关** |`n| 吸收泡泡 | 长体积（＝血量＋判定框） | 同左 | **只加分，不长大**（`score.absorb`） |

**布局属于气泡类型，不属于全局** —— 这是设计文档里定下的架构决定，也是它排在第二种气泡之前的原因。
暴躁气泡蓄力时要**锁定方向**，如果瞄准是全局的，"冻结"就变成一条特例规则；而瞄准来自"这个类型自己的输入"时，
类型只是"不再读它"就够了（而且它的按钮列表里根本没有喷吐/消化，所以那两个键盘键对它完全无效）。

**外观命名空间也是按类型分开的**：成长阶段管速度与大小，怒气阶段管颜色与形变，两者不会抢同一块画布——
这是设计文档第一条待定问题的答案，用"一局选一种"解决了。普通气泡用同一套形状、但**不随任何状态改色**：
它没有状态可以宣扬（见下）。

### 普通气泡：一滴血，而且不长大

**碰到任何敌人就破裂。** 这是 `BubbleType.hitsToPop` 存在的理由：本来的规则是**体积就是血量**
（一次受击固定扣 `volume.hitCost`，所以吃大了就能多挨几下），而这条规则会悄悄给普通气泡多几条命——
那是这个类型唯一不能有的东西。所以它写成一个**类型属性**（和 `swallowsHazards` 并排），
而不是配置里的一个平衡数值：这不是旋钮，这是这个角色**是什么**。

**它也不会因为吸收泡泡而变大**（`BubbleType.growsByAbsorbing: false`）。吸收照旧把泡泡吃掉，只是**换算成分数**
（`score.absorb`，默认 5 分/个）：不长体积、不升成长阶段、速度不变。所以它身上不存在"变大变慢"这回事。

> 这两件事是同一个 bug 的两半：它原来会像吞噬气泡一样长大。那等于让它在偷偷玩吞噬气泡那一套
> （吃东西、变大、多挨几下），而它的设计是"一碰就死"——长大对它只有代价（判定框更大、速度更慢、还有阶段惩罚），
> 换不到任何好处。它不该有那个能力，所以现在没有了。

- 它**没有**吸附、没有胃袋、没有喷吐与消化、没有蓄力与爆破。会吞危险物这条是按类型开关的，它当然是关的，
  而且它**连吐出来的动词都没有**，正好符合"会吞的类型必须有出口"那条不变量。
  所以它也**不会把生物吞进去**：实测九种危险物在体积 10 时 `canEat` 全是 false，接触就是挨打。
- 它**保留技能按钮**（`controls: ['skill']`）。技能是**关卡给的道具**，不是这个气泡的能力——如果连按钮都没有，
  捡到的技能就永远用不出去，而一个什么都做不了的拾取物比没有拾取物更糟。
- 它**保留这把枪**（`firesBullets: true`）。一滴血 + 零能力的话，每个生物都是必死的障碍物，唯一的选择就是跑；
  枪是唯一让"距离"变成可花资源的机制。枪本来就是游戏的默认武器（两种气泡都有），关掉它不会让这个类型更"普通"，
  只会让它是另一个游戏。
- HUD 的状态行对它显示"**幼泡 不成长**"，而不是 `0/12`：一个永远到不了的进度条是在承诺一件不会发生的事。

### 暴躁气泡这一轮做到哪

主干是 **积怒（受伤）→ 压缩蓄力 → 冲撞 → 怒气爆破**：

- **它没有胃袋。** 这是它和吞噬气泡最根本的差别，也是**修掉的一个 bug**：它原本会吞下敌人，而它既没有喷吐、也没有消化，所以吞进去的东西**没有出口**——过饱引信烧完就是必死，玩家什么都做不了。现在吞危险物是**按类型开关的**（`BubbleType.swallowsHazards`），而且有条不变量守着：**会吞的类型必须有吐出来的动词**（`e2e/bubble-types.spec.ts` 对每一种类型都查）。
  所以对它来说，**碰到敌人就是挨打**——而那正是设计要的：它的怒气来源就是被打。它只吃气泡（食物），靠接触、不靠吸力，所以收集得笨（设计第九节把"精准收集能力弱"列为它的弱点，这里采用了最彻底的读法）。
- **怒气只从"挨打但没破"来**。这是设计文档里那句话的字面实现：致命伤会结束这一局，没有状态可以携带怒气，
  所以也不可能有"死了还赚怒气"这种事。
- **冲撞的破坏力只看怒气，不看体积**（`P = base × (1 + 1.5 × 怒气/100)`）。这不是随手写的：它正面回答了
  设计文档里那个风险——"挨打换来怒气，但挨打也让你快死了，于是有怒气却用不出来"。**变小不会让武器失效**，
  所以残血反打是可行的，而不是死循环。
- **撞中要花怒气**：撞到障碍 −15，撞碎 −35。这是"怒气是消耗品"的来源，也让冲撞不能一直按着。
- **怒气爆破**：一次**花光全部怒气**，以气泡为中心放一圈冲击波，**怒气越高范围越大**
  （0 怒气 = 0.22 泳道，满怒 = 0.85 泳道）。它做三件事，而且**"清"和"推"是分开配置的**：
  - **清掉软体小敌人**：鱼、水母、垃圾袋；
  - **弹开清不掉的尖锐危险物**：海胆、电鳗，以及负面食物（炸弹鱼、腐败物、油污）——推得动但清不掉，
    所以冲击波对它们是"给我让开"而不是"删掉"；螃蟹也是推开，因为它是机会不是敌人；
  - **震碎脆弱障碍**：伤害 1.6 刻意只够木箱（1.0）和渔网（0.4），**珊瑚（3.5）和封路木箱（3.0）只掉一层皮**
    ——撞开木箱是**冲撞**的活，爆破要是也能一键开路，冲撞就没有存在理由了。
  哪一种是"清"、哪一种是"推"写在 `angry.burst.hazardMode`，**每种危险物都必须有一行**，缺一行是加载报错——
  否则那种生物会安静地免疫冲击波，看起来像设计而不像漏写。
- **封路木箱被冲撞撞开了**：`wall` 对吞噬气泡的答案是"弹药或最小缺口"，对暴躁气泡的答案是"怒气够高就撞碎"
  ——同一道题的第三个答案。这是设计文档要求"和机制一起定"的那一条，默认开着，开关是
  `angry.charge.slamBreaksUnrammable`（改成 `false` 就让它对木箱也无能为力）。
- **蓄力时方向锁定**：拖着手指（或按着方向键）瞄，松开输入方向就定住，再松按钮冲出去。
- **怒气槽**：HUD 文字下面一根条，填充色就是当前怒气阶段的颜色，**刻度是阶段阈值**（从外观表读的，
  所以在配置里挪阈值刻度跟着走）。它是**爆破之后**才做的——在那之前怒气只会堆满然后待着，
  一根槽只是在报一个没有用途的数字。
- **失控与自爆**：**怒气满了不是终点，是一段倒计时**（4 秒，剩余秒数显示在怒气那一行上）。这段时间里气泡
  **更大、更笨、而且能撞碎大部分障碍**（包括任何体积都撞不碎的封路木箱——判定**真的**变大，不只是画得大）。
  必须在倒计时结束前把怒气放掉：
  - **爆破**（永远可用），或者**撞碎一个大型目标**（血量 ≥ 3 的那两种：珊瑚、封路木箱）；
  - **撞碎木箱不算释放**：设计文档列的是"大型目标"，如果撞个小箱子也算，那玩家一碰布景失控就结束了，
    那不叫决定；
  - 没放掉：**受一次重伤（3 个命中点）并强制清空怒气，但不会因此破裂**。护栏和"消化不会杀死你"是同一条、
    同一个理由——设计文档明说"不会直接结束游戏"，一个没来得及按按钮的玩家不该被判死刑；
  - **失控期间的撞击不花怒气**。如果花，玩家可以一路撞到空槽，然后**没有怒气可以释放**：那个"必须释放"
    的状态会变成"让释放变得不可能"的状态。

**暴躁气泡到此闭环。** 设计文档的切分表里只剩 **G（环境内容：船锚、逆向洋流、可反弹墙面）**，
那是纯内容，它依赖的东西已经全部到位。

配置在 `angry` 段（怒气收支、冲撞、爆破、失控、四个阶段的外观、共用几何、怒气槽），全部有中文说明。
选择行的配色在 `menu` 段。

## 版本号：这一页跑的是哪个 build

**主菜单底部**和**关卡内左上角调试读数的第一行**都会显示：

```
v1.0.0 · 51be519 (uncommitted)
```

- **版本号**唯一来源是 [`package.json`](package.json) 的 `version`。**每次改动都在同一个提交里递增它**
  （1.0.1、1.0.2……），这条写在 `AGENTS.md` 里。为什么要有版本号：手机上的页面、部署出去的 URL、
  别人发来的一张截图，都回答不了"我看的是哪一版"。
- **git hash** 由**构建时**从 git 读出来（见 [vite.config.ts](vite.config.ts) 的 `define`），
  不是手写的——手写的 hash 就是一个会撒谎的 hash。
- **`(uncommitted)`** 表示打这个包的时候工作区有未提交改动，也就是：**这页是那个提交再加一些别人复现不出来的编辑**。
  没有这个标记，hash 会悄悄宣称比它知道的更多，那比什么都不显示更糟。

两个值都**不是运行时读的**：浏览器里没有 git，手机上没有文件系统。它们在你启动 dev server /
执行 `pnpm build` 的那一刻被**编进包里**（`src/version.ts` 是唯一的出口）。

> ⚠️ **dev 下它是在 Vite 启动时读一次的。** 提交之后显示的 hash 会过期，直到 Vite 重启（改这个文件会触发重启）。
> 这是**诚实**的：那个浏览器里的页面确实是用旧代码加载的。

## 改数值看这里

**所有可调的机制数值都在 [`config/mechanics.json5`](config/mechanics.json5)**，每一项都有中文说明。
改完存盘即可，页面会自动重载（Vite HMR），不需要重新构建。

格式是 **JSON5**（JSON 的超集），所以：

- `//` 行注释和 `/* */` 块注释
- 最后一项的尾逗号
- 键名不加引号
- 颜色写 `0x9fe4ff` 十六进制字面量（写 `"#9fe4ff"` 字符串也认）
- **数值写错会在浏览器控制台报错并指出是哪一项**，不会静默退回默认值——一个悄悄失效的配置
  文件比没有配置文件更糟
- 运行时的 `window.__GB.tuning` 和它是**同一个对象**，所以控制台里改和改文件是一回事

代价是 json5 解析器会进包：**主包 +33 kB（gzip +10.5 kB）**，一次性。这是"配置文件人能手工编辑"
的价格。

`src/mechanisms.ts` 负责读取与校验，`src/config.ts` 只保留**不是数值旋钮**的东西（设计分辨率、
世界投影、标定契约），因为那些改起来会牵动代码而不只是平衡。

### 关卡：`config/levels.json5`（手工配置刷怪）

**关卡不再是代码。** 一个关卡 = 一段水域 + 一张刷怪表，全在 [`config/levels.json5`](config/levels.json5) 里，
中文注释，和机制配置一样是 JSON5、一样**逐项校验并指名报错**。

**一块刷怪**（`spawns` 里的一项）说清楚四件事：

| 你要决定的 | 写什么 |
|---|---|
| 什么时候 | `at`：相机走过多少米（**按距离，不按时间**，所以改节奏不会让关卡错位） |
| 刷什么、几个 | `kind` + `count`。`kind` 可以是收集物、9 种生物、技能泡，或 4 种障碍物 |
| 怎么摆 | `arrange`：`single` / `line`（横排）/ `column`（竖列）/ `spread`（沿距离摊开，横向正弦摆动）/ `barrier`（留缺口的障碍横排） |
| 从哪边进来 | `from`：`top`（默认）/ `left` / `right` / `bottom`，见下 |

**从四边进场**是这一轮新加的。以前只有 `top`——内容在视野上方生成，随水流向下漂进画面。

- `left` / `right`：在**泳道外**生成，横向游进来，`depth` 决定它在屏幕哪个高度切入（0 = 下边缘，1 = 上边缘）。
  `arrange` 给出的 x 是它**进场后要去的位置**。水流仍在往下带，所以进场路线是斜的。
- `bottom`：在视野下方生成，以比水流更快的速度**向上**追，**一路升到和玩家齐平**才交回给它自己的 AI。
  这一条是必要的：这个游戏里所有东西相对玩家都在下沉，所以如果进场只到"看得见"就结束，它会露一下脸然后
  立刻掉回去。进场速度必须盖过 `scrollSpeed`，默认值（45 对 25）有余量。
- **只有生物和障碍物能从侧面/下方进来**：收集物和技能泡随水流下来，写在配置里会加载报错。
  **障碍物不能写 `bottom`**（布景不会自己往上游）；`left`/`right` 的障碍物会横着漂进来，
  **停在 `x` 指定的位置**（像被水冲过来的木箱），不会一路漂穿泳道。
- 每块可以覆盖 `enterSpeed`；默认值和"出生点在画面外多远""切入高度"这些手感数字在
  `config/mechanics.json5` 的 `spawning` 段，全关卡共用。

**例子**（`config/levels.json5` 里就有这三块，可以改也可以删）：

```json5
// 一小队鱼从左边游进来，散在 24 米里
{ at: 300, span: 24, count: 3, kind: 'fish', arrange: 'spread', from: 'left', depth: 0.68 },
// 从下面追上来的两条鱼：压力来自背后
{ at: 900, span: 18, count: 2, kind: 'fish', arrange: 'spread', x: 0.5, from: 'bottom' },
// 被水从右边冲进来的木箱，漂到泳道 0.72 处停下
{ at: 1010, kind: 'crate', x: 0.72, from: 'right', enterSpeed: 26 },
```

**加载器会拒绝的东西**（每条都会说出是哪一关、第几块、哪一项）：拼错的键名（否则那一项会被静默忽略，
看起来像游戏坏了）、从侧面进来的收集物、从下方进来的布景、把生物排成 `barrier`、
`at`/`kind` 缺失、以及**没有缺口的障碍横排**（那会让"要不要变瘦"不再是选择题）。
写错 `count` 之类的数字也不会静默：报错会告诉你它应该是什么范围。

**换关卡**改文件顶部的 `start`（那是**新玩家默认选中**的一关）；`levels` 数组里可以放多关。

### 关卡选择与进度（主菜单最上面一行）

关卡现在是**可选**的，而且**关卡顺序就是解锁顺序**：

- 菜单最上面一行是**关卡**，一关一格。三种状态：**选中**（填充）、**可选**（描边）、**锁着**（更暗更冷）。
- **第一关永远能玩**；第 N+1 关要**通关第 N 关**才解锁（`cleared` 里必须有前一关的 id）。
  这是**按顺序的规则**而不是"通关了几关"的计数：以后在文件中间插一关，规则依然正确，计数会错。
- **锁着的那一格按下去不会有反应**（连"按下"都不进），而且行下面那行字会说清楚：
  `通关「开阔水域」后解锁「暗礁水道」`。
- **通关 = 击败这一关的 BOSS**（不是活下来更久、也不是跑完距离）。解锁会**写在结算横幅上**（`新关卡解锁：暗礁水道`），
  因为一个只在菜单上悄悄变色的解锁，玩家根本不会注意到。
- 选择和解锁会**存进 `localStorage`**，key 是 **`tgba.progress.v1`**，内容是
  `{ cleared: ["..."], selected: "..." }`。

**关于存档**（这是这个项目里唯一会跨页面存活的东西）：

- **读的时候不信任它**：解析失败、形状不对、`cleared` 里出现**已经不存在**的关卡 id，全部丢弃。
  最坏的结果是"从头开始"，而不是"开机崩溃"。私有窗口里 `localStorage` 会抛异常，那种情况下游戏照常能玩，
  只是不记事。
- **可以重置**：`window.__GB.game.debugResetProgress()`（进度回到只剩第一关、选中文件里的 `start`），
  或者手工删掉那个 key。测试也靠这个钩子把阶梯重置到干净状态。
- **测试里**还有 `debugProgress()`（读）和 `debugClearLevel(id)` / `debugSelectLevel(id)`（写，
  走的是菜单用的同一条路径），所以不用真打两遍关卡才能测到解锁。

**还没做**：关卡选择只在主菜单上（关卡中途不能换，符合直觉）；星级/最好成绩**没有按关卡分开存**——
`最好 Xm` 目前是本次会话内的。要按关卡记录成绩，是给存档加两个字段的事，等你需要的时候说。

**这一轮同时把 `level.scrollSpeed` 从机制配置挪进了关卡**：节奏是**关卡的属性**（同一长度的两关应该允许
用不同节奏），所以它和 `scrollLength` 一起写在关卡里。

### 触屏控制：屏幕任意位置拖动

手机上**没有摇杆**：在**屏幕任意位置**（按钮以外）按下并拖动，气泡就按手指移动的方向和距离移动**同样的距离**——
手指在屏幕上移动 30px，气泡就在自己的位置上移动 30px。松手即停，没有惯性、没有加速。

这是**相对位移**，不是"气泡跟到手指下面"：手指可以按在离气泡很远的空白水面上，一边看着气泡一边操作，
手不挡视野。

配置在 `movement.drag` 段，有中文说明：`sensitivity`（位移倍率，1 = 严格 1:1）和 `penaltiesApply`
（成长阶段/吸附/减速这些速度惩罚要不要也乘进拖动距离，默认关——关着才是严格 1:1）。

### 积分（常驻在左上角）

屏幕**左上角常驻显示本局得分**（`分数 1234`，金色），每局从 0 开始；结算卡上给最终分数和本次会话的最佳得分。

**什么给分**（都在 `score` 段，键名就是事件名，**任何一项设成 0 就等于把这件事从积分里拿掉**，不会留下一串零）：

| 事件 | 默认 | 为什么给它分 |
|---|---|---|
| `drivenOff` | 25 | 把一条生物**打跑**（血打空）。这是枪的回报：不设分的话，开枪只是把水变空 |`n| `absorb` | 5 | **吸收一个收集物**。只有**不能靠吸收长大的类型**（普通气泡）会拿到：对会长大的类型，成长本身就是回报 |
| `skill` | 50 | **捡到特殊道具**（技能泡泡）。关卡里唯一的纯奖励，也是唯一要主动去够的拾取物 |
| `eaten` | 40 | **吞掉**一只生物。反转是招牌动作、也是最危险的那个（气泡会变大变慢），所以它给分 |
| `boss` | 1000 | **击败 BOSS**：一关的目标，整局最大的一笔，其它都是零钱 |

分数读数长什么样（位置、字号、颜色、不透明度）在 `hud.score` 段，也是设计像素。分数记的是**每个事件发生了多少次**（账本），总分按当前配置算出来——所以改一个数值，不会留下"一半按旧表算的总分"。

**得分会在原地飘字**：`+25` 出现在**得分发生的位置**（打跑鱼的地方、拾取到道具的地方），向上飘、渐隐、3 秒后消失。**所有参数都在 `score.popups` 段**（字体族除外，那是全局的 `text.fontFamily`）：

| 键 | 默认 | 管什么 |
|---|---|---|
| `lifeSeconds` | `3` | 活多久（就是你要的那个数） |
| `risePx` | `46` | 这段时间向**上**飘多少（设计像素） |
| `riseEase` | `1` | 上升曲线：`1` 匀速 · `0.6` 先窜后缓（街机手感）· `1.6` 先慢后快。**只改路径形状，不改总高度** |
| `size` | `16` | 字号（设计像素） |
| `colour` | 金色 | 颜色 |
| `alpha` | `1` | 基础不透明度（淡出是在这个值上再乘，`0.6` = 整体淡一点） |
| `weight` | `"bold"` | `"bold"` 或 `"normal"` |
| `prefix` | `"+"` | 数字前面加什么。`""` 就只显示数字 |
| `fadeFrom` | `0.45` | 前百分之多少的时间保持全亮，之后才淡出 |
| `fadeEase` | `1` | 渐隐曲线：`1` 线性 · `2` 亮到最后一下没 · `0.5` 一开始就明显变淡 |
| `anchorX` / `anchorY` | `0.5` / `0.5` | 事件位置落在飘字的哪个点上（`0` = 左/上边缘，`1` = 右/下边缘）。`0.5/0.5` 是以事件为中心；想让数字从事件**上方**冒出来，把 `anchorY` 设成 `1` |
| `max` | `24` | 同时在飞的上限，**护栏**不是预算：真到上限就退休最老的那个（玩家早读过了） |

**每一项都能在控制台里实时改**（`window.__GB.mechRef.score.popups`）：飘字是池化复用的，所以每一发都会重新套用样式（Pixi 的样式 setter 在值没变时会提前返回，所以常规情况只是几次比较），不会出现"改了一半标签还是旧样式"。

> **位置是"发生那一刻的屏幕位置"，不是世界坐标。** 两者看起来都行，实测才知道差别：水面以 25 m/s 往下走，3 秒里把屏幕上的东西往下带 85 像素，而飘字自己只往上飘 35 像素——**净结果是往下沉 33 像素**。一个往下沉的东西不叫"漂移"，而漂移才是让人看见它的原因。所以飘字挂在这一刻的位置上，然后一路向上。（左上角那个读数说的是"这局值多少"，说不出"刚刚这一下值多少"，这就是飘字存在的理由。）

**结算卡现在会换行**：以前它只跟着世界缩放，而"一行字能有多宽"和"一米占几个像素"没关系，所以往上加一条事实就会被屏幕两边切掉（玩家只看到自己成绩的中间一段）。现在 `hud.resultsCard.widthRatio` 给了它一个以屏幕为基准的换行宽度，超了就折行。

**最佳得分是"本次会话"的，不写进存档**——和 `bestClimbed` / `bestVolume` 一样，这是 `src/progress.ts` 里的明确决定：存档只存关卡解锁，分数是每局的事实。

### 触屏按钮：右侧一列

**所有动作按钮竖排在泳道最右边**，从下往上按"越常用越靠下"：技能/吸附（最下面，拇指最容易够到）、喷吐（或爆破）、消化（最上面，也是最小的一个）。

**为什么挤到一条边上**：移动是"任意位置拖动"，所以屏幕左边和中间整片都是干净的操控区——手指不用绕开按钮、也不会挡住气泡；按钮集中成一列，位置固定，闭着眼也能按。旧布局是左右两个角各放一组，等于把两个下角都花掉，玩家只能在中间那道缝里操作。

按钮的顺序**按类型也固定**：某个类型没有的按钮就空着那个位置，不会把别的按钮挤上来——所以"喷吐在中间"在任何一局里都成立，换个气泡不用重新记。

配置在 `touch` 段（半径、半径上限、离右边缘的距离、离底边距离、按钮间距，都是设计像素）和
`hud` 段（`bossBar` 是顶部那条 BOSS 血条的位置、宽度、颜色与字号；`score` 是左上角的分数）。**"离海面还有多少米"的水位管、那行文字、以及左边缘那列地标标签（鱼群 / 气泡潮 / 爆发）都删掉了**：距离不再是进度，而段落名关卡本来就会在事件发生的那一刻用横幅喊一次——屏幕边上一列常驻的段落名读起来像菜单，不像水里的景象。

**run 横幅（"射速升级 · 第 2 档"这类提示）是居中的、并且会换行**：它以前**根本没有定位过**（锚点在中心、坐标是画布原点），所以每条消息都有半条挂在屏幕左边缘外面——截图上那句被切掉一半的字就是这么来的。

> 顺带修掉一个**一直存在**的布局 bug：按钮尺寸原来是用 `viewport.scale`（世界缩放）算的，而横屏/矮窗口下这个数反而很大——915×412 的手机横屏算出 2.49 px/米，按钮半径变成 95px，整列被顶出屏幕（消化按钮的 y 是 −147）。现在和 HUD 一样用 `designScale(画布)`，并且是在 `TouchControls.layout` 内部自己算的：没有"传错的参数"这回事了。

**为什么不是"气泡跟着手指走"**（那是早先的做法）：跟手是把手指位置当作**目标位置**，于是手指必然挡住气泡——
拇指得待在目标位置上，玩家自己的手遮住了自己在操控的东西，而这个游戏的核心技能就是早点看见危险。
拖动保留了"手不挡视野"，同时因为是**相对位移**，力度也不再被浪费：移动多少就是多少。

**代价，说清楚**：既然"手指移动多少气泡就移动多少"，那"气泡越大越慢"就没法同时成立，所以
**成长阶段和吸附的速度惩罚默认不作用于触屏**（键盘不受影响）。想要那条张力，把 `penaltiesApply` 打开，
代价是不再严格 1:1。

**瞄准（喷吐 / 蓄力冲撞）跟着拖动方向走**：方向取的是"手指相对按下点的偏移"，所以慢慢拖也能保持一个明确
的朝向；手指松开、回到按下点，就回到默认的朝上。键盘那一套仍然是方向键 + 默认朝上。

### 气泡成长阶段的外观

**每个阶段一个对象**，在 `stages.appearance` 数组里，所有外观数值都在里面（含 alpha 和线宽）——
改一个阶段不用在多个平行数组之间数下标，加阶段就往数组末尾再塞一个对象。少于阶段数时最后一个会被复用。

| 键 | 管什么 |
|---|---|
| `radius` | 阶段越高气泡越大。**同时影响判定**——画多大就吃多大，两者走同一个函数 |
| `rim` / `rimAlpha` / `rimWidthRatio` | 轮廓。**色相的主要载体**，最饱和、接近不透明，余光里分辨阶段靠它。**想换颜色先改这里** |
| `glow` / `glowOuterAlpha` / `glowInnerAlpha` / `glow*RadiusRatio` | 外圈光晕。要**亮**，不要饱和——它以 1.18 倍半径压在气泡内部之上，亮度直接决定内部多亮 |
| `inner` / `innerAlpha` | 内部填充。只有 12% 不透明度，**接近白色**即可 |
| `innerRing` / `innerRingAlpha` / `innerRingWidthRatio` | 轮廓内侧的细环。**形状线索**：手机上白天看暖金和暖粉会混，一圈和两圈不会混。想让**更多阶段**靠形状区分，就把它改成"环的数量" |
| `sheen` / `sheenAlpha`、`specular` / `specularAlpha` | 内高光和镜面高光点 |
| `hudColor` | HUD 上阶段标签的颜色。要**在深色 HUD 上**看得清，和 `rim` 的背景不同，不能混用 |
| `name` | 阶段中文名 |

**内部为什么几乎透明**：五个半透明浅色层（两次光晕、填充、内高光、镜面高光）叠在一起会趋近白色，
在深色水上就是**中性灰**——阶段色相恰好在玩家最常看的地方被平均掉了。所以内部保留水的深色，
色相交给天生不透明的轮廓和光晕承担。

实测三个阶段画出半径 17.5 / 32.3 / 42.0 px，轮廓色 `#d8fbff` / `#ffcf6b` / `#ff8fbe`。

颜色两种写法都认：JSON5 十六进制字面量 `0x9fe4ff`，或取色器给的 `"#9fe4ff"` 字符串。

### 弹幕：逼你不断移动

默认节奏是"躲开"，但如果危险只会慢慢飘过来，站着不动就是最优解。所以要有**主动压过来**的威胁：

**冲锋（`charges` 段）**：`chargers` 表里的生物进入自己的 `triggerMeters` 就会**蓄势**——把自己将要走的**整条曲线**画出来（落点上还有一个环）——然后沿这条**固定曲线**一头撞过来。**每种生物一行**（和敌方子弹的 `shooters` 一样的约定），所以不同生物可以有不同方向的冲锋：

| | 小鱼 `fish` | 水母 `jelly`（碰到还会**减速 + 掉血**） |
|---|---|---|
| 路径 | 从它现在的位置直接俯冲，弯 0.3 | 从它现在的位置甩出一条大弧（弯 **0.85**），所以看起来是横扫过来 |
| `triggerMeters` | 300 | 320 |
| `telegraphSeconds` | 0.75 | 0.95（它的弯更大，需要更多时间让人读出"它要绕哪边"） |
| `travelSeconds` | 0.55 | 0.6 |
| `bowRatio` | 0.3（弯一点，逼你读方向） | 0.85（甩出去再扫回来） |
| `cooldownSeconds` | 2.2 | 2.8 |

`telegraphColour` / `telegraphAlpha` / `trailColour` / `trailAlpha` 是所有冲锋共用的外观：预警曲线（蓄势时脉动，所以静止的线读起来是倒计时）和冲刺拖尾。

> **为什么是固定曲线，而不是追踪**：曲线在**蓄势开始那一刻就定死**，瞄准的是"那一刻的你"，之后**永不修正**。这是"有规律的弹幕"和"不公平的追踪攻击"之间的区别——玩家永远只需要做一件事：在窗口里**挪开**。`bowRatio` 的理由也是公平性：直线冲锋看一眼就知道往旁边站，弯过来的必须读出它**弯向哪边**，"往哪躲"于是从条件反射变成一次判断。
>
> **公平性的一半是可见性**：曲线和落点环在蓄势期间就画在屏幕上，玩家不用背板也不用猜。水母也一样：它的弧线在蓄势期间就画出来了。

实测（412×915，玩家体积 1.8 所以吃不了鱼）：站着不动 → **被撞中 1 次**；蓄势期间横向挪开四分之一个泳道 → **0 次**。同一条鱼两次冲锋的间隔 **3.49 秒**，正好是 `cooldownSeconds + telegraphSeconds + travelSeconds`（2.2+0.75+0.55 = 3.5）。冲锋路径距"起点—终点"直线最远 **33 米**（227 米冲锋的 15%，即 `bowRatio` 的一半，与二次贝塞尔的性质一致）。水母的冲锋实测：起点与它**自己身体的当前位置重合**（相差 2 米，就是起跳那一帧的漂移），蓄势期间位移 **0 米**——它不再"先走到某个位置再跳"，而是**原地起跳**，弧线完全由 `bowRatio` 提供（实测偏离弦 15% ≈ 0.85 的一半）。

**爆炸会抖屏**（`hazards.bombfish.blastShakePixels` / `blastShakeSeconds`，默认 7px / 0.3 秒）：抖的是**整个画面**（连 HUD 一起），因为这不是"水在晃"而是"这一下打在你身上"；幅度刻意小，抖屏期间玩家还得躲下一颗子弹。实测舞台位移峰值约 4px（配置 7 × designScale 0.76 = 5.3px 振幅，采样间隔导致的低估），结束后精确回到 (0, 0)。

**② 敌方子弹（`enemyBullets` 段）**：`shooters` 里列出的生物会**瞄准你开火**。默认是电鳗（射电，108 m/s）和**海胆（尖刺，181 m/s —— 全场最快）**——**不在表里的生物就是不开枪**（不是用默认值：一个因为漏写配置而开始开枪的生物，是一次没人做过的难度改动）。水母曾经在表里，现在不在：它改成从侧面冲锋了（见下）。

| 键 | 默认 | 管什么 |
|---|---|---|
| `shooters` | 电鳗 / 海胆 | 每种会开枪的生物一行：`perSecond`（每秒几发）、`speedPerSecond`（速度，**泳道宽/秒**）、`spread` + `spreadRadians`（一次几发、扇形夹角）、`damage`（扣几个命中点）、`shape`（`bolt` 普通弹丸 / `spike` 尖刺） |
| `rangeMeters` | `420` | 只在这个距离内开火，所以子弹**永远不会从你看不见的地方飞过来**；超出时扳机是**按住**而不是攒着 |
| `radiusRatio` | `0.016` | 子弹半径（相对泳道宽） |
| `lifeSeconds` | `7` | 存活秒数 |
| `coreColour` / `rimColour` / `rimAlpha` | 暖金 / 橙红 | 外观：亮芯 + 暖色外圈，和玩家那串冷色小泡泡在余光里不会混 |

> **公平性靠三件事，而且三件都是配置**：瞄的是**开火那一刻的你**（之后不修正）；速度是**泳道宽/秒**，默认 0.22~0.3，比你横穿泳道的 2 秒慢得多，所以"躲得开"在物理上永远成立；只在 `rangeMeters` 内开火。**弹幕的难度全在这三个数上**——嫌凶就调 `perSecond`，嫌烦就把某一行删掉。

**子弹会被障碍物挡住**（和玩家的子弹同一条规则：看得见的木箱就该挡住子弹），所以布景对双方都是掩体。命中走的是**同一个 `takeHit`**，没有第二条伤害路径；同一帧里的多发会被无敌帧合并，这是有意的保护。

实测：静止不动站 5 秒 → 电鳗打中 **4 次**、体积正好掉 **0.8**（4 × `volume.hitCost` 0.2）；中间放一个木箱 → 只中 **1 发**（掩体是"挡住大部分"，不是"绝对安全"）；**一直横向走** → **0 次**。三种生物的射速实测 0.76 / 1.3 / 0.6 组每秒，和配置的 0.7 / 1.1 / 0.45 一致（多出来的是测试生成的第一次立即开火）。

### 吞噬：食物链反转

**刚才还要躲开的东西，变大后可以回头一口吃掉。**

判定是**双向**的，这是它好玩的原因：

- 体积**够** → 你撞上去，它被你吃掉，你变大
- 体积**不够** → 同一只、同一次碰撞，但结果是它伤害你

所以同一只水母在关卡前半段是威胁、后半段是补给，而**分界线由玩家自己吃出来**——没有任何东西被
脚本改成"现在可以吃了"，是世界对玩家的意义变了。

配置在 `consumption` 段：

| 键 | 管什么 |
|---|---|
| `tierVolume` | **体积档位阶梯**。下标就是档位，值是进入该档所需的体积。默认 5 档（微型/小型/中型/大型/巨型） |
| `edibleAtTier` | 每种危险物从第几档开始可吃。调高 = 威胁期更长 |
| `mass` | 每种危险物吃下去值多少体积 |
| `massEfficiency` | 消化损耗。小于 1 表示吃危险物得到的比它自身轻，于是不能靠它无限膨胀 |
| `marker` | 可吞噬标记的颜色/线宽/不透明度 |

**为什么档位阶梯是独立的、而不是复用成长阶段**：成长阶段按**吸收个数**晋升，体积按每颗的大小累加，
两者不是同一个量——体积反推不出阶段。第一版就是用吸收个数当体积阈值，结果长到阶段2 的玩家体积只有
2.3、却要 13 才算"第2档"，**永远吃不到鱼**。

**标记用的是独立的一套视觉语言**：阶段色（青/金/粉）继续说"我是第几阶段"，可吞噬标记是画在危险物
**自己**身上的金色光环，说"这个是食物"。两者互不覆盖。默认只画"可吞"这一半，因为那是玩家**行动所需**
的信息；`marker.showBlocked` 打开后会额外画红色硬边表示"不可吞"。

判定规则只有一处实现（`src/consumption.ts`），**碰撞和标记问的是同一个函数**——如果两者不一致，
标记承诺是食物而碰撞给了一下伤害，那会是这个机制最糟的 bug，因为它惩罚玩家相信看到的东西。

### 吸附（长按产生吸力）

**长按右侧最下面那个按钮**（技能/吸附，一钮两用）产生吸力，把范围内的物体拉向自己。松开即停。

这是**同一个按钮**兼作技能钮：**点击=使用技能**（离散动作），**按住=吸附场**（持续状态）。不拆成两个按钮，因为拇指够得着的角落只有一个，而这两件事不会同时想要。图形上靠形状区分：外环是吸附场，内里的星形是技能（没技能时星形不画，于是"我有没有东西可花"不用看 HUD 就知道）。

配置在 `suction` 段，全部有中文说明：

| 键 | 管什么 |
|---|---|
| `radiusRatio` / `radiusPerVolume` / `maxRadiusRatio` | 吸附半径随体积增长（体积越大吸得越远） |
| `pullPerSecond` | 拉动速度 |
| `heavyRatio` / `heavyFloor` | 按**目标质量 / 玩家质量**衰减。≤1 全速，≥`heavyRatio` 只剩 `heavyFloor` |
| `moveSpeedFactor` | 吸附期间玩家速度倍率（**这是这个机制唯一的代价**） |
| `fieldColor` / `fieldAlpha` / `fieldWidthRatio` | 吸附场的视觉 |
| `tetherAlpha` / `tetherWidthRatio` | 预留给"吸附轨迹"连线 |

**关键设计：吸附只负责拉近，不负责吃。** 拉到位之后仍然走食物链档位判定——所以把一只你吃不了的螃蟹吸过来，等于**加速把危险物拉到自己脸上**。加上吸附期间减速，两重代价合起来才让"什么时候按住"变成真正的决策，而不是白送的加宽嘴巴。

**为什么按相对质量衰减**：同一个浮游生物，在你小的时候很重、在你巨大的时候微不足道——于是吸附能力**自动随玩家成长**，不需要第二套成长系统。

实测：玩家体积 1 时，质量 0.16 的收集物被拉近 0.57，质量 4.84 的只被拉近 0.12（**4.9 倍差距**）。

### 修复：路径串挤成一堆 / 路径上的敌人不再冲锋 / 去掉随深度变强的环境音

**① 一串里的守卫改成"沿着曲线排开"，而不是"先后出发"。** 之前靠时间线的 `staggerMeters` 让它们先后进场——同一帧进场的成员（传送过去、卷动很快时）会**完全叠在一起**，而且每个成员的曲线是**锚在自己出生点**上的，所以六条鱼其实是同一个形状画了六遍：实测横向铺开 **0 泳道**、纵向 **0 米**，就是一坨。

现在两处一起改：曲线锚在**摄像机**上（同一条屏上形状，大家穿过同一个地方），并且每个成员按**序号**在曲线上占据 `pathOffset = i / n` 的位置而不是靠出生时刻错开。实测同屏 8 条：横向铺开 **1.38 泳道宽**、纵向 **454 米** ✓ —— 一条一条，不再重叠。

**② 路径上的敌人只开枪，不冲锋。** 冲锋是一条**瞄准玩家的固定曲线**，而路径是**关卡作者指定的固定曲线**；两者同时生效，意味着玩家一靠近，编排好的形状就当场被放弃——本该横扫过屏幕的一串鱼改成掉头俯冲。枪保留（一边游一边打仍然是关卡要的形状 + 压力），冲锋关掉（`const charger = h.path ? undefined : ...`）。实测同屏 8 条路径鱼：`charging: 0` ✓

**③ 环境噪声床改成固定音量**（`audio.ambientVolume`，默认 0.35）。它以前**跟着深度变强**——越往上越响越亮，听起来像游戏自己在加大音量，而不是像海。你要的是"保留质感、不要上升"，这也确实是它该有的形状：**水下的声音是关卡的属性，不是气泡爬了多高的属性**，所以它由配置设一次，而不是每帧重新送一遍新数值。实测：起点与爬升到最后，`ambient 0.217 / noise 0.315` 完全不变 ✓，改配置即改音量 ✓。被否掉的 `setDepth` 留在 `src/audio.ts` 里不调用。 那是一层随深度上升的合成噪声床，问题正如它听起来那样：**越深越响**，而降下来的办法只有主音量（会把音效一起压小）。现在气氛交给每关自己的音乐（上一条新增的），一件事做完就够了。`audio.setDepth` 与音床本身留在 `src/audio.ts` 里不再调用——一次失败实验删掉比争论便宜，真觉得太静，一行就能接回来。

### 路径点（spline）：一串敌人沿同一条曲线游过屏幕

关卡里新增 `paths` 表，刷怪块用 `path: '名字'` 把它的 `count` 个敌人放到同一条曲线上——**依次出发**，于是就成了"一串鱼"：

```json5
paths: {
  weave: {
    points: [
      { x: 1.25, y: 40 },   // 屏幕右侧外面
      { x: 0.78, y: -70 },  // 进来、下沉
      { x: 0.45, y: 90 },   // 再上扬
      { x: 0.16, y: -60 },
      { x: -0.3, y: 30 }    // 从左侧出去
    ],
    seconds: 7.5,           // 走完整条曲线要多久
    staggerMeters: 26       // 同一串里相邻两条的间隔 —— 它才是"一串"的来源
  }
},
// 时间线里：
{ at: 400, kind: 'fish', count: 6, path: 'weave', x: 1 }
```

**坐标是两种不同的东西，这是刻意的**：`x` 是**屏幕坐标**（泳道比例，<0 / >1 就是屏幕外——"从右边进、从左边出"是关于屏幕的陈述），`y` 是**相对出生点的高度**（关于关卡，唯一有意义的原点是它进场的地方）。

曲线是**穿过**路径点的 Catmull-Rom spline，不是 Bézier：作者写"从这里过一下"就是要真的从那里过，而 Bézier 只会被拉近。世界仍在往下卷，所以同一条路径在不同卷动速度下会呈现不同斜度，不必重画。

实测（第一关 `weave`，6 条鱼）：**从右侧 1.21 泳道宽处进场** ✓、横向走到 **−0.05** 并从左边出去 ✓、过程中在 **280m** 的高度范围内上下摆动 ✓ —— 就是"从屏幕右侧出现一串鱼依次上下游动、最后从左侧游出"。

修了两个实现上的坑，都记在提交信息里：路径的 x 一开始被**加在出生点上**（于是 x=1.25 变成 2.25 泳道宽，鱼永远进不来），以及普通生物的**泳道夹紧**把路径的两端钉在了泳道边缘（于是"从屏幕外进来"变成了"贴着右边墙出现"）。

### 修复：过期结算卡 + 结算界面按钮"没反应" + 出场改成从下方飞入

**① 上一关的结算卡留在屏幕上**：结算卡（`finishBanner`）以前只在 `burst` 阶段淡出，所以只要新一关是从别的阶段开始的，它就**一直挂在画面上**（截图里那个"破裂 · 深度 1404m / 得分 125"就是很早以前那次死亡留下的，和当时 HUD 上的 2955 分完全对不上）。现在只有"真正结束这一局的 burst"才配得上这张卡，其它任何阶段都直接清空（透明度 + 文字），`startRun` 也一并清掉——**一个过期的分数浮在活着的关卡上，比没有卡更糟**。

**② 结算界面的【返回主菜单】"没反应"**：按钮其实**生效了**——菜单已经在面板**后面**显示出来了，只是面板没关，所以屏幕上看起来一模一样。现在 `exitToMenu` 会先把结算面板收掉：**只有一个按钮的面板，按下它就必须离开**。

**③ 出场改成"从屏幕底部飞上来"**：以前每关开头是气泡**从小到大膨胀**出来（意思是"一个新气泡诞生了"）。但这一局现在是**上一关飞出屏幕顶部**结束的，所以对应的入场就是同一个动作的逆放：气泡**从屏幕下边缘下方升起**，缓动减速、停在正常位置（`INTRO_START_SCREEN_Y = -0.18` → `0.5`，1.6 秒，期间不可操作）。膨胀的那段缩放去掉了——气泡本来就是这个大小。

实测：`screenY` 从 **-0.18** 升到 **0.5** ✓；死亡后重开，卡片被清空 ✓；结算界面按下按钮 → 阶段 `menu`、面板 `isOpen: false` ✓

### 通关流程：继承强化、过关演出、最终结算

**① 武器强化跨关继承**：枪的**排数**和**射速档位**现在是**这一局**的东西，和分数一样——走关带着走，死亡重来才清零。以前每次 `startRun` 都重置，这在"一局就是一关"时是对的；现在走进下一关是同一次下潜的继续，拿走玩家刚用来通关的强化等于**惩罚他通关**。

**② 攻克 BOSS 的演出改成了"赢的样子"**（以前和死亡长得一模一样：破裂 + 白闪 + 结算卡）：

```
playing → cleared → ascend → intro（下一关）
```

- **cleared**：气泡**停住不动**、**无法操作**（除了 `playing`，没有任何阶段接受输入），同时播放一段**过关音乐**（`audio.clearSting`：大调上行琶音 do-mi-sol-do）。音乐长度从演奏用的同一组数字算出来，所以"音乐播完"和"气泡起飞"不可能各说各话。
- **ascend**：气泡**向上飞出屏幕**。这一段的上升走的是玩家的**屏幕比例**而不是世界坐标——`player.y` 每帧由摄像机推出来，直接写 y 会被覆盖（实测 600m 的爬升只画出 11m）。实测现在 `screenY` 到 **1.14**（越过屏幕顶边）、世界高度上升 **510m**，确实飞出去了。
- 飞出之后才切关（或进入结算）。

**③ 六关通关后展示结算界面**（`src/summary.ts` + `summary` 配置段）：面板显示**本轮总得分**（一个数字，最大字号）、通关数、用时、最佳得分/新纪录、构建号，以及一个**返回主菜单**按钮（唯一一个按钮，因为只剩这一件事）。它自己处理指针（全屏面板如果让点击穿到水里，会去操控一个看不见的气泡），遮罩 0.86 把水和 HUD 压下去。

实测：第一关带 2 排枪 + 第 2 档射速通关 → 进入第二关后**仍是 2 排 / 第 2 档** ✓、分数 200 → 1200 ✓、阶段序列 `playing → cleared → ascend → intro` ✓；打通第六关 → 阶段 `summary`、面板打开、总分 1100 ✓

### 击中闪白（`hazards.hitFlash`）

子弹打中**任何**敌人，它都会闪一下白：`{ seconds: 0.14, colour: 0xffffff, alpha: 0.85, radiusScale: 1.1 }`。

**为什么这是必须的**：以前**只有 BOSS 会闪**，普通小鱼小虾打上去只有血量的变化——而血量在画面上看不见。于是"我到底打到了吗"这个问题**没有答案**。闪白就是那个答案，而且它必须**每个敌人都有**，否则玩家学到的是"有些敌人打上去没反应"。

**画法是在敌人画完之后盖一层白色椭圆**，而不是改每一种敌人的颜色：

- **一处生效**、六种敌人一致；
- **不会漏掉以后新增的种类**（这是它比"在每个分支里各写一行"更重要的理由——BOSS 早就自己有闪白，同一个主意已经有三种实现方式了）；
- 透明度乘以"还剩多少时间"，所以长闪读作**淡出**而不是一块卡住的白斑。

同时把时长从 `boss.hitFlashSeconds` 挪到 `hazards.hitFlash`：设置闪白的地方只有一个（子弹命中的那一处），但用的却是 BOSS 的配置——这就是"只有 BOSS 会闪"的全部原因。

实测：对小鱼走**真实的伤害路径**（`hazards.hit`）→ `hitFlash` 从 0 变 0.14 ✓，截图里整条鱼变白 ✓

```json5
"bullets": {
  "image": "玩家子弹",   // src/assets/ 下的文件名，不写扩展名；空 = 代码画的小圆点
  "imageAlpha": 1, "imageTint": 0xffffff, "imageScale": 1

```

**和气泡同一条路，但按"池"而不是"一个"**：子弹一屏几十发、每发只活零点几秒，所以**按槽位复用精灵**（子弹没有 id，也不需要——它们彼此没有区别），池子永远不会超过屏幕上的发数。气泡那两个坑都提前避开了：先 `await image.decode()`（0 宽纹理会让 `width =` 除爆 ✗）、Y 轴反向抵消世界翻转 ✗。

### 玩家气泡的旋转（`playerBubble.imageRotation`）

**你看到的"转反了"不是贴图的问题，是坐标系的问题**：世界是**上下翻转**画的（世界 +y 向上、屏幕 +y 向下），所以放进世界容器的贴图默认是**镜像**的——代码画的气泡上下对称，谁也看不出来；换成有高光的图，一眼就看出来是倒的。

代码现在**自动抵消**那个翻转（`worldYIsFlipped` 沿父链把 Y 缩放乘起来判断，而不是只看直接父节点——第一版就只看了一层，结果对一个明显翻转的精灵报了"没翻转"），所以：

- **`imageRotation: 0` = 你的图保持原样朝上**（如上图：高光在上，正确）；
- 图上如果有别的朝向需求，`imageRotation` 就是**贴图自身的角度**（度，顺时针为正），正值转、负值回。

`imageScale` 也会一起复原——我上一轮打补丁时**误把你调好的 1.5 覆盖回 1**，已经改回 **1.5** 了。

### （历史）玩家气泡的贴图（已打开）

`playerBubble.image: "玩家气泡"` —— 图片在 `src/assets/玩家气泡.png`。**两个 bug 造成的"巨大气泡"**，都不是尺寸算错：

1. **`Texture.from()` 在图片尺寸已知之前给的是 0 宽纹理**，而下一行 `sprite.width = size` 正好是**除以它** → 缩放爆炸，512 宽的图被放大到铺满半个屏幕（截图里那些**方块状像素边**就是"小图被放大到离谱"的指纹）。现在先 `await image.decode()` 再建纹理，并且**用 `scale` 而不是 `width`**。
2. **每帧都新建了一个精灵**：判断条件用的是"精灵是否存在"，而它在图片加载完成前一直是 null → 加载期间每一帧都再起一次加载、再 add 一个精灵；其中在摄像机还没就位时被定位过的那些**永远留在了屏幕上**，就是左边那个巨大的泡泡。现在用一个 **pending 标志**保证"一个文件名，一个精灵"。

教训写在代码注释里：**当测量和屏幕互相矛盾时，屏幕是对的，测量是在量别的东西**。上一轮我量到的是"最后赋值的那个精灵"（尺寸正确），而屏幕上那个巨大的根本不是它。

实测（按你的窗口尺寸 967×1322）：贴图屏幕宽 **121px**、画出来的气泡 **125px**（差值就是原来那圈光晕），**中心 x 都是 376** ✓ 上图确认巨大泡泡消失 ✓

### 图片资源怎么管（换成中文名，手动替换即可）

**放哪儿**：`src/assets/levels/`，文件名用**中文**，按关卡命名：

```
src/assets/levels/黑烟囱墓场-最远景.jpg
```

**怎么引用**：关卡文件里写**文件名本身**（不是路径）：

```json5
// config/levels.json5 → levels["black-smokers"]
backdrop: { image: '黑烟囱墓场-最远景.jpg', speedFactor: 0.03, heightScreens: 1.15, alpha: 0.62, tint: 0x8f6a7a }
```

**怎么换图**：把同名文件覆盖掉就行——**不用改代码、不用改配置**。开发时刷新页面即可；名字打错或没有这个文件时，控制台会**列出所有可用的文件名**，不会静默失败。

**为什么不是 `public/`**：一开始放在 `public/levels/` 用路径引用，结果 `Assets.load` 报 `InvalidStateError: The source image could not be decoded`——而那张图用 `<img>` 加载同样的 URL 也失败，**请求还是 200**。也就是说"200 + 解码失败"这个组合把人往"文件坏了"的方向带，实际是**非 ASCII 路径**的问题。

改成 `import.meta.glob` 静态导入之后从根上解决：图片在**构建时**被读入，产出**ASCII 哈希名 + 正确的 content-type**，而配置里保留**你认识的那个名字**。dev 与线上都实测 `loaded: true` ✓（构建产物：`黑烟囱墓场-最远景-BjCiyhNL.jpg`）。

（顺便把失败原因**报出来**而不是吞掉：这是给人手动换的文件，`loaded: false` 必须能看出是哪张图、为什么。）

### 最远景改到**水后面**，水暂时全部隐藏

按你的判断改了图层：**图在水后面**（`WorldLayer.root` 的第一个孩子 → `backdrop → gradient → margins → world`）。要让这一点成立，图必须是**屏幕坐标**——因为水体渐变是一个屏幕空间的填充，世界坐标的精灵会被摄像机变换、从它下面滑出去。所以图现在按**像素**定尺寸，滚动也是 `scrolled × speedFactor × 像素每米` 换算一次。

另外加了一张**同样的图偏移一整个图高**：单张图盖不住窗口——绕回会把它的上边缘扫过整整一个图高，一个循环里总有一段时间窗口越过了它的下边缘。两张就永远盖满。

**第一关的水现在 `waterAlpha: 0`（完全隐藏）**，先让你单独看这张图。看够了把它改回去就行：

- `waterAlpha: 0.35` → 水是很淡的一层雾，图主导；
- `waterAlpha: 0.6` → 水明显，图是暗处的背景（上一版的样子）；
- `waterAlpha: 1` → 完全不透明，图看不见（最初的 bug 状态）。

### 第一关的水色改成"薄雾"（不再遮住背景）

`palette.waterAlpha`（新键，0..1，默认 1 = 和以前一样完全不透明）：水体渐变现在按这个不透明度绘制，**低于 1 时它是一层水色薄雾，而不是一块不透明色板**——最远景那张海底火山图就能透出来。第一关设 **0.62**，同时把这层暗红的 `tintStrength` 从 0.22 降到 **0.14**（"过渡颜色太明显"主要是它）。其它关没有手绘图，保持默认 1，观感不变。

**为什么这才是对的形状**：图是画在**水里**的，不是画在水后面——所以"水盖住图"不是图层顺序问题，而是水的**不透明度**问题。

### 第一关的最远景：一张手绘海底火山图

`levels["black-smokers"].backdrop`：

```json5
backdrop: {
  image: 'levels/black-smokers-backdrop.jpg',  // public/ 下
  speedFactor: 0.03,   // 每米卷动移动多少（最远的一层几乎不动）
  heightScreens: 1.15, // 画多高（屏高），>1 才能无缝绕回
  alpha: 0.62,         // 叠在水体渐变上的不透明度
  tint: 0x8f6a7a       // 乘进去的颜色：让它落在这一关的黑/暗红里
}
```

这是全项目**唯一一个"图片才是对的答案"**的地方：一关的环境是一件**美术品**（海床上的火山脊），再多的程序化微粒也说不出这件事。按关卡给，理由和 `palette` 一样——六关是六个地方。

**图层顺序**：水体渐变（水）→ **这张图**（水里的远处）→ 视差微粒（镜头和那个远处之间的水）。图必须在渐变**之上**，否则被不透明的水盖住，就是一张没人看得见的背景。

**原图 4 MB，导入时压到了 65 KB**（1080 宽、JPEG q84、渐进式）——手机加载 4 MB 的背景图是实打实的代价。想要原图分辨率就把 `public/levels/` 里的文件换掉，配置不用动。

顺带修了 `vite.config.ts` 的 watcher：把 `public/levels/**` 加进忽略列表——**盯着一个几 MB 的文件正是刚才 dev server EBUSY 崩掉的原因**。

### 视差滚动：四层背景微粒

`background.layers` 四行，**由远到近**（绘制顺序也是这个顺序，第一行在最底层）：每行一个 `speedFactor`（关卡自身卷动的倍数）、`count`、`sizeRatio`、`colour`、`alpha`。

| 层 | speedFactor | 数量 | 说明 |
|---|---|---|---|
| 最远 | 0.08 | 90 | 几乎不动、最小最暗 —— 远处的悬浮物 |
| 远 | 0.22 | 70 | |
| 中 | 0.5 | 46 | |
| 近 | 1.0 | 26 | 跟着世界走，最大最亮；也最容易被误认成敌人，所以最稀 |

**为什么是四层而不是一层**：原来只有一层海雪，单一速度看起来就是**一堵会飘的点墙**，摄像机从旁边滑过去。四层四种速度才是空间——眼睛读的是**层与层之间的速度差**，那才是距离——场景里其它东西都不用动，"这片水有多深"就已经说出来了。

速度是关卡的**倍数**，所以卷动更快的关卡四层一起更快，而**相对运动**（眼睛真正读的东西）不变；最近那层是 1.0，其它三层靠它定位。每层自成一个 `tileScreens` 屏高的纵向带，微粒按世界米摆一次，层的位置 = `scrolled × speedFactor`（**不是累加器**——所以传送、卡帧都不会把它抹开或卡住），超出可见带的按带高绕回，有限的粒子覆盖无限的上浮。

实测：`scrolled` 从 200m 走到 600m（即 400m），四层分别移动 **32 / 88 / 200 / 398 米**，正好是 `400 × speedFactor` ✓ 由远到近递增 ✓；粒子数量与外观全在配置里 ✓

### 修复：BOSS 的一切都挂在"玩家在哪"上（"第二关的 BOSS 又没有出现"）

这是上一个修复的另一半，而且更根本：BOSS 的**出现位置和悬停位置都相对于玩家**。

- 入场点原来是 `玩家.y + 可见深度 × 0.62`。只有玩家贴着摄像机时这才等于"从画面上方进来"。**第二关的通道很窄、还有撞不碎的封路木箱**——被挡住的玩家会被水流甩在摄像机下面，这时按玩家算出来的入场点就在画面**下方很远**，生成后立刻被清理掉，谁也没看见。
- 悬停高度也按玩家算，同样的问题：玩家掉在后面，BOSS 就悬在**他**头上，而不是在打斗发生的地方。

现在两处都以**摄像机/可见带**为准：

- **入场**从可见带顶部上方 42% 处进来（`camera.y + band × 0.42`），不再看玩家在哪；
- **悬停**仍然以玩家为基准算出一个舒适距离（`holdBandRatio` / `holdMinMeters` / `holdMeters`），但最后**夹进可见带里**（上下各留 8% 边距）。

一句话：**"存在但不在屏幕上"和"不存在"对玩家是同一件事**，而关卡只有打死它才结束——所以它永远必须在屏内。

实测（第二关，且每帧把玩家强行拖到摄像机下方 400m，模拟被卡住）：

| 窗口 | 可见深度 | BOSS 相对摄像机 | 在屏内？ |
|---|---|---|---|
| 412×915 | 802 m | −18 m | ✓ |
| 1280×720 | 289 m | +47 m | ✓ |
| **1600×420**（极扁） | **168 m** | +52 m | ✓ |

### 修复：宽窗口下 BOSS 悬在画面外（"第一关的 BOSS 没有出现"）

BOSS 的悬停高度原来是一个**绝对值 330m**。手机上可见深度约 802m，330 稳稳在屏内——所以我按手机尺寸做的每一次验证都通过了；但**窗口越宽越扁，可见深度越小**：

| 窗口 | 可见深度 | BOSS 悬停高度 | 屏幕上半高 | 在屏内？ |
|---|---|---|---|---|
| 412×915 | 802 m | 330 m | 401 m | ✓ |
| **1280×720** | **289 m** | 285 m | **144 m** | **✗ 跑到屏幕上方** |
| 900×600 | 241 m | 260 m | 120 m | ✗ |

BOSS 悬在画面外，玩家永远看不到它；而这一关只有打死它才结束——所以表现就是"BOSS 没有出现"。

现在高度由**可见深度**推出来：`holdMeters`（330）是**上限**，实际 = 可见深度 × `holdBandRatio`（0.34），再夹到 `holdMinMeters`（90）之上。上限防止大屏上离得太远，比例是"必须在屏内"那条，下限防止扁窗口把它塞到脸上。

实测（同一套探针，三个窗口重跑）：**802m → 286m**、**289m → 112m**、**241m → 95m**，三个都 `onScreen: true` ✓

### 一局跨六关：进度图 + 分数继承 + 自动进入下一关

击败一关的 BOSS 之后，这一局**不会**停在结算卡上：如果还有下一关，玩家带着**分数**直接走进下一关；只有**最后一关**才是这一局的终点（结算卡只在那里出现）。

- **分数继承**：`startRun(carryScore)` —— 死亡重来是 0，走关是带着走。分数是一局的总账，停在 0 就永远说不出"这一趟下潜走得怎么样"。（飘字仍然会清空：上一关留下的 `+25` 浮在这一关上是没有事件支撑的数字。）
- **自动进入下一关**：BOSS 死亡的收尾动画播完后交接（不是立刻切，否则胜利横幅还挂在屏幕上人已经在新关卡里了）。切关走的是菜单用的同一个 `selectLevel`，所以"通关走过去"和"从菜单点进去"是同一件事。
- **总进度图**（`hud.progressChart`）：屏幕右上角一行**六颗小圆点**，通一关点亮一颗，当前那关套一个金圈，下面一行"总进度 N/6"。它回答的是"**这一局**走到哪了"——和 BOSS 血条回答的"这一关走到哪了"是两个不同的事实，所以两个一起显示：BOSS 死的那一刻，一个变、一个归零。
  - 它画的是**本局**清关数，不是存档里的解锁列表：存档是"这辈子通过哪些"，一局只有一次下潜，用存档画会在你还没到第三关时就画满。

实测：第 1 关 0/6、分数 0 → 打死烟囱蟹王 → **自动进入沉船幽谷**、进度变成 **1/6**、分数 **1000（继承）**、横幅写着「第 2 关 · 沉船幽谷 · 分数继承 1000」 ✓

### 主菜单的关卡选择会换行

关卡药丸**按行排列**：一行的数量由 `menu.levelMinWidthRatio`（默认 0.3 = 一行 3 颗）决定，放不下就换到下一行、每行居中，说明行始终贴**最后一行**下面。

这是修一个真实的 bug：以前是**一行均分**，三关时看着正常，六关时每颗药丸只有自己名字三分之一宽，**六个名字叠在一起**。关卡行本身是一次**选择**，读不出名字的按钮就不是选择。

### 作弊：无限血量

设置面板里新增了 **作弊 / CHEATS** 一节，目前只有一项：**无限血量**（默认关）。开着的时候：

- 任何**命中**（碰撞、敌人子弹、爆炸）都**完全不发生**——不是"掉血之后补回来"，而是连受击音效、闪白、统计都不产生（`takeHit` 直接返回）。所以无敌的气泡和"从来没被碰到过"在任何可观察的层面都一样。
- **持续掉血**（垃圾袋的吸、海胆的放血）也走同一条路，所以也会被挡掉。
- **过饱爆炸**（`punishOverload`）是第三条死法，同样被挡住——只挡碰撞的作弊会让玩家"吃太多把自己弄死"。

它是**会话内**的开关、不写 `localStorage`：和音量同一个待遇，而且"重载后仍然开着"的作弊正是有人会忘记关掉的那种。实测：默认关 ✓；打开后把一条鱼按在气泡上 4 秒 → **存活**、`hits` 统计 **0**、关卡没有结束 ✓；再关掉 → 同一条鱼立刻造成伤害 ✓（开关真的是开关）。

不可射击 ✓；雨滴落地命中、把气泡下压 ✓。

**导电连锁**（第三关，已实现）：气泡是一个电容。被 `zapper`（电击水母）的放电环扫到加一大截电荷，靠近它会慢慢加，
不在电场里会泄露；**电荷过阈值后靠近任何一只水母就会引爆连锁**，放电在它们之间按距离跳（最多 12 只、每只 4 点伤害）。
带电时气泡外面套一圈电（线宽 = 电荷，到阈值开始闪），放电是一圈扩散光环。于是同一个机制同时是**危险**（带电时你会
引爆整片水母林）、**武器**（主动带电去炸敌群）、**路线解谜**（把电导向封路的触须）。实测：4 只围成一簇 → 环触发、
连锁把 4 只全部打跑。

`zapper` 是全场唯一"**越打越危险**"的敌人：碰到或**被打中**都会放一圈电，而放电环的半径就是判定半径。

| `vent` 热液喷口 | 喷口上方是**致命柱**，周期性喷发；喷前变亮、喷时画出危及边界 | 静默期 **0 命中**；喷发期 **5 点伤害 → 死亡** |
| `mineral` 矿物颗粒 | 随热流**上升**（全场唯一往上走的东西） | 3 秒上升 **350m** |
| `shrimp` 盲眼虾 | 从侧面**直线**逼近，不追踪 | 3 秒横移 **−90m** |
| `angler` 灯笼鱼 | 吊着发光诱饵悬停，靠近后张口冲刺 | 触发扑击 ✓ |
| `torpedo` 失控鱼雷 | 先直飞、**再转向追踪** | 直飞 **221m**（配置 220）后转弯 |
| `tube` 管虫群 | 障碍：会开合的管丛，血量 3.0、缝比网窄 | 画成活的管丛 ✓ |

第二关的其余名目映射到现有种类：锈蚀食腐蟹 → `crab`，幽灵水母 → `jelly`，漂浮残骸 → `crate` / `coral`，船体板 → `wall`，缆绳 → `net`。

**还没做的**（明确记在 `.scratch/levels/issues/01-two-levels.md`）：第二关的**附着与挤压**（吸附在船体下抵抗暗流、太久被藤壶挤压、体积越大越难挤进船舱）、幽灵水母的**带电触须轨迹**、两个 BOSS 的**阶段变化**（触手被破坏后坍塌 / 堵喷口后猛烈爆发）、以及每关独立的水体配色。

### BOSS：每关的终点

**关卡不再因为距离走完而结束**：卷动到 `scrollLength` 就停住（最后一段自然变成一个出不去的决斗场），而真正的通关条件是**打掉这一关的 BOSS**。没有击败它，这一关永远不会结束——这正是它的意义。

| 写在哪 | 内容 |
|---|---|
| `config/levels.json5` 的 `boss` | `at`（走到多少米它出现，**必须 < scrollLength**，否则加载就报错）、`health`、`name`、`colour`。这是**关卡强度**：两只 BOSS 可以不一样厚、不一样颜色。 |
| `mechanics.json5` 的 `hazards.boss` | 它怎么动（`holdMeters` 悬停高度、`patrolAmplitude` / `patrolPeriodSeconds` 横向游弋、`seekSpeedFactor` 追你的速度）、`contactDamage`、`radiusRatio`（体型）、颜色与受击闪白 |
| `enemyBullets.shooters.boss` | 它的枪：一次一波扇形（默认 5 发、±0.62 弧度） |

**它不随水流走**——它咬住画面，一直悬在你上方 `holdMeters` 处横向游弋并缓慢逼近。所以它跑不掉，只能打（或者死）。它是一条 hazard，所以玩家的子弹打它、无敌帧保护你、伤害与飘字全都不用新代码；只有三件事是它自己的：**不下沉**、**血量归零是"死"而不是"逃跑"**（那也正是通关信号）、**不能被吃**（`edibleAtTier` 锁在最高档）。

**屏幕顶部那条紫色的条就是这一关的进度**（`hud.bossBar`：位置、宽度、颜色、字号）。它只在 BOSS 战期间出现——**它的"不出现"本身也是信息**：BOSS 来之前和死之后，屏幕顶上不该有一条显示 0 的条。

实测（412×915，第一关 `at: 1300`、`health: 120`）：走到 1315m 时 BOSS 出现，血量 120、体型 0.11 泳道宽、血条显示名字"深渊灯笼鱼"；**把它按在场上、把卷动走到底再等 5 秒，关卡仍然没有结束**（`phase` 一直是 `playing`）✓；把它打掉 → 关卡结束（进入结算），加分走 `score.boss`（**+1000**，实测账本 `boss: 1`）✓

### 掉落物：技能泡、火力升级、射速升级

关卡里掉下来的拾取物有三种（关卡文件用 `kind: 'skill'` / `'upgrade'` / `'rate'` 放置），**捡起来都加分**（`score.skill`，默认 50），外形和颜色都必须一眼分得开：

| | 技能泡 `skill` | 火力升级 `upgrade` | 射速升级 `rate` |
|---|---|---|---|
| 形状 | 紫色**菱形** | **两个叠起来的箭头**（绿） | **一个箭头 + 两侧速度线**（橙） |
| 效果 | 随机换一种技能（`id` 在**拾取那一刻**才掷，不是放置时） | **火力 +1 排**：一次齐射从每排各出一发 | **射速 +1 档**：扣扳机更快 |
| 上限 | — | `bullets.maxStreams`（默认 2） | **三档**（= `bullets.rateTiers` 的长度） |
| 持续 | 单槽，捡新的换掉旧的 | 整局有效，**死亡后重置** | 同左 |

**掉落物是各自独立的**（修的一个 bug）：以前水里只有**一个拾取位**，关卡把两个掉落物放在附近时，后一个会**覆盖**前一个——玩家看到的就是"拾取物凭空消失了"。第 1 关正好有这种排布（520m 的射速升级 + 540m 的技能泡，相距 20 米），这个 bug 就是这么被发现的。现在它们是一张列表，各自漂移、各自拾取，**同一帧捡到两个也会各自生效**（实测：两个相距 18 米的掉落物同时在屏、都被收集、档位 +1 且加两次分）。

**两个升级是两个独立乘数**：排数 × 射速。实测：单排一档 **3.6 发/秒**（配置 4）→ 拾取射速升级一档 **6.12**（配置 6）→ 再一档 **9.18**（配置 9，**到顶**）→ 再捡两个仍是第 3 档、横幅明说「已经是最高档（第 3 档）」→ 此时再捡一个火力升级 = 两排 × 第 2 档 = 配置 12，实测 **12.5 发/秒** ✓ 两个乘数确实相乘。

**射速的档数就是那个数组的长度**（默认 `[4, 6, 9]`）：加一档就多写一个数，删一档就删一个数——不存在第二个"上限"要同步。开局用第一档；把第一档设成 0 就是全员关枪。

**火力升级改的是"排数"，射速升级改的是"扣扳机的频率"**：前者每一发齐射从每排各出一发（`bullets.upgradeSpreadRatio` 是排间距，默认 7.5% 泳道宽；`maxStreams` 默认 2，**改成 3 或 4 就能叠加**），后者沿 `bullets.rateTiers` 这条阶梯往上一档。上限内重复拾取会被消耗并给出提示，不会静默失效。

> **为什么排间距不大**：弹道之间那道缝也是玩家瞄准用的通道，而敌人和玩家在同一条泳道里——把整条泳道糊满会让"躲"这件事失去意义。

实测：升级前 **4.42 发/秒**（配置 4，单排），升级后 **7.66 发/秒**（配置 8，双排）——**几乎正好翻倍** ✓ 拾取即生效、掉落物当场消失。

### 喷吐（吞下的东西就是弹药）

**点按右侧中间那个按钮**，把胃袋里最早吞下的那只危险物射出去。

规格里那句话是核心：**"吞噬不是终点，被吞下的东西也是弹药。"** 被吐出的物体**保留自身属性**——吐螃蟹是重冲击、吐垃圾袋是轻推。所以你吞了什么，决定了你手上现在有什么弹药。它也让"极限瘦身"成为可能：清空胃袋、体积下降、擦过原本过不去的窄缝。

配置在 `spit` 段：

| 键 | 管什么 |
|---|---|
| `capacity` | 胃袋容量。满了会点燃引信，见下面的过饱一节 |
| `speedPerSecond` / `decaySeconds` | 弹道速度与射程 |
| `hitRadiusRatio` | 命中半径 |
| `knockbackMeters` | 基础击退量，再乘上弹药种类系数、除以目标质量 |
| `spitInvulnerableSeconds` | 命中后的短暂无敌，防"我打中它、它顺势撞到我" |
| `emptyCooldownSeconds` | 空喷的冷却，让"什么都没有"是一个明确的反馈而不是静默 |

**命中效果是击退，不是伤害。** 喷吐本身不掉血——它是把吞下去的东西**扔回去**。真正掉血的是气泡自带的**小泡泡子弹**（见下一节），两者是两套东西：喷吐的代价是胃袋容量，子弹的代价只是时间。

**吞下多少就还回多少。** 每件东西在**吞下的那一刻**记下它给气泡加了多少体积，之后不管是吐出去还是消化掉，都还的是这个数、不是重新算一遍。于是"吃下去再吐出来"是严格守恒的（否则反复吞吐就能凭空长体积），而且**"极限瘦身"才真的存在**——清空胃袋，体积下降，擦过原本过不去的窄缝。

> 这一条曾经是**写了但没做**的：`spit.ts` 的注释、提交信息和这份文档都说喷吐会降体积，而代码里**没有任何地方**减过 `player.volume`（只有受击会减）。于是"极限瘦身"只是一句承诺。现在它是每件东西各自记账的结果，不是第二个"喷吐该扣多少"的判断。

三个按钮的形状刻意区分方向：**金黄色、刻度向外 = 喷吐**（右侧中间）；**紫色、刻度向内 = 吸附/技能**（最下面，一钮两用）；**绿色、向内挤压 = 消化**（最上面，而且更小）。移动本身没有控件，是**在屏幕任意位置拖动**。

实测（玩家体积 20、目标为螃蟹）：蟹弹药击退 **51.55 m**、垃圾弹药 **28.80 m**，基础值 26。数学对得上——蟹 `26×1.6/0.8 = 52`，垃圾 `26×0.9/0.8 = 29.25`。

### 小泡泡子弹（气泡自带的枪，默认一直开火）

**不用按键**：气泡按固定节奏自己往上吐小泡泡，像街机空战里的子弹。打在生物身上**掉血**，血掉光它**不会死，而是掉头加速游出屏幕**——被赶走，不是被杀。

| 键（`bullets` 段） | 管什么 |
|---|---|
| `rateTiers` | **三档射速**，如 `[4, 6, 9]`：第一档是开局，每捡一个射速升级升一档。**档数 = 这个数组的长度**；第一档设 0 = 完全关枪 |
| `damage` | 每发伤害 |
| `speedPerSecond` | 速度（泳道宽/秒）。屏幕上迎面接近的速度 = 这个 + 关卡卷动速度 |
| `lifeSeconds` | 存活秒数，也就是射程 |
| `radiusRatio` | 子弹半径（相对泳道宽）。做得很小，不挡视线 |
| `colour` / `alpha` / `rimColour` / `rimAlpha` | 外观 |

血量在 `hazards.health` 段，**每种危险物一行**（漏了会加载报错）：默认**鱼 2、水母 2、炸弹鱼 10、海胆 15**，其余全是 0（打跑，不是打死）。**0 = 子弹直接穿过去**，也就是"这种不参与被打跑"。

**打跑不等于拆弹**（炸弹鱼）：它的血打空就**在原地**炸开——远距离打爆是唯一安全的拆法，贴脸打爆等于自爆。这一条和它的追踪速度、点燃距离、引信长度、爆炸半径一起写在 `hazards.bombfish` 段。

**海胆是全场最快的子弹来源**：发射**尖刺**（`shape: "spike"`），181 m/s，比电鳗那发 108 m/s 快 1.67 倍。尖刺画成一颗顺着飞行方向的细长菱形——远程的普通弹丸在余光里只是一个点，而一根针能说出它朝哪去。

**退场是三个方向随机之一：上方 / 左边 / 右边**（`fleeScreensPerSecond` 是速度，单位**屏幕高/秒**，默认 0.9 ≈ 一秒多窜出画面）。为什么不是永远往上跑：只有一个方向的话，玩家两分钟就学会"被赶走的鱼都往上飘"，那看起来像一段固定动画；三个方向都有，每次都不一样，才像"这条鱼自己决定跑了"。侧向退场会从左右边缘游出画面（所以横向也要有清理），而且**朝向会跟着退场方向**（往左跑就是头朝左）。

> 速度单位为什么是"屏幕高/秒"而不是"相对水流几倍"：水流只有 25 m/s 而一屏有 800 m，第一版写成"水流的 2.2 倍"听上去很快，实测却是半分钟才出画面。

**退场中的鱼是暗的**（`fleeAlpha`，默认 0.42）：用**同一套画法整体压暗**，而不是换一套退场专用颜色——形状、颜色、朝向全都还是它，只是明显比水里的其它鱼淡。玩家一眼就能分出"这条已经在走了，别浪费子弹"。

**开枪和打中各有音效，而且是"一对"**：打出去是往**下**掉的一小声加一记气声（`audio.bulletFireVolume`，默认 0.3），打中是往**上**挑的一声脆响（`audio.bulletHitVolume`，默认 0.5）——光凭方向就能分出是出膛还是命中。打中那个更响，因为**开枪是节奏、打中才是信息**。

- 打出的声音**每一发音高随机飘几个百分点**：一秒四发、音高完全一样的话，它就不是音效而是节拍器。
- **打空、打在木箱上都不出声**，只有真的掉血那一下才响；把生物打跑的那一发会按打中的音量再响一点（×1.4），算是"这条搞定了"的收尾。
- 两者都是全游戏最短的音效，因为一秒要响好几次，不能挤掉别的音；打中的那个和"挨打"那声低沉闷响是两件事（一个"我被打了"，一个"我在打它"）。

**两个设计判断，写在这里免得被当成 bug：**

- **掉血不等于死。** 这游戏里生物只有两条出路：**被吃掉**（食物链反转）或**被赶走**。小泡泡买的是第二条，所以血掉光时它加速离场，不爆炸、不给分、不掉东西。
- **开枪是类型属性**（`BubbleType.firesBullets`），两种气泡默认都开着。想让它纯粹是近身角色，把这个类型的那一项改成 `false` 就行。
- 子弹会被**障碍物挡住**（看得见的木箱就该挡住你打出去的东西），但**不会打坏它**——开箱子是冲撞和喷吐的活。

### 过饱（唯一给贪婪设上限的机制）

**胃袋满了会点燃引信。引信烧完，气泡爆开。**

逻辑闭环不需要额外规则：

```
胃袋满  →  canSwallow 已经关闭（喷吐那节就实现了）  →  你没法靠继续吃来解决问题
        →  出路是喷吐（立刻）或消化（慢，且要付代价）  →  腾出空间就熄灭引信
```

**这是这份规格里唯一让"吃太多"成为可挽救危机的机制。** 刻意不是硬失败：**没有出路的惩罚只是死亡，有出路的惩罚才是决策。** 而现在有两条出路、代价不同，"我该怎么办"才真的是个决定。

配置在 `spit` 段的过饱部分：`overloadFuseSeconds`（**设成 0 关闭整个机制**）、`overloadMoveSpeedFactor`、`overloadSuctionFactor`、`bulgePerItem` / `bulgeMax`、`pulseHz`、`rimColor`、`panicBelowFraction` / `panicPulseFactor`。

过饱的视觉有三个同时生效的信号，都刻意做到**不用读 HUD**：

- **轮廓换成警告色**（`rimColor`）
- **外形不规则变形** —— 三个低频波瓣绕轮廓游走，读起来像"里面有东西在挤"，而不是整个气泡在呼吸
- **脉动加速** —— 引信剩余低于 `panicBelowFraction` 时频率乘上 `panicPulseFactor`，越接近爆开跳得越快

`overloadSuctionFactor` 是**惩罚里混着诱惑**：撑住的时候吸力反而变大、范围更广，你会不由自主地把更多东西拉过来——**而你已经吃不下了**。

实测：轮廓色 `#ff7a5a`，外形明显鼓起变形；引信点燃 → 倒计时 → 喷吐一次即熄灭并**买回整个窗口**（不是部分返还，否则喷晚了仍然必死，机制就退化成拖延）。

### 消化压缩（胃袋的第三条出路）

**按住右侧最上面那个绿色按钮**，胃袋里的东西开始被压下去：**体积一点点变小，换来「可吞等级」。**

胃袋里的东西现在有三条出路，而它们各自要的东西不同：

| 出路 | 要的时间 | 换来什么 |
|---|---|---|
| **喷吐** | 立刻 | **弹药**（保留它自己的属性） |
| **消化** | 慢 | **可吞等级**（体积变小，反而能吃掉更大的东西） |
| **不管它** | 引信 5 秒 | 爆开 |

消化是唯一**把库存变成收益**的一条，也是唯一**主动管理体积**的手段——这是它值得付出代价的原因。

配置在 `digest` 段，全部有中文说明：

| 键 | 管什么 |
|---|---|
| `passivePerSecond` | 不按键时最老那件每秒消化多少。**刻意慢于引信**，所以被动消化救不了你 |
| `compressPerSecond` | 按住时的速度。默认容量 3 ÷ 0.9 = 3.3 秒 < 引信 5 秒，**所以压缩是过饱的一条出路** |
| `energyPerMass` / `energyPerTier` / `maxTierBonus` | 质量 → 成长能量 → 可吞等级的汇率，以及最多能加几级。默认一条鱼 ≈ 0.238 质量，1.0 能量换一级，上限 3 级 |
| `extraHitPoints` | **消化期间受击的额外命中点**。默认 1 = 伤害翻倍。设 0 = 关掉这条代价 |
| `pulseHz` / `pulseDepth` / `rimColor` | 压缩期间轮廓的脉动频率、深度和颜色 |

**"防御力下降"怎么落的**：这个游戏没有防御力，只有**固定命中次数**和体积，所以规格里那句"消化期间防御力下降"最诚实的翻译就是**一次受击扣更多命中点**。它写在 `takeHit` 一处，所以危险物、障碍、垃圾袋的吸取全都自动适用。

**没有"消化缩小多少"这个数值**，这是刻意的：每件东西吞下时记下了自己加了多少体积，消化就是把这份体积**按进度还回去**，还完的同时产出能量。于是"质量守恒"只有一处实现，喷吐和消化共用它。想调"消化让体积掉多少"，请调 `consumption.mass` 或 `consumption.massEfficiency`——多一个旋钮就会和它们打架。

**收益跟着"体积真的流出了多少"走，而不是跟着"这件东西消化完了"走**，有两个原因其实是一个：

- **账是平的**：流出去多少体积，就付多少能量。所以把一件消化了一半的东西吐出去，不会静默丢掉那份质量——吐出去的那一半还回来，已经流走的那一半**早就付过钱了**
- **也刷不了**：消化被允许最多把你压到还剩 1 点血（**它不会杀死你**——这是唯一一个玩家能用来杀死自己的机制，不该无声发生）。如果按"请求流出多少"付钱而不是按"实际流出多少"付钱，一个卡在残血的气泡就能坐在那里**把空气换成等级**

**为什么压缩是独立的一个按钮，而不是喷吐键的长按**：两者是玩家**在两者之间挑一个**的动词，而"按下就顺带吐出一发"的控制根本不是选择——更糟的是，胃袋里只有一件东西时你将**永远无法消化它**，因为按下就已经把它射出去了。（吸附和技能可以共用一个按钮，因为那两件事不会同时想要；这两个会。）

**视觉上怎么看出来**：压缩期间轮廓换成绿色并按 `pulseHz` 脉动——脉动在**不透明度**上而不是形状上，刻意和过饱区分开：过饱是**外形扭动**（有东西要挤出来），压缩是**原地呼吸**（有东西正在被压下去）。同时**气泡会瘪下去**：鼓包按"还有多少没消化完"算，所以"胃袋在空"和"我在变小"是同一幅画，**不需要任何新 UI**。

实测：消化一条鱼，体积从 1.238 回到 1.000（`drained` 与吞下时加 0.238 **相等**）；6 条鱼 = 1.428 能量 = 可吞等级 +1，而**体积 1 的气泡从"吃不了鱼"变成"能吃鱼"**；压缩期间一次受击 0.200 → **0.400**，吸附**无效**（按住吸附键也一样）。

### 负面食物：可吞噬，但有副作用（五种）

规格把可吞噬物分三类：可吞噬 / **可吞噬但有副作用** / 不可吞噬。这一类就是第二类，而它存在的理由很直接：

> **没有它，吞噬永远是纯收益**——质量加弹药，玩家会无脑吃，"这个东西值不值得吃"这个问题根本不成立。

所以这五种**吃下去之后还会继续做事**，而且**动词刻意各不相同**——"五种都从内部扣血"就是同一个机制画五遍：

| | 动词 | 代价 | 收益 | 唯一的答案 |
|---|---|---|---|---|
| **海胆** `urchin` | 远程**尖刺** + 持续**放血** | 在胃袋里每秒扣血；**带着它压缩会更惨**（压缩期间受伤翻倍） | 重（0.5，比水母重），硬弹药（击退 ×1.2） | 血量 15（最厚），打跑它要时间；吃掉它是"用持续掉血换一份重弹药" |
| **炸弹鱼** `bombfish` | **追着你来的定时炸弹** | 外面：靠近 → 进 110m 点燃引信，3 秒后炸开（半径 33% 泳道）；**血打空就在原地炸** | 吐出去是**一颗手雷**（命中时范围击退） | 跑出半径、或者**远距离**把它打爆；贴脸打爆等于自爆 |
| **电鳗** `eel` | **失控** | 每隔几秒电一下，被电时**左右操作是反的** | 仍带电的弹药（击退 ×1.1） | 憋过去，或者赶紧处理掉 |
| **腐败物** `rot` | **消化变慢** | 它在胃袋里时消化速度乘 `rotDigestScale`（默认 0.35） | 一般 | 先吐掉它，再处理别的 |
| **油污** `oil` | **吐不出来** | 每次喷吐只有 `oilSpitChance`（默认 0.25）的概率成功，**它还占着容量** | 最重的一种（0.6，仅次于螃蟹），击退 ×1.35 | 一边按一边等引信烧完——或者一开始就别吃 |

**为什么电鳗只反横向**：关卡是纵向上升的，把纵向也反过来会让玩家觉得**关卡**坏了，而不是气泡被电了；而"手不听话"恰恰是要让人立刻察觉的。**为什么油污是概率而不是墙**：`0` 是彻底堵死、`1` 是普通道具，中间那档（0.25）才是最好玩的——它出得来，但要花掉你几次机会，而**过饱引信不会等你**。

配置在 `hazards` 段（和螃蟹、垃圾袋的数值放在一起，因为都是"某一种生物的数值"）：

| 键 | 管什么 |
|---|---|
| `urchinDrainPerSecond` | 海胆每秒扣多少命中点。0 = 吞下去就没事了 |
| `bombfishFuseSeconds` / `bombfishDetonationHitPoints` | 引信长度（**从吞下那一刻开始烧**）与爆开扣几点 |
| `bombfishBlastRadiusRatio` | 吐出去的爆炸半径。0 = 退化成普通弹丸，那就只剩代价没有诱惑了 |
| `eelShockPeriodSeconds` / `eelShockSeconds` | 电鳗多久电一下、电多久。`eelShockSeconds = 0` 等于关掉这条副作用 |
| `rotDigestScale` | 它在胃袋里时消化速度的倍率。1 = 没影响 |
| `oilSpitChance` | 每次喷吐把它吐出去的概率。0 = 永久堵死 |
| `eelShockColor` / `eelShockWidthRatio` | 被电时气泡上那圈锯齿电光的颜色与线宽 |

**"质量转化为等级"的账在炸弹鱼身上是分开的**：`StomachTick` 同时报 `drained`（消化流出的，**付**成长能量）和 `destroyed`（被炸掉的，**不付**）。合成一个数就等于让玩家用炸弹把食物白换成等级，正好和这只生物存在的理由相反。

**为什么它们同时也在危险物列表里**：这不是额外规则，而是沿用食物链反转那条**双向判定**——档位不够时撞上去一样受伤（和鱼一样）。所以"什么时候能吃它"和"能不能吃鱼"是同一个问题，而不是五种特例。

**胃袋内容物画在气泡轮廓上**（`stomach` 段配置）：一圈小点，每颗是它自己的颜色，**引信快到时那一颗会闪**——这是炸弹鱼唯一的预警，而它必须存在：玩家看不见自己肚子里有一颗正在烧的炸弹，那就不是决策而是偷袭。被电时气泡外面还有一圈**锯齿状闪动的电光**，因为控制反转是玩家唯一会怀疑"游戏坏了"的机制。画在轮廓上而不是气泡内部，因为内部已经叠了四层半透明（阶段色的教训），糊掉的信息等于没有。

**一件生物的属性在它被吞下的那一刻确定**（`StomachEffect` 存在那一件东西上），所以引信不会在倒计时中途变长、电鳗的周期也不会突然改。这是刻意的：**倒计时下面的数字不该被一次存盘改掉**。代价是测试要先把数值调好再吞。

实测：海胆 4/秒 → 连续扣血，**吐出去立刻停止**；炸弹鱼引信 0.70 秒 → 体积 8.38 → 7.80（炸掉的 0.383 **加上**那 0.2 的命中点），`energy` 完全不动；吐出去的炸弹鱼范围 **40.7 / 40.8 m**，半径外的只飘 **1.6 m**；电鳗按住"右"时 `vx` 符号 **−1 → +1**（被电时向左、恢复后向右）；腐败物在胃袋里消化速率 **0.250/秒 vs 1.000/秒**；`oilSpitChance = 0` 时喷吐被拒（内容物留下、`clogs` +1、无弹丸），改成 1 后同一操作立刻把它射出去。

### 障碍物（四种，四种答案）

障碍是**已有机制的靶子**：喷吐说好要"打碎脆弱墙体"但之前没有墙；过饱与喷吐让"变小"有意义但之前没有任何东西是变小才好过的。

四种障碍**不是四档耐久，而是四个不同的答案**——这是它们存在的理由，所以每一种都必须有一句话能说清"怎么过"：

| | 怎么过 | 撞得碎吗 | 耐久 | 外观 |
|---|---|---|---|---|
| 木箱 `crate` | 撞碎它，或者一炮 | 体积 ≥ 4 | 1.0（一炮） | 棕色方格 + 细十字 |
| 珊瑚 `coral` | 绕开它，或者变小穿缝，或者几炮磨掉 | 体积 ≥ 4 | 3.5（好几炮） | 粉色团块 + 分枝 |
| 封路木箱 `wall` | **只能喷吐**，或者从最小缺口挤过去 | **撞不碎** | 3.0（小气泡要好几秒，见下） | 棕色**横板**（同一种木头，形状更厚） |
| 渔网 `net` | **穿过去就撕开了**，或者一炮 | 不适用 | 0.4 **秒**（见下） | 青色绳网 + 撕开的洞 |

配置在 `obstacles` 段，全部有中文说明。`ramVolume` 里按种类覆盖"撞碎它需要的体积"，`null` = **撞不碎**。

**`null` 而不是一个很大的数**：`volume.max` 以后可能调大，而 99 会某天变成可达的。用 `null` 的话，"墙撞不碎"是规则而不是当前的数值巧合。

**渔网的耐久单位是秒，而且是被物理定下来的**。它不是被打碎的，是被**撕开**的：接触期间每秒算 1 点，所以 0.4 就是"在网里待 0.4 秒"。为什么是 0.4：玩家被卷轴以 25m/s 带着走，和一张网的重叠大概只有 0.5 秒。**第一版写的是 1.6 秒，测试眼看着一张网扛了 600 帧没破**——任何比一次穿过更长的撕裂时间都意味着"永远撕不开"，而一张撕不开的网看起来什么都没做。一炮打上去仍然是伤害点（鱼 0.96、蟹 1.92），所以网是"穿过去，或者一炮"。

**渔网会拖慢你**（`netDrag` 0.35，两轴都乘）。这不是装饰：一个又挡不住你、又不掉血的障碍如果什么都不做，就**和空水域完全没区别**，玩家冲过去不会知道那里有东西。拖慢是能感觉到的，而且它顺带解释了为什么会被撕开——被拖住的那点时间刚好够把它磨开。

**渔网不掉血**（`contactHurts` 对它是 false）。它是唯一对**小**的玩家不惩罚的障碍：小的玩家撞不碎木箱，但可以穿网。

**封路木箱的形状改了三次**，因为"它和木箱是同一种木头，只是不给你一次撞碎"这句话得让形状说：四等分读起来像**窗框**（一个带厚框的物体），四等分再加木板线读起来像**格栅**——那是三者里最糟的，因为**长得像渔网的墙，是玩家一眼认不出来的墙**，而这两者是相反的答案。最后用**横板**：和绳网没有任何共同形状，也和单个木箱没有。

**最重要的一条规则**：`minGapFraction` 要求**每一排都必须留出一个玩家最小时也能通过的缺口**。

这不是体贴，而是让"变小"成为**选择**而不是必需——如果某排能把泳道封死，玩家就必须在那个时刻是小的，否则死，于是"这里该不该大"就不再是问题。留了缺口之后，大气泡永远可以选绕路（慢、贵、大概要挨一下），小气泡可以穿线，**两种都可行，选择才是真的**。

`assertLevelSane` 在启动时对着这条规则检查**每一个手工排布的排**，违规直接抛错并指出是哪一排。**它立刻兑现了价值**：我第一版的两排设计就违规了，报错是

```
Level "open-water" is unusable: obstacle row at 1070m leaves no gap of 0.17 or more
```

原因是 `place.barrier` 第一版"先均匀放块、再删掉落在缺口里的"——删除后**留下的块仍然离缺口不够远**。现在改成**先把缺口撑开、再把块放在外侧**，缺口宽度由同一条规则推导出来，所以是保证而不是请求。

实测：小气泡（体积 1）撞木箱**掉血 1、木箱不碎**；大气泡（体积 8）**掉血 0、木箱击碎**（阈值 4）。**体积 20 撞封路木箱：不碎、掉血 1**；**体积 6 挂上渔网：0.4 秒撕开、掉血 0、全程被拖慢到 0.35 倍**。

#### 关卡里的用法：先教，再并排，最后连成一段

- **750m**：第一张渔网，两块、缺口很宽。它教的是一件**没有别的障碍教过的事**——它挡住你、不伤你、你一直压着它就开了。刚学会"木箱撞、珊瑚绕"的玩家没有理由猜到这一条，所以第一张是拿来试的，不是拿来考的。
- **920m + 960m**：渔网和封路木箱**并排**（相隔 40m）。和 1030/1070 的珊瑚+木箱同一个手法：两种障碍放在一起，"我手上有什么、我有多宽"才会变成一个**问题**，而不是两件事。
- **1386 / 1416 / 1446m**：最后一段变成**连续的窄缝走廊**（三排珊瑚，间隔 30m = 1.2 秒），关卡最后的**海胆和两个垃圾袋就在走廊里面**。

最后这一条是把"极限瘦身"从**一个瞬间**变成**一段状态**：一次窄缝是你要活过去的事，三次、中间还夹着危险物，是你必须**保持**的状态。吃下去的东西挡路的时间从一秒变成四秒，而"要不要继续变瘦"在这四秒里一直是个决定。

顺带删掉了 1440m 那排鱼（6 条）。**不是为了腾地方，是它已经不构成压力了**：鱼追最大的气泡，而走廊的作用恰恰是保证玩家到海面时是小的——一排鱼对着一个小气泡是**饭**，不是威胁。留着它就是把奖励伪装成危险。


### 图鉴页（主菜单 → 图鉴）

主菜单第二个按钮进入。一页一页的卡片，五个页签、**33 张卡**：**敌人（9 种危险物）· 环境（收集物 / 木箱 / 珊瑚 / 技能泡）· 气泡（吞噬气泡 6 张 + 暴躁气泡 5 张）· 技能（6 种）· 天赋（3 种）**。

**气泡那一页现在是按类型生成的，不是手写的一张清单。** 第一版图鉴只写了当时唯一存在的那种气泡，于是那五张卡读起来像是**游戏的规则**而不是一个角色的能力——"吸附、喷吐、消化"写得好像每个气泡都会，而在那一个提交里确实如此；第二种气泡让这句话变成了假的。
所以卡片是**循环 `BUBBLE_TYPES` 生成**的：一种类型一张自我介绍，后面跟着它自己的机制，文案按**游戏自己的类型 id** 索引——**少写一种类型的文案是加载报错**，`e2e/codex.spec.ts` 再从外面断言一次（游戏有几种气泡，就得有几张卡）。
顺带补上了**「过饱」**那张：胃袋满了会烧引信本来就是吞噬气泡的核心机制之一，之前只在 README 里有，图鉴里没有。它也正好让页数落在类型边界上——第 1 页整个是吞噬气泡，第 2 页整个是暴躁气泡。

**卡片上的数字不是写死的。** 质量、可吞档位、耐久、技能次数、作用半径、体内副作用、**每种气泡有哪些按钮、每一条怒气收支、爆破清哪些推哪些**——全部从游戏**同一张表**里读出来，[src/codex.ts](src/codex.ts) 只提供文案。所以改了数值图鉴跟着变，而不是变成一份没人维护的旧说明书。

这一条有两个测试守着，因为它们正是这类页面烂掉的两种方式：

1. **覆盖**：`e2e/codex.spec.ts` 拿 `Object.keys(KIND_TUNING)`（游戏真正的生物表，加一种生物不加那一行是**编译错误**）、`SKILLS` / `TALENTS` 的 id、以及 **`BUBBLE_TYPES` 的气泡类型**，去比对图鉴的 id 列表。**加了生物或气泡却没写卡片 = 测试失败**，而不是没人注意到的空白。
2. **不过期**：测试在运行时改掉 `consumption.mass.fish`，切页签再回来，断言**画出来的文字里有那个新值**。模块级常量会在 import 时把旧值冻住，那样这个断言就是失败的。

**图标用的是游戏自己的画笔**：危险物和障碍走 `paintHazards` / `paintObstacles`（一张"只有一个对象"的合成场），所以卡片上的画就是在水里的画，改了半径或颜色两边一起变。技能和天赋没有运行时的物体可以交给画笔（技能只在用出去的那一瞬存在），所以它们是自己画的小图标——**重复的是几个形状，不是任何一条规则**，颜色仍然从配置读。

**图鉴在关卡里打不开。** 它是参考材料，不该能在引信烧着的时候翻出来；关卡里"我要查一下"归暂停面板管，那个本来就会冻结模拟。

配置在 `codex` 段（排版与配色，全部有中文说明）和 `menu` 段（主菜单两个按钮的几何与配色）。

## 测试

**端到端测试用 Playwright**，在 `e2e/`：

```bash
pnpm test                # 全部（phone + desktop 两个 project）
pnpm test:phone          # 只跑手机尺寸，迭代时用这个
pnpm test:ui             # 交互式：时间旅行、逐帧看、重跑单个用例
pnpm test:report         # 打开上一次的 HTML 报告
pnpm test:shots          # 只截图（不算测试，看画面用），输出在 test-results/
```

**为什么是 Playwright。** 之前 `scripts/` 里的探针每一支都靠裸 CDP 驱动浏览器：手动 spawn Chrome、
轮询 `/json/list` 拿 websocket、手写 promise 客户端、再 `Runtime.evaluate` 字符串。**每个文件重复约 130
行脚手架，而那些探针的绝大多数 bug 就住在那层脚手架里**——读了游戏已改名的字段、抄了实现而没调用它、
`until` 辅助函数返回了上一轮的采样。

Playwright 把这一切换成 `page.evaluate(() => ...)`：页面里的真函数调用、自动等待的 locator、trace 查看
器、`--ui` 模式、失败重试和失败自动截图。**脚手架成本归零，断言终于可以只关心游戏本身。**

游戏自己的测试钩子 `window.__GB` 仍然是正确的接缝——canvas 里没有 DOM 可查，水面、气泡、危险物都是
Pixi 的绘制调用，所以"气泡动了"没有诚实的 locator。钩子是**刻意的**：它暴露卷轴、玩家的屏幕比例、危险物
列表和音频图，好让测试断言**事实**而不是事实的替身。

只有两样东西走真实输入，因为那才是被测对象：**菜单的开始按钮**和**设置面板的控件**——它们由游戏自己做
命中判定，所以点歪了就是失败，而不是悄悄通过。

## 发布流程

### 公网：push 到 `main` 就自动发布

站点在 **<https://forteencdbw.github.io/TGBA/>**，HTTPS，手机流量直接打开就能玩。

[`.github/workflows/deploy-pages.yml`](.github/workflows/deploy-pages.yml) 在**每次 push 到 `main`** 时自动
跑：`vite build` → 把 `dist/` 的内容 force push 到 `gh-pages` 分支 → GitHub Pages 从那个分支发布。
实测从 push 到 run `success` 约 40 秒。

**唯一的前提是「必须 push」。** `git commit` 是纯本地操作，GitHub **看不见**它，所以不会触发任何东西——
**这个坑真踩过一次**：两个提交做完了但停在本地，站点一直没动，看起来像"workflow 坏了"，其实只是"没推"。
一句话：**站点永远等于 `origin/main` 的尖端，不是你本地 `HEAD` 的尖端。**

> 想重发不用造一个提交：Actions 页面 → Deploy to GitHub Pages → **Run workflow**
> （workflow 里有 `workflow_dispatch`）。

**为什么跑的是 `vite build`，不是 `pnpm build`。** `pnpm build` 是
`tsc --noEmit && tsc --noEmit -p tsconfig.e2e.json && vite build`，会**连带类型检查 `e2e/`**。
那样**正在开发中的一个 spec 文件里哪怕只是一个未使用变量，就能让站点停止更新**。Vite 只转译、
不检查类型，所以类型错误照样发布。**这是刻意的取舍**：宁可发布半成品，也不要让站点变得可被一个
坏测试文件卡死。想加质量门禁就是在 workflow 里加一行——但那就把上面这句话反过来了。

**为什么推分支，而不是用官方的 `actions/deploy-pages`。** 官方那套要求把 Pages 的 Source 改成
"GitHub Actions"，那是一次额外的仓库设置改动，而且 workflow 一旦有问题站点就直接**空白**。推分支沿用
"Deploy from a branch" 的现有设置，也让构建产物不进 `main` 的历史（`dist/` 仍然是 gitignore 的）。

**Pages 设置**（已在仓库配好，这里只是记录）：Settings → Pages → Source = **Deploy from a branch**，
分支 **`gh-pages`**，目录 **`/ (root)`**。

> ⚠️ **不要选 `main` + `/ (root)`。** 仓库根目录的 `index.html` 是**开发入口**
> （`<script type="module" src="/src/main.ts">`，TypeScript 源码），而 Pages 只是把文件当静态资源发出去，
> 结果是**白屏**，且报不出有用的错。要发布的是 `gh-pages` 分支，那里才是构建产物。

> **`gh-pages` 是生成产物，不要手工编辑它。** workflow 每次 force push 覆盖它，所以它没有值得保留的历史。

> **缓存**：Pages 回 `Cache-Control: max-age=600`，所以刚发布后手机上**最多可能滞后约 10 分钟**才看到
> 新版——"明明发布了手机还是旧的"多半是这个，不是没发布。资源文件名带内容哈希，新资源本身立刻可取，
> 被缓存的是 `index.html`；强刷或换无痕窗口即可立刻确认。

### 手动打包（itch.io、离线分发）

需要 zip 的场合才走这条：

```bash
pnpm build                              # 类型检查 → dist/
node scripts/verify-dist.mjs            # 必做：确认打包产物能跑
```

```powershell
Compress-Archive -Path dist\* -DestinationPath release\bubble-battle.zip
```

**产物**：10 个文件 / **763 kB**（主包 gzip 后 **159 kB**），打成 zip **233 kB**。
（这组数字以前写的是 590 kB / 101 kB / 175 kB，早就过期了；现在是重新量过的。）

> ⚠️ **`pnpm build` 现在会警告主包超过 500 kB**（514 kB，Vite 的默认阈值）。**这条警告是留着的，不是没看见**：
> 阈值看的是压缩前的体积，而实际传输量是 gzip 后的 159 kB；把阈值调高只会训练人忽略警告。
> 真要减，最划算的一刀是**图鉴改成动态 `import()`**——它的文案只有按下按钮的人才会用到，现在却算在首屏里。

`vite.config.ts` 设了 `base: './'`，所有资源都是**相对路径**，所以：

| 目标 | 做法 |
|---|---|
| itch.io | 把 `dist/` 里的**内容**（不是 `dist` 目录本身）压成 zip 上传 |
| 任何静态托管 | 把 `dist/` 整个目录作为站点根，**放在子目录也行**（`/bubble/` 已实测；GitHub Pages 就是 `/TGBA/`） |
| 本地试跑 | 见下 |

> ⚠️ **不能用 `file://` 直接打开 `dist/index.html`。** 这是 ES module 的 CORS 限制，浏览器会拒绝加载模块，
> 页面上不会报有用的错，只是**白屏**。本地要起一个静态服务：
> `npx serve dist`、`python -m http.server -d dist`，或 `node scripts/verify-dist.mjs`（它就顺带验证了）。

**source map 默认不发。** 它们曾占产物的 2.9 MB / 3.0 MB，而浏览器只在打开 devtools 时才下载。
需要读压缩后的堆栈时，把 `vite.config.ts` 里的 `sourcemap` 临时改成 `true` 再构建。

> 以前这里写着"**故意不做环境变量开关**：读环境变量要用 `process`，而本项目 tsconfig 是浏览器向的、没有
> Node 类型，于是 `pnpm build` 会直接失败"。**那个理由现在不成立了**：`vite.config.ts` 已经搬到自己的
> [`tsconfig.node.json`](tsconfig.node.json)（它要在构建时读 `package.json` 和 git，本来就需要 Node 类型），
> 而游戏的 tsconfig 仍然只有 `vite/client`——所以 `src/` 里出现 `process` 或 `fs` 依旧是类型错误。
> 两条都保留：配置有 Node 类型，游戏没有。
>
> 开关本身仍然不做：一个只有构建机才能翻的开关，就是一个永远不会被翻的开关。

### 关于验证（约定）

**没有回归测试套件了，2026 年删的。** 曾经有 15 个套件、并行跑约 88 秒，靠一行
`CHECKS: {...}` JSON 判定通过与否。删掉的原因是**维护成本**：玩法从"强制上升 + 只能左右"
改成"平面自由移动 + 卷轴关卡"之后，其中 5 个测的是已删除的功能，另外 4 个引用着已改名的字段。
把它们逐个修好、再让它们跟上后续每一次机制调整，花掉的时间**超过了它们挡住的 bug 的价值**。

留下的是**不花时间的工具**：`probe-layout` / `measure-pixels` / `performance` 都只输出数字或图片
给人和 agent 看，不作断言，所以既不会过期也不会拖慢任何东西。

日常验证就两条：**`pnpm typecheck`**（顺手、约 5 秒），以及**针对自己刚改的东西做一次真实测量**。
改完手感或布局后，`probe-layout` 截一张图看一眼通常比任何断言都值。

## 测量工具的坑（重要）

**不要用 `drawImage` 读画布像素。** Pixi 没开 `preserveDrawingBuffer`，WebGL 画布合成后缓冲区即被清空，
`getImageData` 会**静默返回全黑**——我因此误判"渐变没铺满"并去修一个不存在的 bug。

要读真实像素，用 `scripts/measure-pixels.mjs`：它走 CDP 截图 + 自己解 PNG。

同理，**不要用 `--dump-dom` + `--virtual-time-budget` 验证动画**：那样只跑得到个位数帧，
看起来像"世界没推进"。用 `scripts/probe-layout.mjs`（CDP + 真实墙钟时间）。

## 调手感

所有手感参数集中在 `src/config.ts` 的 `tuning`，**运行时可改**，不用重新编译：

```js
// 浏览器控制台
__GB.player                        // 实时状态（x 是水柱比例 0..1，vx 单位是"水柱宽/秒"）
__GB.game.diagnostics              // 帧数 / 用时 / 名义总时长 / 本机标定出的横向参数
__GB.lateralSnapshot               // 这台设备解出的 accel / boostSteerFactor / stopSpeed
__GB.frame()                       // 一次性打印所有尺寸（排查移动端显示问题用这个）
```

> **横向手感参数不在这里**，而在 `src/config.ts` 顶部的**手感目标**里，以"横穿时间"表达：
> `COLUMN_CROSSING_SECONDS`（默认 2.5s）、`KEYBOARD_CROSSING_SECONDS`（默认 2s）。
> 真正的速度由 `src/lateral.ts` **按泳道宽度运行时反解**，所以换个设备手感不变。
> 纵向速度是它的 `verticalSpeedScale` 倍，两个方向用同一个常量，斜向移动不会更快。
>
> **关卡节奏改 `src/levels.ts` 的 `scrollSpeed`**（默认 25 m/s），它与操作完全解耦：
> 改它只影响世界走多快、关卡多长（`scrollLength / scrollSpeed` 秒），不影响手感。

## 注意

- `vite.config.ts` 里 `build.minify` **不能**设成 `'esbuild'`：esbuild 只是 Vite 8 的可选
  peer dependency，pnpm 默认不装，会直接导致构建失败。
- `server.watch.ignored` 排除了 `scripts/`、`.scratch/` 等目录：Windows 上 Vite 的 fs watcher
  碰到编辑器/工具产生的临时目录会抛 `EBUSY` 并**直接杀掉 dev server**。
- **用 `pwsh` 跑 `.ps1`**。Windows PowerShell 5.1 在这里的执行策略是 `Restricted`（脚本文件被禁），
  而 `pwsh` 继承 `LocalMachine = RemoteSigned`，本地脚本可直接运行。
  若 `pwsh` 找不到，见下。

## pwsh 的安装方式（本机特殊情况）

PowerShell 7 是以 MSIX 包装在
`C:\Program Files\WindowsApps\Microsoft.PowerShell_<版本>_x64__8wekyb3d8bbwe`，
而机器 PATH 里留的是**已不存在的旧版本目录**（7.6.4 装完升级到 7.6.6 后旧包被删），
所以 `pwsh` 无法解析。

两个坑：

1. **PATH 扫描会跳过 `WindowsApps` 目录本身**。把 junction 建在 `WindowsApps` 里面**没用**，
   `where pwsh` 依然找不到。
2. 直接写死带版本号的路径，**下次升级就会再坏一次**。

所以稳定入口建在 `%LOCALAPPDATA%\pwsh7`（junction，指向当前包），并加进用户 PATH。
**PowerShell 升级后重跑一次即可**（脚本自动发现最新版本目录，可重复执行）：

```powershell
pwsh -File scripts\install-pwsh-path.ps1
```

> 机器 PATH 里那条失效的 7.6.4 条目已经无害（目录不存在，只是拖慢一点点路径查找），
> 但它归 `Machine` 作用域，**需要管理员**才能清理。脚本只报告、不修改。
